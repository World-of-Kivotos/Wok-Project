# WOK 本体掌勺小游戏 MC 测试

产品线为 WOK 本体，modId `miningdim`，Minecraft 1.20.1 / Forge 47.x。源码在 `com.miningdim.job.chef.zhangshao`。

本次接入的是已拍板规格 §17.13 的练习模式。使用网页原型 simVersion 2 的同一 Java 内核与参数，四台均可玩；不扣食材、信用点，不产出菜品、经验或手熟。正式菜谱生产与职业效果重构不在本次测试范围。

## 进入

- 正常右键九台新烹饪台，打开台子界面，再点击「练习」进入对应模拟。
- 潜行且任一手持方块时保留原版放置；创造模式双手空着潜行右键继续保留外观预览。
- 农夫乐事厨锅保持全部原有右键交互；从它原生界面右侧的「练习」按钮进入。进入前正常关闭容器，不改其库存和烹饪进度。
- `/chef practice [pot|fryer|oven|prep]` 仅作为权限等级 2 的管理员调试入口，打开对应台子选择界面。普通玩家无需命令即可练习。

## 操作

上方按钮循环选择台子、星级、等级、性子和手熟。练习允许任意等级，选择不写入玩家职业数据。

- 回车或点击开始：一秒倒数后开局。
- 空格或左键按住：火候条上浮；松开下落，用火候条框住食材。
- F 或右键：炸锅压火、烤炉翻面、备餐台按节拍摆料。
- R：重开。1.5 秒内两次按 Esc：退出；界面不暂停单人世界。
- 右上角「帮助」：查看七页玩法说明；用按钮或左右方向键翻页，Esc 或「返回练习」关闭。查看期间只暂停本局练习，游戏世界继续运行；返回后不会补跑看说明的时间。

结果显示品质、分数、准确率、欠火/过火、调料瓶、Perfect、本台失误和回放校验。实时输入结束后重演同一局，比对状态哈希及完整结果；不一致会在界面和客户端日志明确报错。

## 测试包

使用本体目录 `D:\WOK测试\versions\1.20.1-Forge_47.4.20\mods`。客户端和服务器均须使用同一个测试包，重启 Minecraft 后生效。

为保留当前测试 JAR 中尚未汇总进主线的其他模块，测试产物可以通过 `tools/chef_mc_practice/package-playtest.ps1` 将主线构建并重混淆后的掌勺模块叠加到指定本体 JAR。脚本只允许新增 `job/chef/zhangshao` 类、对应素材/金样本/许可，以及更新清单版本；会逐项核对其余条目内容完全相同，并记录输入与产物 SHA256。当前测试基包及主线完整构建产物均保留。

## 验证

内核金样本包含全部随机数与哈希向量、15 个固定业务 case 和四台回放结果。新增入口用例验证九台路由、原交互保留、网络边界与练习不扣料不加经验。

基础接入的业务验收必须同时满足对应工程编译通过、GameTest 日志出现 `All N required tests passed`。客户端手感与实际中文排版仍以本次游戏内试玩反馈为准。

1.0.35 基础接入执行 `compileJava runGameTestServer jarJar -Pmod_version=1.0.35-chef-playtest` 成功；最终日志为 `All 2101 required tests passed`，其中掌勺批次包含 3 项 GameTest。完整基线模块仍由主线测试套件校验。

1.0.36 仅新增客户端分页帮助和练习暂停查看，已通过 `compileJava verifyModuleBoundaries jarJar`；检查了七页文字的保守排版高度和帮助期间输入隔离、返回计时逻辑。内核、服务端入口、物品和经济结算没有变化，本次未重复全量 GameTest。

当前环境无 Context7 工具，Minecraft/Forge API 按工程锁定的 Minecraft 1.20.1 / Forge 47.3.0 映射 JAR 与现有源码核对签名，并通过编译和专用服务器加载验证。

## 正式烹饪接入方案

本轮范围已确认：先交付帮助按钮，明确下面的正式接入顺序；本轮不启用扣料、收费或出菜。正式规则以 `docs/chef-rework/minigame-spec.md` §17–20、`dish-stars.tsv`、`dish-effects.tsv` 和 `stations.md` 为准。

当前差距已经核对：九台新烹饪台尚无生产用方块实体、库存、菜单或配方类型；掌勺频道只负责打开练习，未接正式开局、输入上报和服务端结算。旧调味台仍运行原来的生产流程，不能将练习结果直接盖到食物上充当新系统。

| 阶段 | 可交付闭环 | 验收重点 |
| --- | --- | --- |
| 1. 炸锅单份生产 | 三种外观共用库存、容器槽、调料槽、出品槽及可保存的锅内暂存；接真实配方与家常制作，再接单份掌勺 | 玩家实际放料、开局、控火、出锅、取菜；非厨师只能做家常；配方、余料和容器数量准确 |
| 2. 服务端完整结算 | 复用同一内核，由服务端锁定菜谱、等级、种子、金瓶和费用，校验逐段输入，结算品质、负面、调料、经验、手熟和个人最佳 | 不接受客户端上报品质；同一局只扣一次、只出一次；两人争台、重复输入或结果包不能复制物品 |
| 3. 三台与厨锅接入 | 共用生产事务扩展到烤炉、备餐台；按农夫乐事锁定版本接厨锅界面和暂停原生烹饪；逐项迁移正式菜谱 | 外观不影响功能；农夫乐事缺失仍能加载 WOK；漏斗只走家常路径，配方不存在或被替换时明确报错 |
| 4. 完整职业与迁移 | 接固定菜品效果表、星级、批量、快手、连做、闪耀管控和旧调味系统迁移；保留存量物品和存档兼容 | 品质只决定时长，菜品效果由菜表决定；旧新入口不能重复生产或重复盖章，现有存档正常加载 |

阶段 1 和 2 构成首个可放进生存测试的最小版本，应一起完成再开放生产。扣料与费用在服务端开局统一处理；糊锅、撂勺、死亡、下线、离台或拆台按规格出家常，不退费用；服务器重载恢复未完成的暂存材料和费用，不能重复退款。练习帮助的暂停只适用于练习，正式生产不提供暂停或免费重开。

正式实现前先确认规格 §22.2 仍标为待拍板的取值，尤其是闪耀每日上限 3 或 6、多产出配方是否统一一份，以及 `motion / flips / beats` 提案是否写入正式菜表。它们尚未因为本次帮助更新而成为已确认规则。旧调味台退出和菜谱切换应在新生产闭环验证通过后一起迁移。

每个生产阶段使用本体工程编译和模块边界检查，并以 GameTest 的 `All N required tests passed` 验收；业务用例优先覆盖真实扣料出菜、失败无部分扣费、争台与重复结算、撂勺降级、重载退款五条路径。最终 JAR 只部署到 WOK 本体测试目录。
