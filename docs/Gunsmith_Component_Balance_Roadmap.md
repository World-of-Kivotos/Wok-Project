# 枪匠组件平衡与后续扩展路线

> 状态：基础组件与稀有组件的分层原则已确认；首个特殊射速组件“格赫娜高速导气”已按独立规格进入实现。除该独立规格外，本文出现的其他具体部件、百分比和惩罚组合仍为说明性示例，不代表数值已经定案。
> 关联文档：[枪匠组件命名计划](Gunsmith_Component_Naming_Plan.md)、[枪匠图纸射击模式策略](Gunsmith_Blueprint_Fire_Mode_Policy.md)。

---

## 一、文档目的

本文件固定枪匠组件的当前平衡边界，并为后续稀有组件预留统一规则。核心目标不是让新组件成为基础组件的纯数值上位替代，而是让玩家在强化某一属性时承担清晰、可计算且能在界面中提前看到的代价。

本文必须区分以下三层概念：

| 概念 | 决定内容 | 示例 | 不能混同为 |
|---|---|---|---|
| 组件类型 `variant` | 组件的具体机制与正负属性组合 | 基础导气、未来的特殊导气 | 品质档位 |
| 品质 `quality` | 同一组件类型内部的品质和数值浮动 | 普通、改良、军规、精密、传奇 | 稀有组件类型 |
| 获取稀有度 | 图纸、掉落、制作和交易中的获取难度 | 后续稀有组件来源 | “传奇”品质本身 |

因此，“稀有组件”表示后续新增的特殊 `variant` 及其获取层级，不等于现有的“传奇”品质，也不能只靠更高品质冒充新的组件机制。

## 二、当前基础组件硬规则

### 2.1 基础组件定位

当前已存在的导气、枪管、枪机、枪托、护木、握把，以及各平台对应的手枪、无托、精确射手和狙击部件，均属于基础组件。机枪平台的基础组件规格另见[机枪平台组件规格](Gunsmith_Machine_Gun_Components.md)，其中基础脚架归入操控与瞄准稳定属性。基础组件用于建立稳定、可预测的枪械强化基线，不承担改变枪械核心节奏的职责。

基础组件继续遵循当前属性分工：

- 枪机、击锤或机匣影响伤害，具体来源由平台决定。
- 枪管影响爆头倍率。
- 导气影响有效射程。
- 枪托或套筒影响后坐力。
- 护木或扳机影响散布。
- 握把影响操控、开镜时间或瞄准散布。
- 机枪基础脚架影响操控与瞄准稳定；机枪规格中的射程属性固定为 `1.0`。

### 2.2 射速禁区

基础组件不得修改射速，包括但不限于 RPM、射击间隔、连发循环速度或点射循环速度。射速会直接改变单位时间伤害、弹药消耗和压制能力，属于足以重塑整把枪强度的核心属性，不能进入基础组件的通用品质浮动。

基础组件和普通图纸还必须保留源枪的完整、有序射击模式列表。射速变化与射击模式变化是两个不同概念：未来即使某个稀有组件调整 RPM，也不得因此增加、删除、替换或重排 `auto`、`semi`、`burst` 等模式。

### 2.3 基础组件数值边界

基础组件应维持可预测、可比较的常规强化区间，但本文不直接确定伤害或其他属性的最终百分比上限。各属性上限、品质区间与平台差异必须在后续数值评审中分别确认，不能从某个说明示例推导为全局规则。

当前原型使用普通 `0.96-1.04`、改良 `1.05-1.12`、军规 `1.13-1.22`、精密 `1.23-1.35`、传奇 `1.36-1.50` 的通用品质系数，并将组件系数映射到对应属性。这些数值属于当前实现快照，不因本文中的举例自动改变，也不代表后续特殊组件必须沿用同一套区间。

后续确定正式上限时，应以明确的数据规则计算并验证最终效果，不得用界面文案掩盖实现差异，也不得在属性结算末端用静默钳制代替可审查的数值设计。

## 三、后续稀有组件规则

### 3.1 射速组件必须独立实现

任何能够增加或降低射速的组件都必须作为额外的稀有组件类型开发，不得回填到现有基础组件，也不得只修改现有品质系数实现。

首个已批准实现为[格赫娜高速导气组件](Gunsmith_Gehenna_High_Speed_Gas.md)。其 AR 平台限制、导气槽位、最高 `+25%` 半自动/全自动循环射速、随同一浮动系数最高 `+40%` 的上跳后坐力、品质公式和 TaCZ 三连发边界以该独立规格为准，不得从本文的说明性示例反推或覆盖。

每个射速组件在进入实现前必须单独确定：

1. 适用平台和槽位。
2. 射速变化的明确数值与计算方式。
3. 对单位时间伤害、弹药消耗、后坐累积和操控表现的影响。
4. 必须承担的负面属性或使用限制。
5. 图纸、冲压、掉落、交易和解锁来源。
6. 装配前预览、成品 tooltip 与 TaCZ 实战缓存的一致性。

### 3.2 极致强化必须带有代价

未来可以设计显著强化单项属性、超出常规基础组件区间的稀有组件，但其定位必须是有明确取舍的构筑选择，而不是对基础组件的全面上位替代。

任何提供极高单项收益的组件必须同时满足以下要求：

- 至少绑定一项会实际生效的负面属性或使用限制。
- 正面收益与负面代价必须同时写入组件数据，不能只存在于说明文本。
- 装配界面必须在确认组装前显示完整的正负数值。
- 成品 tooltip 必须继续显示完整效果，不能隐藏惩罚。
- 负面代价不能通过同一组件自身或无条件兼容组合被自动抵消。
- 最终实战属性必须与预览值一致，并由自动测试断言具体数值。

可选的平衡代价包括降低射速、增加后坐力、扩大散布、延长开镜时间、降低射程或增加其他明确限制。具体使用哪一种代价以及代价数值，需要按组件逐件评审，不能套用统一的无脑模板。

### 3.3 设计示例，不代表已定案内容

讨论中曾使用“基础伤害组件最高提高 `+30%`，未来特殊导气组件提高 `+60%`”来说明普通强化与极致强化的差异，并用以下两种方向说明负面代价：

- 方案 A：伤害 `+60%`，同时降低射速。
- 方案 B：伤害 `+60%`，同时增加后坐力。

整组场景都只是解释设计原则的例子。`+30%` 不是已经确认的基础伤害上限，`+60%` 不是已经确认的稀有组件数值，“特殊导气”也不是已经确定的组件类型。组件名称、正面收益、惩罚数值、平台范围、获取方式和最终配方均需后续单独评审；没有完成实战测试与数值确认前，不得把示例直接注册为可获取物品。

## 四、数据与界面要求

后续非基础组件必须新增稳定的 `variant` 数据维度，并与平台、槽位、品质和单件浮动值分别保存。不能把新组件类型塞进显示名、品质名或现有通用系数中。

每个特殊组件至少需要保存并校验：

- 稳定的组件类型标识。
- 适用平台与槽位。
- 正面属性修改列表。
- 负面属性修改列表。
- 品质允许影响的数值范围。
- 数据版本与旧物品迁移规则。

界面必须以数字显示装配前后的最终属性，至少覆盖伤害、爆头倍率、射程、后坐力、散布、开镜时间和射速。只显示“提升”“降低”或组件综合系数不足以表达极致强化组件的真实代价。

## 五、实现与验收顺序

1. 先修复当前冲压与 TaCZ 属性结算问题，确保预览、NBT 和实战缓存一致。
2. 分别确定基础组件各属性的正式上限、品质换算与平台差异，并用具体业务数值补充 GameTest。
3. 引入独立 `variant` 数据结构及兼容迁移，保持现有基础组件可识别。
4. 完成正负属性并列显示和成品组成展示。
5. 先实现一个不修改射速的稀有组件，验证取舍模型与数据结构。
6. 射速相关稀有组件逐件建立独立规格，并针对单位时间伤害、射击模式边界和实战手感单独评审；格赫娜高速导气是首个落地验证件。

验收测试至少必须覆盖：

- 所有基础组件都不能修改射速。
- 所有基础组件的最终属性都符合届时批准的属性上限与品质换算规则，测试不得把本文示例值当作既定断言。
- 稀有组件的正面收益和负面代价同时生效。
- 删除任一已声明的负面代价后，对应测试必须失败。
- 射速组件不会改变源枪射击模式列表及顺序。
- 装配预览、成品 tooltip、NBT 与 TaCZ 实战缓存的具体数值一致。
- 非法平台、槽位、组件类型或超界数值被明确拒绝，不使用静默默认值。

## 六、当前非目标

本路线图与格赫娜高速导气的首件落地不包含以下扩张：

- 不因格赫娜高速导气的落地自动注册其他稀有组件、极致强化组件或射速组件。
- 不把 `+30%`、`+60%`、其他未单独批准的特殊导气或示例惩罚视为已经确定的数值与内容。
- 除格赫娜高速导气所需的独立变体、属性与数据迁移外，不调整现有基础组件数值。
- 不改变现有图纸保存的射击模式列表及顺序，也不改写 TaCZ 源枪数据；射速变化仅由装配了该组件的成品枪属性缓存产生。

后续实现必须以本文为平衡边界，并在同一枪匠模块 PR 中说明改了什么、为什么采用该代价、验证了哪些具体业务数值。
