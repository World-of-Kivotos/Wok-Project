## 0. 术语

| 词 | 含义 |
|---|---|
| tick | 逻辑步，固定 20 次/秒（50 ms）。 |
| 正式 tick（pt） | 倒计时之后、备餐台「摆料段」之外的 tick。计分、时限、调料瓶出现时刻都按 pt 算。 |
| 全部 tick（tick） | 倒计时之后的所有 tick（含摆料段）。输入流按它编号。 |
| u | 轨道单位。轨道全长 `TRACK = 1,000,000 u`，0 = 锅底（最小火），1,000,000 = 顶（最大火）。1 u = 星露谷 1/1760 像素。 |
| ‰ | 千分比。 |
| 火候条 | 玩家控制的区间（星露谷的绿条）。按住往上、松开往下。 |
| 食材 | 要追的目标图标（星露谷的鱼）。 |
| 熟度 | 进度条（0–1,000,000），满了出锅、空了糊锅。 |
| 调料瓶 / 金调料瓶 | 宝箱。普通瓶只加分；金瓶是闪耀的必要条件。种子只决定「有没有瓶」，是不是金瓶由服务端私下抽（§10）。 |
| Perfect | 全程没让食材连续离条超过 1 tick，且本台规则零失误，且正常出锅。 |
| 掌勺 / 批量 / 快手 / 家常 | 四种做法，见 §17。只有「掌勺」「批量」玩小游戏。 |
| 糊锅 / 撂勺 / 到点 | 熟度掉光 / 中途离开 / 超过时限，见 §12。 |

## 1. 一句话玩法与设计目标

**一句话**：左边一根竖着的火候轨道。按住鼠标左键或空格，火候条往上飘；松手它往下掉，有惯性，掉到底还会弹一下。食材在轨道里按自己的性子乱跑，你要用火候条把它框住：框住时熟度往上涨，丢了就往下掉。涨满出锅，掉光糊锅。开局 1–3 秒可能冒出一个调料瓶，把它也框住 1.5 秒就算抓到。全程不脱手叫 Perfect；**Perfect + 抓到金调料瓶 = 闪耀**。四个台子共用这个内核，各自多一条规则（厨锅攒火候、炸锅压油温、烤炉翻面、备餐台摆料节奏）。

**设计目标**（全部由 §16 的仿真表核对）：
1. 品质只看手艺，不再「选目标品质 + 掷骰」。同样的输入永远得到同样的结果。
2. 闪耀极稀有：普通玩家满级约 0.3–1%/局，高手满级约 1–3%/局，另有灵感冷却和每日上限封顶（§18.9）。读种子的外挂也挑不出「金瓶局」（种类不在种子里）。
3. 超凡是熟练玩家的常态上限：低星几乎稳拿，★7 满级约 30%。
4. 一局 8–12 秒（完美一局约 8 秒，备餐台约 9.5–10.5 秒），手熟后快约 40%。做得差也最多 15 秒（备餐台 12 秒 + 摆料段），不会越差越拖。
5. 挂机（全按 / 全松）必定糊锅；规律连点宏被检测封顶。
6. 四台难度差在半星以内；同星不同性子差在一档以内。

## 3. 时钟、单位与输入

### 3.1 时钟
- 规则固定 20 tick/秒，只在整 tick 上算。客户端按**真实时钟**每 50 ms 推进一 tick（不用 MC 客户端 tick）。
- **画面用预测渲染**（v2）：每帧拿当前状态 + 此刻的按键状态预跑下一 tick（克隆状态，只用于画面），在「当前 → 预测的下一 tick」之间插值。出条变红、出条箭头按**同一帧画出来的位置**判断；按下主键的那一帧条上沿立刻亮一下。v1 画「上一 tick → 当前 tick」，画面比判定晚一 tick（按键到画面动约 75 ms），条边上会出现「条已经变红、食材看着还在条里」。预测只影响画面，判定永远以内核为准。
- 客户端掉帧时一帧里**一次补跑完**（不封顶；v1 原型「每帧最多补 250 ms」等于悄悄慢放，不许带进 Java）；补跑的 tick 都用补跑那一刻的按键状态，轻点锁存只记在第一个补跑 tick 上。客户端停住超过 5 秒（切后台、卡死）按撂勺处理，与服务端「5 秒收不到输入」一致（§18.6）。
- 一局 = 20 tick 倒计时（不计入任何统计、不记输入）+ 正式段（含备餐台摆料段）。下文的 `tick` 从倒计时结束算起，从 0 编号。

### 3.2 输入字节（每 tick 1 字节）
| 位 | 名称 | 含义 |
|---|---|---|
| bit0 | `hold` | 推进本 tick 的瞬间按住主键，**或**自上次采样以来按下过主键（轻点锁存）→ 1。主键 = 鼠标左键 / 空格。 |
| bit1 | `act` | 自上次采样以来按下过动作键（按下沿）→ 1，一 tick 最多 1 次。动作键 = 鼠标右键 / F。厨锅不用。 |
| bit2–7 | — | 必须为 0，否则整包作废（§18.6）。 |

两个键都在「厨师」按键分类里，可改键。

### 3.3 除法助手（内核里所有带符号的除法都用它）
```
tdiv(a, b)  // 要求 b > 0；结果向零截断；只对非负数做真正的除法
  = a >= 0 ? a / b : -((-a) / b)
```
Java 直接写；JS 写 `a >= 0 ? (a / b) | 0 : -(((-a) / b) | 0)`。被除数和除数都非负的地方直接用 `/`（JS 加 `|0`）。

## 4. 开局初始化（所有掷骰都在这里）

### 4.1 随机数
- 发生器 Mulberry32，三条独立子流（种子派生见 §18.2）：`rT` 食材、`rB` 调料瓶、`rS` 台子事件。
- `rnd(n) = (next() >>> 1) % n`；`range(lo, hi) = lo + rnd(hi − lo + 1)`（**含两端**）。

### 4.2 开局抽签（固定次数、固定顺序，与输入、与台子无关）
| 流 | 顺序 | 抽什么 |
|---|---|---|
| rT | 1 | `tgt = range(100000, 899999)`（开局第一跳，防原地连点白拿分） |
| rB | 1 | `bottleRoll = rnd(1000)`（有没有瓶） |
| rB | 2 | `bAt = range(bAppearMin, bAppearMax)`（出现的正式 tick；手熟 0 时 20–60，即开局后 1–3 秒，手熟越高越早） |
| rB | 3 | `bOff = range(bOffMin, bOffMax)`（离食材多远：0.55–0.9 个火候条长） |
| rB | 4 | `bDir = rnd(2)`（1 = 往上，0 = 往下） |
| rS | 1–8 | `jit[k] = {−2, 0, +2}[rnd(3)]`，k = 0..7（备餐台节拍抖动，任何台子都抽满 8 个） |
| rS | 9 | `kickBits = next()`（炸锅爆油 / 烤炉翻面的溅射方向掩码） |

有没有瓶：`bottleRoll < bottlePm`（= 普通瓶‰ + 金瓶‰，封顶 1000）→ 有瓶，否则本局没有瓶。**瓶的种类不在这里抽**（v2）：服务端开局时用 `SecureRandom` 私下抽，有瓶时以 `goldPm / bottlePm` 的概率定为金瓶，不进种子、不进参数块，结算时作为 `ext.gold` 传给结算（§14），瓶出现时再告诉客户端（§18.3）。金瓶率在开局时已按冷却、日上限、批量、可疑分清零（§18.9）。v1 用种子定种类，读种子的外挂能只在金瓶局打 Perfect，躲开 Perfect 率检测。

## 5. 每 tick 执行顺序（权威伪代码）

两端必须按此顺序、一步不差。`in` 为本 tick 输入字节。

```
step(in):
  if end != 进行中: return
  hold = in & 1;  act = (in >> 1) & 1

  // ⓪ 备餐台摆料段：只跑节拍判定，其余全部冻结（§13.4）
  if inSeg: prepSegmentTick(act); tick += 1; return

  // ① 本台输入事件（§13）：炸锅压火、烤炉翻面
  stationPre(act)

  // ② 火候条（§6）
  top = TRACK − H
  if hold && (yb == 0 || yb == top): vb = 0
  a = hold ? ACC : −ACC
  if inPrev: a = tdiv(a × 6, 10)
  vb += a;  yb += vb
  if yb > top:  yb = top; vb = −tdiv(vb × 2, 3)
  elif yb < 0:  yb = 0;   vb = −tdiv(vb × BB, 3)        // BB = 2，3 级起 1
  pin = (yb == 0 || yb == top) ? pin + 1 : 0
  pinned = pin >= 10

  // ③ 食材：固定 3 个子步（§7）
  repeat 3: fishSub()

  // ④ 判定（§8）
  geo   = yb <= yt && yt <= yb + H
  inBar = geo && !pinned
  side  = inBar ? 内 : (yt > yb + H ? 欠火 : yt < yb ? 过火 : (yb == 0 ? 欠火 : 过火))

  // ⑤ 调料瓶（§10）
  bottleStep(pinned)

  // ⑥ 本台中段：算本 tick 的熟度倍率 mul（‰），可能触发爆油（§13）
  mul, burst = stationMid(inBar)

  // ⑦ 熟度（§9）
  g = GAIN;  g = g×mul/1000;  g = g×PACE/1000;  g = g×MAST/1000;  g = g×BPACE/1000
  l = LOSS;  l = l×PACE/1000; l = l×BPACE/1000
  if inBar:                         P += g
  elif bState == 在场 && bIn:        (不变)
  else:                             P −= l
  if burst:                         P −= 60000
  if 烤炉 && flipIdx < flips:        P = min(P, 990000)

  // ⑧ 统计
  S += 1
  if inBar: I += 1; outRun = 0
  else:     (side == 欠火 ? U : O) += 1; outRun += 1; if outRun > 1: perfect = 0
  if 厨锅:  hSum += h

  // ⑨ 本台后段（§13）：烤炉自动翻面/翻面提示，备餐台进入摆料段
  stationPost()

  // ⑩ 收尾
  inPrev = inBar ? 1 : 0
  pt += 1;  tick += 1
  if P >= 1000000: P = 1000000; end = 出锅
  elif P <= 0:     P = 0;       end = 糊锅
  elif pt >= CAP:               end = 到点
```

## 6. 火候条

| 项 | 值 | 说明 |
|---|---|---|
| 长度 H | `max(180000, 150000 + 11000 × (L − 1))` | L1–3 保底 18%，L4 18.3% … L10 24.9%（v2 加保底：L1 的 15% 比星露谷 0 级还短） |
| 加速度 ACC | 3,960 u/tick² | 星露谷 0.25 px/帧² × 1760 × 9 |
| 框住时 | × 6/10 | 用**上一 tick**的框住结果（本 tick 的判定在条移动之后才算） |
| 贴边按键 | 先把速度清零 | 星露谷原版做法，按住贴顶不会带回弹余速 |
| 碰顶 | `yb = top`，`vb = −vb × 2/3` | |
| 碰底 | `yb = 0`，`vb = −vb × BB/3` | BB = 2；**3 级「稳手」起 BB = 1** |
| 顶死 / 熄火 | 贴顶或贴底连续 ≥ 10 tick（0.5 秒）后，这些 tick 一律不算框住（调料瓶也抓不了） | 防「一直按住」「一直松开」挂机。贴顶 = 猛火失控（记过火），贴底 = 熄火（记欠火）。界面火苗变灰。正常碰一下弹回来不会触发。 |

## 7. 食材 AI（星露谷鱼 AI，每 tick 3 个子步）

### 7.1 难度值 D
`D = clamp(星级基础值 + 性子修正, 0, 100)`

| ★ | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| 星级基础值 | 32 | 40 | 47 | 54 | 61 | 67 | 73 |

| 性子 | 混 | 窜 | 稳 | 沉 | 浮 |
|---|---|---|---|---|---|
| 修正 | 0 | −6 | +11 | −2 | −1 |
| 行为 | 随机大移动，偶尔小跳 | 时不时短距离急窜（v2 起概率是 v1 的 1/3） | 走到一个点停下再走，没有小跳 | 总往 30% 线沉 | 总往 70% 线浮 |

对照星露谷：D32 ≈ 太阳鱼，D54 ≈ 鲑鱼，D73 ≈ 鲟鱼。

### 7.2 子步（每个正式 tick 跑 3 次；摆料段不跑）
速度 `vt`、漂移 `ad` 的单位都是「u/子步」。`NONE = −1` 表示当前没有目的地。

```
fishSub():
  // 固定抽 8 个数，不管后面用不用（保证抽签次数与输入无关）
  a1 = rT.rnd(4000)
  a2 = rT.range(10, 44)
  a3 = rT.range(100000, 899999)
  a4 = rT.range(10, 29)
  a5 = rT.rnd(2000)
  a6 = rT.range(88000, 177759)
  a7 = rT.rnd(dartChanceDiv)                     // v2：3000（v1 是 1000）
  a8 = rT.next()                                  // 原始 32 位：bit0 小跳方向，bit1 急窜方向，>>>2 急窜距离

  // 1 换目的地
  mul = (性子 == 稳) ? 20 : 1
  if (性子 != 稳 || tgt == NONE) && a1 < D × mul:
      pct = min(99, D + a2)
      tgt = yt + tdiv((a3 − yt) × pct, 100)

  // 2 沉 / 浮漂移（到线就停，不贴死底/顶）
  if 性子 == 沉: ad = (yt > 300000) ? max(ad − 18, −2640) : 0
  if 性子 == 浮: ad = (yt < 700000) ? min(ad + 18,  2640) : 0

  // 3 追目的地 / 小跳 / 滑行，三选一
  if tgt != NONE && |yt − tgt| > 5280:
      div = a4 + 100 − min(100, D)
      acc = tdiv(tgt − yt, div)
      vt  = vt + tdiv(acc − vt, 5)
  elif 性子 != 稳 && a5 < D:
      tgt = (a8 & 1) ? yt + a6 : yt − a6
  else:
      tgt = NONE

  // 4 窜：急窜
  if 性子 == 窜 && a7 < D:
      dmax = (101 + 2D) × 1760
      size = 88000 + ((a8 >>> 2) % (dmax − 88000))
      tgt  = ((a8 >>> 1) & 1) ? yt + size : yt − size

  // 5 夹取与移动
  if tgt != NONE: tgt = clamp(tgt, 100000, 900000)
  yt += vt + ad
  if yt < 100000: yt = 100000; vt = 0
  elif yt > 900000: yt = 900000; vt = 0
```

### 7.3 与星露谷的偏离（防挂机必需）
- 开局条和食材都在正中，并且有开局第一跳；
- 沉/浮停在 30%/70% 线，不再贴死底/顶；
- 食材只在 10%–90% 活动（保证不用顶死、不用贴底也能框到）；
- 顶死/熄火 0.5 秒后不算框住。

熟悉星露谷的玩家会发现「沉底鱼」不太一样了。不改的话，完全挂机做「沉」性子 ★1 能出超凡（「手感」方案已实测）。

### 7.4 速度量级
子步算法与「手感」方案逐帧一致，「混」的速度分布可直接引用：★1 中位 3%/秒、p99 19%/秒；★4 中位 6%、p99 33%；★7 中位 10%、p99 56%（单位：轨道/秒）。火候条按住 0.5 秒就有 79%/秒，所以 ★1–★4 都追得上，★7 的冲刺要靠预判。

## 8. 判定

- 在条内：`yb ≤ yt ≤ yb + H`，且不在顶死/熄火状态。
- 判定发生在**本 tick 火候条和食材都移动之后**。
- 不在条内时记方向：食材在条上方 = **欠火**（火给小了）；在条下方 = **过火**（火给大了）；几何上在条内但被顶死 = 过火，被熄火 = 欠火。
- 方向用于负面（§14.5），界面上出条时显示「火小了 ↑ / 火大了 ↓」箭头。

## 9. 熟度（进度）

| 项 | 值 |
|---|---|
| 范围 | 0 – 1,000,000 |
| 起点 P0 | 250,000（25%），每级手熟 +20,000，最高 350,000 |
| 基础涨速 GAIN | 4,689 /tick（全程框住正好 160 tick = 8.0 秒出锅） |
| 基础掉速 LOSS | 4,689 /tick；**6 级「耐火」起 3,516** |
| 台子节奏 PACE‰ | 厨锅 800 / 炸锅 1000 / 烤炉 1000 / 备餐台 1250（涨掉都乘） |
| 本台动态倍率 mul‰ | 只乘涨速，见 §13（厨锅火候、炸锅油温、烤炉焦面） |
| 手熟 MAST‰ | 1000 + 80 × 手熟级（只乘涨速） |
| 批量 BPACE‰ | 1 份 1000 / 2 份 750 / 3 份 620 / 4 份 540 / 5 份 480 / 6 份 440（涨掉都乘） |
| 瓶护 | 没框住食材、但调料瓶仍在场且在条内时，本 tick 不掉熟度（星露谷：去抓宝箱时鱼的进度暂停下降） |
| 烤炉封顶 | 还有面没翻时熟度最多 990,000，翻完才能出炉 |

乘法顺序固定为 `GAIN → ×mul → ×PACE → ×MAST → ×BPACE`，每乘一步就 `/1000` 截断。

**时限 CAP**（正式 tick）= `baseCapTicks × 1,000,000 / (时限节奏‰ × BPACE)`（整除），`baseCapTicks = 300`，时限节奏‰ `stationCapPm` = 厨锅 1000 / 炸锅 1000 / 烤炉 1000 / 备餐台 1250。单份时：厨锅、炸锅、烤炉 300（15 秒），备餐台 240（12 秒 + 摆料段）。

> v2：时限从 400 改 300，厨锅不再跟 PACE 800 拉长到 25 秒。熟度涨速 = 掉速，框住率低于约 77% 就到不了满，v1 的长时限只是让新手熬 20–25 秒再出同样的低/中 + 夹生。厨锅满火时实际节奏 0.8 × 1.3 ≈ 1.04，和别的台一样，所以时限也一样。画布右下画倒数条，最后 3 秒闪「快到点」。

## 10. 调料瓶（宝箱）

| 项 | 值 |
|---|---|
| 种类与出现率 | 每局最多 1 个。普通瓶‰ = `250 + 15×(L−1)`；金瓶‰ = `12 + 3×(L−1)`（v2 下调，v1 是 30 + 8×(L−1)）。有没有瓶由种子定（`bottleRoll < 普通‰ + 金‰`，§4.2）；**是不是金瓶由服务端私下抽**，概率 金‰ ÷ (普通‰ + 金‰)，瓶出现时才告诉客户端 |
| 出现时刻 | 第 `bAt` 个正式 tick：`range(20 × 1000 / MAST, 60 × 1000 / MAST)`。手熟 0 时 20–60（开局后 1–3 秒），手熟 5 时 14–42（v2：跟着节奏提前） |
| 出现位置 | `pos = yt ± bOff`（`bDir` 定方向），`bOff = range(H × 550 / 1000, H × 900 / 1000)`（v2：0.55–0.9 个火候条长；v1 是 20%–45% 轨道）；越出 [100000, 900000] 就换另一侧；再夹到 [100000, 900000]。之后不动、不消失，直到被抓或本局结束 |
| 抓取 | 每 tick：瓶在条内（且没顶死/熄火）→ `K += bFill`（`= 34000 × MAST / 1000`，手熟 0 时 34000）；否则 `K −= 30000`（**9 级「眼尖」起 15000**），最低 0。`K ≥ 1,000,000` 即抓到（手熟 0 时连续框住 30 tick = 1.5 秒，手熟 5 时 22 tick） |
| 收益 | 任一种瓶：总分 +40。金瓶 + Perfect + 正常出锅 + 单份局 → 闪耀 |
| 界面 | 出现时「叮」，金瓶带金光和弦（种类在瓶出现时揭晓）；Perfect 一断，金瓶在界面上褪成普通色（提示闪耀机会没了），但照样能抓来加分 |

**设计张力**（v2）：瓶离食材 0.55–0.9 个火候条长。保持 Perfect 的人可以把食材压在条的一端、瓶放在另一端，硬扛 1.5 秒——紧张但可控；读种子的完美机器人在出金瓶的局里抓到 67–79%（v1 低星只有 7–17%，全看食材碰巧游过去）。没有 Perfect 时，普通瓶的 +40 正好能把 920 分拉过超凡线——「贪不贪」的抉择还在。瓶够得着以后，金瓶率下调，闪耀总量仍在 §1 目标内（§16.3）。

**为什么种类要私下抽**：种子必须下发（客户端要实时跑），v1 的种类从种子推出，读种子的外挂能只在金瓶局打 Perfect（完美外挂 ★7 闪耀率是熟练真人的 10 倍），而且 Perfect 率很低，躲开「★6 以上 Perfect > 80%」的检测。v2 种子只决定「有没有瓶、在哪、何时出现」，外挂最多知道「这局有瓶」。

## 11. Perfect

同时满足才算 Perfect：
1. 从第 0 个正式 tick 到出锅，食材**从没连续 2 个 tick 离条**（单个 tick 擦边原谅）；
2. 本台零失误：
   - 厨锅：无额外条件；
   - 炸锅：没有爆油，且过热 tick + 冷油 tick ≤ 20；
   - 烤炉：每次翻面都是「正好」（含提示出现前 3 tick 内的预判按键，§13.3）；
   - 备餐台：没有漏拍、没有乱按（只按出「可以」不算失误）；
3. 结束方式是出锅（不是到点、糊锅、撂勺）。

界面左上挂「✦ PERFECT」徽章，第一次失误就碎裂。规则一句话：**Perfect 必超凡，Perfect + 金瓶必闪耀**（批量局除外）。

## 12. 结束条件

| 结局 | 条件 | 结果 |
|---|---|---|
| 出锅 | `P ≥ 1,000,000` | 按 §14 结算 |
| 糊锅 | `P ≤ 0` | 家常菜（无品质、无厨师效果、0 经验，料不退） |
| 到点 | `pt ≥ CAP` 还没出锅 | 强制出锅：按 §14 结算后品质封顶「中」，必带夹生 |
| 撂勺 | 主动放弃、关界面、离台 > 8 格、死亡、换维度、下线、台子被拆、5 秒收不到输入（含客户端自己停住 5 秒）、输入包不合法 | 家常菜（台子被拆时掉在地上），0 经验，料不退 |

同一 tick 内按 出锅 → 糊锅 → 到点 的顺序判，取第一个。撂勺由服务端在 tick 之间判定。

## 13. 四台附加规则

四台共用 §3–§12 的内核。每台只多一组状态量、最多一个动作键。九个烹饪台方块（炸锅/烤炉/备餐台 × 田园/不锈钢/中式）只换贴图，规则完全相同。

| 台 | 练什么 | 动作键 | 本台扣分来自 | 本台零失误（Perfect 条件） | 默认性子 | PACE‰ |
|---|---|---|---|---|---|---|
| 厨锅 | 稳：攒火候 | 无（单键，适合新手） | 平均火候低 | 无 | 按菜名（§13.6） | 800 |
| 炸锅 | 一心二用：压油温 | 压火 | 过热、冷油、爆油 | 不爆油，且过热+冷油 ≤ 20 tick | 浮 | 1000 |
| 烤炉 | 抓时机：翻面 | 翻面 | 翻早、稍晚、焦面、自动翻 | 每次都「正好」 | 按菜名（§13.6），没填时混 | 1000 |
| 备餐台 | 节奏：按顺序摆料 | 摆料 | 只按出「可以」、漏拍、乱按 | 不漏拍、不乱按 | 混（冷饮浮） | 1250 |

所有台子的扣分、负面贡献都在结算时一次算出（§14）。

### 13.1 厨锅（农夫乐事厨锅，看火候）· 攒火候
**规则**
- 火候 `h ∈ [0, 1000]`，开局 300。
- `stationMid`：框住 → `h = min(1000, h + 30)`；没框住 → `h = max(0, h − 80)`；`mul = 700 + h × 600 / 1000`（0.7×–1.3×）。
- 每个正式 tick 把 `h` 累加进 `hSum`；平均火候 `avgH = hSum / S`。

**感觉**：汤要慢慢熬。稳住 1 秒多火就旺，越做越快；一断火，火候掉得很快。这台奖励「稳」，不奖励「抢」。

**扣分与负面**：本台扣分 = `(1000 − avgH) / 8`；欠火 += `(1000 − avgH) / 6`（火候不够，菜就夹生）。

**换皮**：轨道是汤锅侧剖面，火候条是一段发光的火候区，食材是这道菜的主料图标在汤里上下翻；左边一根火苗柱显示 h（小火/中火/旺火），h 满时汤面冒泡、咕嘟声；熟度条画成一只碗慢慢盛满。

**接入**：厨锅就是农夫乐事厨锅，下方要有热源。放好料不点掌勺，锅按农夫乐事原样慢慢煮出家常菜（§17.15）。

### 13.2 炸锅（看油温）· 压油温
**规则**
- 油温 `T`，开局 450；压火冷却 `cd`，开局 0。
- `stationPre`：先 `if cd > 0: cd −= 1`；然后 `if act && cd == 0: T = max(0, T − 280); cd = oilCd[L]`（冷却期内按无效、不罚）。
  oilCd：L1 34 → L10 25（每级 −1）。
- `stationMid`：`rise = (inBar ? 4 : 3) + (★ − 1) / 3 + P / 300000`（最后一项 0–3，炸到后面升得越快）；**`T ≥ 750`（已在过热区）时 `rise = rise / 2`**（v2）；`T += rise`。然后：
  - `T ≥ 1000` → **爆油**：`T = 550`，`bursts += 1`，本 tick 熟度额外 −60,000，食材被溅：`vt += ±8333`（方向取 `kickBits` 的第 `kickN & 31` 位，1 = 往上；然后 `kickN += 1`），`mul = 1000`；
  - `750 ≤ T < 1000` → 过热：`hot += 1`，`mul = 1000`（v2：v1 是 1200「熟得快」，但这对分数没有任何好处，只会让人以为有取舍）；
  - `T < 300` → 冷油：`cold += 1`，`mul = 600`；
  - 其余（金黄区 300–749）→ `mul = 1000`。

**感觉**：一只手稳住火候条，一只手盯油温表，大约每 2–3 秒压一次火。漏压一次是斜坡、不是悬崖：进了过热区升温减半，从 750 升到 1000 要 3–4 秒，期间扣分、攒烧焦，漏压两次才爆油。油温到 880 时温度计抖动、字变成「快压火！」（界面预警，不进内核）。

> v2 依据（瞟油温模型：熟练手 ★4 L5，每隔约 G 秒看一眼油温，看的 0.3 秒里看不到食材）：v1 在 G = 2 秒时 12% 的局爆油、G = 3 秒时 97% 爆油、Perfect 为 0；v2 在 G = 2 秒时 0% 爆油、过热 5% 的时间、超凡+ 51%（专心看 68%），G = 3 秒时仍 0% 爆油，过热 30% 的时间、多数出中品质。`oilRiseIn` 5 → 4 只拉长压火间隔，专心看的人结果不变，瞟着看的人超凡+ 从 30% 回到 50%。

**扣分与负面**：过热‰ = `hot × 1000 / S`，冷油‰ 同理。本台扣分 = `过热‰/3 + 冷油‰/3 + 80 × bursts`；过火 += `过热‰/2 + 150 × bursts`（烧焦）；乱 += `冷油‰/2`（油没热就下锅，菜吸油 → 倒胃）。

**换皮**：油锅侧剖面，火候条是一把漏勺，食材在油里翻滚；右侧竖油温计分蓝/金/红三色带，压火键旁一圈冷却环；爆油时屏幕一抖、溅油花、「滋啦」一声。

**适用**：大炸饺、春卷、盘装大炸饺、春卷拼盘（★2–★4）；可从厨锅迁入的炸鱼薯条、鱿鱼圈、炸蟹角、恩潘纳达炸饺、蜂蜜炸海带。

### 13.3 烤炉（火候 + 翻面）· 翻面
**规则**
- 每道菜要翻 `F` 次（菜表 flips 列）：默认 1；烤串 3；盛宴和整只烤肉 2。
- 翻面点 `mark_k = P0 + (1,000,000 − P0) × k / (F + 1)`，k = 1..F，在进度条上画小三角。
- `stationPost`：
  - 若提示正生效且 `pt − prompt ≥ 80` → **自动翻**（最差评价），`flipIdx += 1`，`prompt = −1`，`burn = 0`，溅射；
  - 若没有生效中的提示、`flipIdx < F` 且 `P ≥ mark[flipIdx+1]` → `prompt = pt + 1`（「翻面！」提示从下一个正式 tick 起生效）。
- `stationMid`：提示生效中且 `pt − prompt > flipGood[L] + 12` → 这一面开始烤焦：`burn += 1`，`mul = 500`。
- `stationPre`（`act` 时）：
  - 提示生效中：`dt = pt − prompt`。`dt ≤ flipGood[L]` → **正好**；`dt ≤ flipGood[L] + 12` → **稍晚**；更晚 → **焦面**（结算本面的 `burn`）。然后 `flipIdx += 1`、`prompt = −1`、`burn = 0`、溅射；
  - 没有提示、`flipIdx < F`：算离翻面点还差多少熟度 `d = mark[flipIdx+1] − P`，按满速涨速 `g0`（框住、本台倍率 1000 时每 tick 涨多少，§9 同一条截断链）换算成 tick（v2）：
    - `d ≤ 3 × g0`（提示出现前 3 tick 内）→ **正好**，消耗这次翻面（`flipIdx += 1`、溅射），这个翻面点的提示不再出现；
    - `d ≤ 12 × g0`（早 4–12 tick）→ **翻早·轻**，扣分、负面和「稍晚」一样轻；
    - `d ≤ 20 × g0`（早 13–20 tick）→ **翻早·重**；
    - 更早按 → 无效、不罚（防误触）。
    翻早两档都算这次翻面（`flipIdx += 1`、溅射），这个翻面点的提示不再出现。一直狂按动作键的人，第一下落在「翻早·重」档，白拿不到「正好」。
- flipGood：L1 8、L2 8、L3 9、L4 9、L5 10、L6 10、L7 11、L8 11、L9 12、L10 13（tick）。
- 溅射：`vt += ±(4000 + 500 × ★)`（u/子步），方向同炸锅取 `kickBits`。
- 还有面没翻时熟度封顶 990,000（§9）。

**感觉**：平时就是普通钓鱼条。盯住进度条上的三角提前做好准备（离三角约 0.3 秒时三角先闪），一到点按一下，再立刻接住蹦起来的食材。

> v2 依据：v1 只要早 1 tick 按就判「翻早」（扣 60、夹生 +120），比「稍晚」罚得重，而界面上的三角又在引导人预判——盯三角按的人在计时误差 σ = 50/100/150 ms 时有 28%/42%/43% 被判翻早。v2 预判型熟练玩家（σ = 50/100/150 ms）翻早 5%/9%/16%，正好 95%/91%/84%，超凡+ 与看提示反应的人相同（63–64%）。

**扣分与负面**（逐次相加）
| 评价 | 扣分 | 负面 |
|---|---|---|
| 正好 | 0 | — |
| 稍晚 | 25 | 过火 +60 |
| 翻早·轻（早 4–12 tick） | 25 | 欠火 +60 |
| 翻早·重（早 13–20 tick） | 60 | 欠火 +120（夹生） |
| 焦面 | `min(200, 100 + burn)` | 过火 `min(300, 150 + 3 × burn)` |
| 自动翻 | 200 | 过火 +300（烧焦） |

**换皮**：烤箱玻璃门视角，火候条是烤架上的火区；翻面时食材图标转 180°，配「翻面！」大字和计时环；派、蛋糕类的翻面动画换成「转烤盘」。

**适用**（36 道）：派与蛋糕、烤肉、曲奇与吐司、烤串。

### 13.4 备餐台（摆盘节奏）· 摆料段
**规则**
- 段数 `segs`：**全部一段**（v2；v1 是 ★6–★7 两段，`segmentsByStar` 可配，内核保留两段的路径）。摆料点 `segMark_k = P0 + (1,000,000 − P0) × k / (segs + 1)`。
- 节拍总数 `n = clamp(这道菜的不同食材数 + 1, 3, 8)`（最后一拍是「装盘/盖顶」，菜表 beats 列可覆盖）。两段时第一段 `ceil(n/2)` 拍，第二段其余。
- 节拍时刻（段内相对时刻，开局一次排好）：段内第一拍在 **16**（v2；v1 是 24，首拍前空等 1.2 秒）；之后每拍 = 前一拍 + `max(7, beatGap[★] + jit[k])`，`k` 是这一拍在整局里的序号（0 起）。beatGap：★1 14、★2 13、★3 12、★4 11、★5 10、★6 9、★7 8（tick）。
- `stationPost`：`segIdx < segs` 且 `P ≥ segMark[segIdx+1]` → `inSeg = 1, segT = 0, bi = 0`，**下一 tick 起**进入摆料段。
- 摆料段内（§5 第 ⓪ 步）：食材、火候条、熟度、调料瓶全部冻结；不计入 S、不计入时限、`pt` 不增加；主键输入忽略。每 tick：
  ```
  prepSegmentTick(act):
    Tm = 本段节拍时刻表; c = 本段拍数; gw = goodW[L]; t = segT
    if bi < c && t > Tm[bi] + gw: miss += 1; bi += 1          // 漏拍
    if act && bi < c:
        d = |t − Tm[bi]|
        if d <= 1:      perfB += 1; bi += 1                  // 正好
        elif d <= gw:   okB += 1;   bi += 1                  // 可以
        else:           mash += 1                            // 乱按（不消耗这一拍）
    segT += 1
    if segT >= Tm[c−1] + gw + 9: inSeg = 0; segIdx += 1       // 最后一拍判完再过 8 tick
  ```
  goodW：L1–L4 为 2，L5–L10 为 3。段内所有拍都判完后再按动作键：忽略。

**感觉**：钓鱼条里插了一小段音游。节拍图标就是这道菜的食材，按顺序落进盘子，汉堡一层层摞起来。乱按会被罚，糊弄不过去。

**界面**（v2）：还没进段时，下一段的料按开段那一刻的位置提前排在节拍道上（半透明），进段时不跳；最后一拍判完后那 0.6 秒（`goodW + beatTail + 1`）轨道不再压暗，显示「接住！」和当前按键状态（恢复后第一 tick 用的就是它）。

> v2 依据：v1 完美手一局 10.4–11.4 秒，摆料段占 38–44%，★6–★7 两段合计空等 3.6 秒。v2 首拍前空等 0.8 秒、★6–★7 并成一段，完美一局 9.4–10.6 秒；空等每局约 1.4 秒。8 拍的菜摆料段仍约占 4 秒（见 §22 待拍板 P）。

**扣分与负面**：扣分 = `8 × 可以 + 50 × 漏拍 + 20 × 乱按`；乱 += `漏拍 × 500 / n + 40 × 乱按`（摆乱了 → 倒胃）。备餐台没有火，所以过火方向的负面**显示为「多盐」**（料放多了），欠火方向仍叫「夹生」（没拌匀、没处理好）。

**换皮**：案板俯视，火候条是手或刀；进入摆料段时轨道变暗，下方出现横向节拍道，图标沿它滑向盘子，拍点有节拍灯和「嗒」声（客户端按帧时钟本地播放，另给音画校准偏移）。

**适用**（52 道）：汉堡、卷饼和塔可、三明治、寿司和饭团、沙拉冷盘、拼盘。

### 13.5 冷饮（并进备餐台，「摇杯」皮）
规则与备餐台完全相同，只改：节拍等距（不加 jit）、间隔 = `max(7, beatGap[★] − 2)`、固定 6 拍、默认性子「浮」。图标换成冰块和雪克杯，拍点就是摇一下。适用 12 道：拿铁、冰淇淋、奶昔、冰棍、果汁等。

### 13.6 性子分配
菜表 `motion` 列逐道覆盖；没填时按台子和菜名关键字（`sim/dish-play.tsv` 是把这张表套到 204 道菜上的结果，即给菜表补 motion / flips / beats 三列的提案，仿真的「真实菜性子矩阵」也按它跑）：

| 台 | 稳 | 沉 | 窜 | 浮 | 其余 |
|---|---|---|---|---|---|
| 厨锅 | 汤/羹/炖/煲/粥/火锅 | 水饺/馄饨/饺子/汤圆 | 虾/蟹/鱿鱼/鱼/贝 | 甜品/糖水/布丁/果冻/酱 | 混（饭/面/炒/烩） |
| 炸锅 | — | — | 虾/鱿鱼/蟹 | **默认** | — |
| 烤炉 | 派/蛋糕/面包/挞/披萨 | 烤肉/整只/排/火腿 | —（v2：烤串改「混」，不再「窜 + 翻 3」叠加） | — | 混（曲奇/吐司/烤串…） |
| 备餐台 | 沙拉/冷盘/色拉 | — | 寿司/饭团/海鲜 | 冷饮 | 混 |

## 14. 结算

### 14.1 统计量（只算正式 tick）
- `S` 计分 tick 数（≥ 1）；`I` 框住；`U` 欠火；`O` 过火；`I + U + O = S`。
- 准度 `C‰ = I × 1000 / S`。
- 抓到瓶 `bottle = (bState == 已抓到) ? 1 : 0`；金瓶 `gold = (种类 == 金)`。

### 14.2 本台扣分 pen
| 台 | pen |
|---|---|
| 厨锅 | `(1000 − avgH) / 8` |
| 炸锅 | `过热‰/3 + 冷油‰/3 + 80 × bursts` |
| 烤炉 | 各次翻面评价扣分之和（§13.3） |
| 备餐台 | `8 × 可以 + 50 × 漏拍 + 20 × 乱按` |

### 14.3 总分
`score = max(0, C‰ − pen + 40 × bottle)`。准度是本钱，本台规则只扣分，调料瓶加一点；四台口径相同，换台刷不了分。

### 14.4 品质（从上往下取第一个满足的）
| 品质 | 条件 |
|---|---|
| 闪耀 | 出锅 且 Perfect 且 抓到瓶 且 这只瓶是金瓶（服务端私下抽的 `ext.gold`）且 单份局 |
| 超凡 | 出锅 且（Perfect 或 score ≥ **960**） |
| 高 | score ≥ **890** |
| 中 | score ≥ **760** |
| 低 | 其余 |

**之后再套上限（取最低）**：到点 → 中；批量 → 高；慢放（§18.6）→ 高；机械节奏（§18.7）→ 中；可疑分 ≥ 40 → 超凡；可疑分 ≥ 80 → 高。
糊锅、撂勺不进结算，直接出家常菜。

**阈值含义**：960 / 890 / 760 ≈ 整局丢失时间 ≤ 4% / ≤ 11% / ≤ 24%；一局 10 秒约等于丢了 0.4 / 1.1 / 2.4 秒。

**举例**
- 厨锅，准度 97.5%，平均火候 920（扣 10），抓到普通瓶：975 − 10 + 40 = 1005 → 超凡。
- 炸锅，准度 93%，过热 3%（扣 10）：920 → 高。
- 烤炉，准度 90%，一次稍晚（扣 25）：875 → 中。
- 备餐台，准度 99%（单 tick 擦边 2 次，不断 Perfect），没漏拍没乱按，抓到金瓶 → 闪耀。

### 14.5 负面（翻车）
**原则**：负面只出在低/中/高；超凡和闪耀永远干净。带哪种、带几条，完全由这局怎么做砸的决定，不掷骰。结算屏写清原因。

**三个翻车值（‰）**
| 值 | 基础 | 各台贡献 | 对应负面 |
|---|---|---|---|
| 欠火 | `U × 1000 / S` | 厨锅 `(1000 − avgH)/6`；烤炉 翻早·轻 +60 / 翻早·重 +120 | 夹生 |
| 过火 | `O × 1000 / S` | 炸锅 `过热‰/2 + 150×bursts`；烤炉 稍晚 +60 / 焦面 `min(300, 150+3×burn)` / 自动翻 +300 | 烧焦（备餐台显示为**多盐**） |
| 乱 | 0 | 炸锅 `冷油‰/2`；备餐台 `漏拍×500/n + 40×乱按` | 倒胃 |

**按品质挑**
| 品质 | 门槛 | 最多几条 |
|---|---|---|
| 低 | ≥ 40 | 2（取最大的两个） |
| 中 | ≥ 120 | 1 |
| 高 | ≥ 150 | 1 |

> v2：中/高门槛从 80 / 80 改为 120 / 150。v1 时中品质 86–91% 带负面、普通玩家在推荐等级 39–69% 的出品带负面，「负面」成了常态而不是「翻车」。v2 普通玩家在推荐等级带负面：★1 8% / ★2 10% / ★3 15% / ★4 16% / ★5 26% / ★6 30% / ★7 44%；熟练玩家各星合计 5%。高品质只在明确事故时才带：爆油（过火 +150）、焦面、自动翻、漏拍；厨锅追条丢一点永远不会让高品质带负面。

值相等时按 夹生 > 烧焦/多盐 > 倒胃 的顺序取。**到点**：挑完后若没有夹生就补上夹生，总数超过 2 条时去掉最小的那条。**快手**：固定 低 + 多盐（§17.8）。**批量**：整锅只算一次，N 份带同样的负面。

**负面效果**（强度沿用 ChefConfig 现有键，按成品品质 低/中/高）
- 夹生 UNDERDONE：缓慢 / 挖掘疲劳 / 虚弱三选一（**按菜品 id 固定**，tooltip 写明），12 / 8 / 6 秒，**必定生效**（原触发概率作废）。
- 烧焦 SCORCHED：吃下扣最大生命 8% / 5% / 3%，至少留 1 血，不致死。
- 倒胃 NAUSEA：中毒 II 8 秒 / I 6 秒 / I 4 秒。
- 多盐 OVERSALT：这一口饱和度减半。
- 失败品 SPOILED：小游戏不再产出，代码保留给腐烂系统和旧菜兼容。
- 负面带「厨师翻车」旁路标记，铁胃挡不了、回甘不缩短（效果池 v3 已定）。成品 tooltip 写明带了哪些负面，买家能看见。

**结算屏写法**：「高品质 · 夹生（9% 的时间食材在火候条上方——火给小了）」；「中品质 · 倒胃（摆料漏了 2 拍）」；「低品质 · 烧焦 + 倒胃（爆油 1 次，冷油下锅 12%）」。

### 14.6 经验
`xp = rawXp[品质] × (1000 + 150 × (★ − 1)) / 1000 × (1000 + 400 × (N − 1)) / 1000`（逐步整除）
- rawXp 沿用：低 50 / 中 80 / 高 130 / 超凡 220 / 闪耀 400；N = 批量份数（单份 1）。
- 糊锅、撂勺、快手、家常、练习：0。入账走 `ChefXpHandler`，每日衰减沿用 LevelingService。

## 17. 流程

### 17.1 台子与按钮
- 打开台子：放料槽、容器槽（碗、瓶等）、出品槽，另有**调料槽**（§17.16）。放进一份完整配方后显示：成品、★、厨师效果与大类、性子图标、本台规则一句话、推荐等级、本局火候条长度（占轨道%）、两种瓶的出现率、手熟级与进度、个人最佳。
- 厨师看到四个按钮（做不了的置灰并写明原因）：
  - **[掌勺]**：做 1 份，玩小游戏，有机会出闪耀。
  - **[批量 ×N]**：N = 2..min(等级上限, 料够几份)；这道菜手熟 ≥ 熟练才能用。玩一局更长的小游戏，N 份同品质，最高「高」，不出闪耀。
  - **[快手 ×N]**：N = 1..16；这道菜手熟 ≥ 入门才能用。不玩小游戏，固定低品质 + 多盐，0 经验。
  - **[家常]**：不玩，和非厨师一样出家常菜。Shift+点 = 剩下的料全做家常。
- 非厨师只看到 **[开火]**，效果等于家常。
- 别人打开正在掌勺的台子只能旁观：「××正在掌勺（熟度 63%）」。台子方块按服务端回放的状态冒烟、起火、滋啦作响。

### 17.2 开局（服务端）
1. 客户端发开局请求：位置、做法（掌勺/批量/快手/家常/练习）、份数。
2. 服务端校验：是厨师；等级门槛；手熟门槛（批量/快手）；配方齐、够 N 份；出品槽放得下（放不下时成品留台内暂存，收走前不能开下一局）；台子空闲且本人没有别的局；距离 ≤ 6 格且界面开着；令牌桶有令牌；信用点够 N 份（§17.18）；厨锅下方有热源。
3. 通过后：把 N 份料从放料槽移进台内**「锅内暂存」**（漏斗抽不走、别人拿不走、只是移走不删除）；扣信用点；锁台给这位厨师；生成 roundId 与种子；按 §18.4 算好参数块；发 S2C 开局包。**从这一刻起本局生效，不能免费取消。**

### 17.3 倒计时
20 tick（1 秒），画面「3·2·1 下锅！」（数字放大两倍、垫在不透明底上，不和食材叠在一起）。火候条居中、食材在条正中、什么都不动，不记输入。倒计时期间关界面 = 撂勺（防看到种子不喜欢就重开）；倒计时里第一次按 Esc 也会提示「再按一次 Esc 撂勺」。

### 17.4 进行中
客户端按真实时钟跑内核、每 tick 采样输入、每 20 tick 上报一包（§18.5）。服务端边收边回放。界面：竖轨道、火候条、食材、熟度条、PERFECT 徽章、实时品质徽章（按当前分数显示中/高/超凡，越线变色）、本台仪表（火苗柱 / 油温计 / 翻面三角 / 节拍道）、出条箭头、轨道旁「生/焦」两根小槽（欠火‰、过火‰ 实时值；红线 = 中品质门槛 12%，过线变红；开局前画空）、调料瓶、**时间**（已用 / 时限 + 倒数条，最后 3 秒闪「快到点」；摆料段写「摆料中」不计时）。

**预警与提示**（v2，只改界面、不进内核）：
- 出条变红、出条箭头按同一帧画出来的位置判断（预测渲染，§3.1）；按下主键时条上沿亮一下。
- 火候条贴边 5 tick（0.25 秒）起条边闪红，并提示「贴底久了会熄火 / 顶太久会顶死」（10 tick 才真熄火 / 顶死）。
- 炸锅油温到 880 温度计抖、字变「快压火！」；烤炉离三角约 0.3 秒时三角先闪；备餐台下一段的料提前排在节拍道上，摆完显示「接住！」和当前按键状态。
- 亮色提示字（黄、橙、红）一律垫深色底再写（浅灰面板上直接写对比度只有约 1.6:1）。
- 新手落点虚影只画离食材超过半根火候条的目的地（§15.2）。

**爽快反馈**：框住时滋滋声、音调随熟度升高；丢失时「嗤」一声、条边闪红；碰顶碰底「咚」；瓶出现「叮」、金瓶金光和弦、抓到爆一圈粒子；熟度过 75% 进入「收汁」，音乐加快、锅气粒子增多；出锅大字盖章显示品质，Perfect 额外弹「Perfect!」，闪耀全屏金光。

### 17.5 出锅
- 客户端先按本地结果播「出锅中…」（≤ 0.5 秒），服务端回放结果到达后覆盖；不一致时以服务端为准并记日志。
- 服务端在同一 tick 内依次：清空锅内暂存 → 盖章出 N × 配方产出（§17.17）→ 放进出品槽 → 消耗调料（抓到瓶时）→ 经验入账 → 手熟 +1（结果 ≥ 中）→ 记个人最佳 → 广播 `ChefEvents.fireDish` → 闪耀时可选全服播报「××做出了闪耀的××」。
- 结算屏：大字品质（闪耀金光）、准度、本台扣分明细、调料瓶（没出现/抓到/错过）、Perfect ✓/✗、负面与原因、经验、手熟进度、个人最佳。按钮：**[再来一份]**（回车，料够就直接开下一局）、**[收取]**、**[关闭]**。

### 17.6 连做
「连做」开关默认开：结算 30 tick（1.5 秒）后自动开下一局（新种子），按 Esc 或点「停止」就停。每局独立、各自一份品质，永远不会把一局的品质复制给别的份。

### 17.7 批量
- 份数 N 受等级上限（§15.2）和手熟 ≥ 熟练两个限制；开局一次扣 N 份料、N 份信用点。
- 熟度涨掉都乘批量系数（§9），难度不变、只是变长：6 份约是单份 2.3 倍时长，换 6 份成品。时限同比放宽。
- 结果：N 份同品质、同负面，**最高「高」**；金瓶率 = 0（不出闪耀），普通瓶照常出、照常加分。
- 经验 = 单份公式 × `(1000 + 400 × (N − 1)) / 1000`；手熟只 +1。

### 17.8 快手（跳过小游戏）
- 手熟 ≥ 入门才能用，一单 1–16 份；战斗菜门槛照旧；开局时一次把 N 份料移进锅内暂存、扣 N 份信用点、消耗 1 个令牌。
- 不打开小游戏。台子按**家常的用时**逐份做（新台子按配方 cookTime，默认 200 tick；厨锅按农夫乐事原时长），永远不比家常快；人可以走开，成品进出品槽。
- 成品：低品质 + 多盐，带这道菜的厨师效果（3 分钟）；0 经验；不加手熟。

### 17.9 家常
厨师可选，非厨师只能选它。没有品质、没有厨师效果、不玩小游戏、0 经验、不扣信用点，可批量（Shift+点）。厨锅走农夫乐事原生烹饪；新台子按配方 cookTime（默认 200 tick/份）。

### 17.10 糊锅
熟度掉到 0 立刻结束：这份料做成家常菜放进出品槽，0 经验，信用点不退。提示「火候没跟上，这锅只能算家常菜」，结算屏照样显示失误统计。

### 17.11 撂勺（中途离开）
- 第一次按 Esc 只提示「再按一次 Esc 撂勺（这锅会变家常菜）」，游戏不暂停（按住键视为松开）；1.5 秒内再按一次才真的撂勺。
- 以下一律立即按撂勺处理：二次 Esc、关界面、走出 8 格、死亡、换维度、下线、台子被拆（不管谁拆）、5 秒收不到输入、输入包不合法。
- 结果：料做成家常菜（台子被拆时掉在地上），0 经验，信用点不退。没有暂停、没有重来。

### 17.12 服务器关机 / 崩溃 / 区块卸载
对局只在内存里；台子 NBT 记「对局中」和锅内暂存。重新加载时发现没打完的局：**料原样退回放料槽、信用点退回**，不产出任何东西。玩家无法主动触发。

### 17.13 练习模式
台子上的「练习」按钮：不需要放料，可选任意星级、台子、性子，纯客户端运行，不出菜、不给经验、不占令牌。用来熟悉手感，原型阶段也拿来收集真人数据。

### 17.14 自动化
漏斗只能喂料和取成品。只有玩家亲手点按钮才会开局，所以自动化永远只出家常（快手需要玩家亲手下单）。

### 17.15 农夫乐事厨锅接入
- FD 厨锅自带烹饪进度、热源判定和漏斗支持。用 mixin 在它的界面加四个按钮；开局时把它自己的烹饪进度清零并暂停，结束后恢复；漏斗喂料只走 FD 原生的家常路径。
- 厨锅的菜照农夫乐事规则用碗取出；盛宴配方挪进厨锅后，一局出一整个盛宴方块，「首份永久、其余按超凡」规则不变。
- 随性乐事自带的炸锅删掉配方（stations.md 已有结论）。

### 17.16 调料槽（旧饱食类效果）
已拍板「调味台拆掉，旧饱食类效果并进厨锅流程（调料瓶）」：
- 每个台子有 1 个调料槽。开局时有调料的话，**抓到任一种调料瓶**就消耗 1 个调料，成品额外带上该调料对应的饱食类效果（增香/增量/回味，映射沿用 `SeasoningTag`/`SeasoningBias`，强度沿用 `[amplify]`/`[nourish_food]`/`[aftertaste_saturation]` 按成品品质），这个加成不占厨师效果槽。没抓到瓶不消耗。
- 调料是否提高调料瓶出现率：默认不提高（`seasoningBottleBonusPm = 0`），待拍板。

### 17.17 一次出多份的配方
一局的产出 = 配方产出数 × 份数 N，同一局全部同品质同负面。闪耀局只有 1 件闪耀、其余按超凡（与盛宴「首份永久、其余按超凡」一致）。建议新台子的配方尽量改成一次 1 份（待拍板）。

### 17.18 信用点
沿用 `tableUseCostCredit`（默认 5），语义改为：掌勺/批量/快手**开局时按份扣**，糊锅/撂勺不退，服务器崩溃退；家常不扣。经济未注入时放行不扣（沿用 `tryChargeTableUse`）。

## 18. 服务端权威

### 18.1 信任边界
客户端唯一能影响结果的，是每 tick 的两个输入位。星级、等级、手熟、台子、参数、种子都由服务端决定；结果由服务端回放重算；盖章只在服务端。客户端本地结果只用来显示。

### 18.2 种子与子流
- 开局时服务端用 `SecureRandom` 生成 `seed`（int32）和 `roundId`（int64），种子只用一次。
- 子流：`rT = Mulberry32(fmix32(seed ^ 0x0F00D5))`、`rB = Mulberry32(fmix32(seed ^ 0x0B0771E))`、`rS = Mulberry32(fmix32(seed ^ 0x057A7))`。改一条子流的抽法不会打乱另两条。
```
// Mulberry32（32 位回绕）
// JS
next(){ this.a=(this.a+0x6D2B79F5)|0; let t=Math.imul(this.a^(this.a>>>15),1|this.a); t=((t+Math.imul(t^(t>>>7),61|t))^t)|0; return (t^(t>>>14))|0; }
// Java
int next(){ a+=0x6D2B79F5; int t=(a^(a>>>15))*(1|a); t=(t+(t^(t>>>7))*(61|t))^t; return t^(t>>>14); }
rnd(n) = (next() >>> 1) % n          // n > 0
range(lo, hi) = lo + rnd(hi - lo + 1)  // 含两端
// fmix32：h ^= h>>>16; h = h*0x85EBCA6B; h ^= h>>>13; h = h*0xC2B2AE35; h ^= h>>>16   （JS 乘法用 Math.imul）
```
- 抽签纪律：rT 开局 1 个 + **每个正式 tick 固定 24 个**（3 子步 × 8）；rB 开局 4 个、之后不再抽；rS 开局 9 个、之后不再抽。抽签次数与输入无关。
- **瓶的种类**（v2）：开局时服务端另用 `SecureRandom` 抽一次：有瓶时 `gold = rnd(bottlePm) < goldPm`。它不进种子、不进参数块、不进状态哈希；只存在服务端的对局里，结算时作为 `ext.gold` 传给 `result`，并写进留档（§18.10，复核回放要用）。

### 18.5 输入编码与上报
- 每 tick 1 字节（§3.2）。整局最多约 `CAP + 摆料段 + 40` 字节，RLE 后一般几百字节。
- 客户端每 20 tick 发一包；掉线恢复后允许挤在一起发，单包 ≤ 40 tick。
- 倒计时的 20 tick 不上报。

### 18.6 回放与校验（每收到一包就推进一段，CPU 开销可忽略）
1. **格式**：roundId 属于此玩家且在进行；seq 连续；firstTick == 已收 tick 数；每段长度 ≥ 1；保留位为 0；单包 ≤ 40 tick。不合格 → 撂勺 + 日志 + 可疑分 +20。
2. **防快进**（墙钟，不看 TPS）：`已收 tick × 50 ≤ 距开局包发出的毫秒 − 1000 + 600`。违反 → 撂勺 + 可疑分 +40。网络延迟只会让玩家「更慢」，方向安全。
3. **防慢放**（v2 收紧）：
   - **每包滞后**：每收到一包，算 `偏移 = 距开局毫秒 − 1000 − 已收 tick × 50`，记下本局见过的最小偏移；`滞后 = 偏移 − 最小偏移`。**连续 3 包滞后 > 2000 ms，或末包滞后 > 2000 ms** → 本局封顶「高」、可疑分 +20、记日志。网络卡一下只会让一两包滞后、之后马上回落；慢放或「关键时刻冻住画面」的滞后会一直挂着（想追回来就会撞上防快进）。
   - **终局**：`距开局毫秒 ≤ 1000 + 结束 tick × 50 × 11/10 + 2000`，否则封顶「高」并记日志（v1 是 ×3/2 + 3000：一局 9 秒能慢放约 1.8 倍或冻住约 7.5 秒都不受罚，熟练玩家慢放后成绩≈高手）。
   - **客户端必须一次补跑完**：掉帧时一帧里把欠的 tick 全补上，不许像 v1 网页原型那样「每帧最多补 250 ms」（那等于悄悄慢放）；客户端停住超过 5 秒直接按撂勺（§3.1）。这样正常玩家的墙钟节奏不变，不会误伤。
4. **断流**：5 秒没收到包 → 撂勺。
5. **结束以服务端为准**：服务端算到出锅/糊锅/到点那一 tick 就结算，多发的 tick 丢弃。客户端声称结束而服务端未结束 → 余下 tick 按输入 0 补到结束，记为不同步。
6. **哈希**：每包的状态哈希、末包摘要与服务端不符 → 只记 desync 日志（seed、参数块、全部输入、两边哈希），以服务端为准，不打断游戏。

### 18.7 机械输入与可疑分
- **机械节奏（本局）**：去掉首尾段后，按住段和松开段各 ≥ **32** 段，且各自**全部**（`mechanicalSamePct = 100`）段长度相同 → 本局品质封顶「中」，可疑分 +20。
  > v2：v1 是 ≥ 16 段、≥ 90% 相同，会误伤稳定连点的真人（审查实测 10 Hz 轻点 9–97%）。v2 对周期抖动 ≥ 10 ms 的 10 Hz 轻点（开环按键流、游戏里闭环悬停两种模型）误判 0%，人类机器人 0%；周期抖动只有 5 ms 的极端稳手最高 3.5%。纯交替宏（每 tick、每 3 tick）仍 100% 命中。带随机抖动的悬停宏两种门槛都抓不到，靠下面的「不跟食材」统计；它本身做不出东西（封顶前出「高」及以上也只有约 5%，大多糊锅）。回归测试见 `bots.mjs` 的轻点悬停与开环按键流。
- **统计检测（跨局，只加可疑分，不直接改结果）**：
  - 预判：火候条加速度与食材加速度的互相关峰值，人眼跟随应落后 3–6 tick；最近 20 局有 ≥ 70% 峰值滞后 ≤ 1 tick → +15。
  - 不跟食材：最近 20 局里品质 ≥ 高、但互相关峰值极弱（悬停宏）的局 ≥ 70% → +15。
  - 急窜反应：食材急窜后第一次往正确方向改输入的延迟，最近 30 次里 ≤ 2 tick 的占 ≥ 60% → +15。
  - 调料瓶预判：瓶出现前 2 tick 火候条已覆盖其位置并朝它移动、而食材在别处，最近 20 个有瓶局里 ≥ 3 次 → +10。
  - 节拍/翻面过准：最近 50 拍全部 0 偏差，或每次都在最优那一 tick 翻面 → +10。
  - Perfect 率异常：★6 以上最近 50 局 Perfect > 80% → +10。
  - 有瓶局挑着打（v2）：种类不在种子里以后，读种子的外挂最多能挑「有瓶局」。最近 50 局里「有瓶局 Perfect 率 − 无瓶局 Perfect 率」> 40 个百分点 → +10；金瓶局里「Perfect 且抓到金瓶」的比例超出同星同级人类分布 3 倍 → +10。
  - L1–3 开着落点虚影的局不计入预判统计。
- 可疑分每天 −10。≥ 40：金瓶率 = 0、品质封顶超凡；≥ 80：封顶「高」并通知管理员。**不自动封号**，管理员靠回放存档人工复核。

### 18.8 节流
- 每个玩家同时 1 局；每个台子同时 1 局；结算后 ≥ 20 tick 才能开下一局。
- 令牌桶：容量 6，每 100 tick（5 秒）回 1 个（约 12 局/分钟，正常连做碰不到）。用完提示「手累了，歇一下」。快手一单耗 1 个，练习不耗。

### 18.9 闪耀管控（服务端按玩家存）
- **灵感冷却**：做出闪耀后 30 分钟内，开局金瓶率 = 0。
- **每日上限**：当天已做出 **3** 个闪耀（v2 建议默认，待拍板 C；v1 是 6），开局金瓶率 = 0；北京时间 08:00 翻日（与腐烂系统一致）。
  > 为什么改：熟练玩家满级不计冷却约每 13 分钟一个闪耀，加 30 分钟冷却约每 43 分钟一个，6 个约 4.3 小时就拿满——专心做菜的厨师每人每天都能拿满 6 个单命永久效果，闪耀的稀有度实际由日上限决定。可选更紧的口径：★6–★7 的闪耀单独每天 1 个。
- 批量局、可疑分 ≥ 40 也是金瓶率 = 0。
- 都在开局时体现为金瓶率，玩家根本看不到金瓶，不会被吊胃口。
- 闪耀全服播报（`broadcastRadiant`，默认开）。

### 18.10 留档与复核
- 每局保存 7 天：玩家、roundId、seed、参数哈希、RLE 输入、瓶种类（`ext.gold`）、结果、标记（约 1–3 KB/局）；闪耀局另存 SavedData 环形缓冲（最近 2000 条）长期保留。
- 管理员命令 `/chef replay <roundId>` 导出 JSON，可拖进网页原型逐 tick 回看。
- 按玩家统计 Perfect 率、金瓶抓取率、每日闪耀数，超出人类分布的进人工复核列表。

## 19. 整数运算约定与 golden 测试

### 19.1 约定（JS 原型与 Java 逐位一致的前提）
1. 内核是纯函数：`(状态, 输入字节) → 新状态`，外加开局初始化和结算两个纯函数。内核里不读世界、不读配置单例、不读时间、不用 `Math.random`；参数只来自参数块。
2. 所有状态与常量都是 32 位有符号整数；布尔存 0/1。禁止 float/double、`Math.round`、`Math.sqrt`，禁止依赖 HashMap 遍历顺序。
3. 除法：被除数、除数都 ≥ 0 时直接除（Java `a / b`，JS `(a / b) | 0`）；带符号的一律用 `tdiv`（§3.3）。不用 `>>` 当除法。`>>>` 只出现在随机数、哈希、`a8` 的位操作里。取模只对非负数做。
4. 乘法：所有积的绝对值 < 2^31（由 §20.13 跨键校验保证），JS 普通乘法即精确；RNG 与哈希里的回绕乘法必须用 `Math.imul`。
5. 执行顺序严格按 §5，同一 tick 内谁先谁后不许改。
6. 改任何规则都要升 `simVersion` 并重新生成 golden。

**最大中间值核对**：`(a3 − yt) × pct ≤ 800,000 × 99 = 79,200,000`；`H × offsetMaxPm ≤ 249,000 × 900`；`fill × MAST ≤ 34,000 × 1,400`；`g0 × flipEarlyZoneTicks ≤ 8,205 × 20`；`vb × 2 ≤ 约 200,000`；`GAIN × mul ≤ 4,689 × 1,300`；`(1,000,000 − P0) × k ≤ 750,000 × 3`；`CAP` 分子 400,000,000；`h × 600 ≤ 600,000`；`I × 1000 ≤ 约 1,200,000`。全部 < 2^31。

- 用例：≥ 50 个种子 × 5 种输入脚本（全松、全按、每 6 tick 开关、2 条真人录制）× 4 台 × 3 个星级（★1/★4/★7）× 2 个等级（L1/L10），外加边界用例（触底、触顶、顶死、急窜、爆油、翻早/焦面/自动翻、漏拍/乱按、到点、批量 6 份、手熟 5 级）。

## 22. 风险与待拍板

### 22.1 风险
1. **所有分布来自 bot，不是真人。** bot = 带反应延迟、感知噪声、最短按键间隔的 PD 控制器。它会高估烤炉（翻面从不分心）、低估备餐台的节奏感、不会「被吓一跳」。原型必须埋点（每局 ★、等级、台、性子、准度、扣分、Perfect、瓶、负面、时长、结局），拿到首批真人数据后按顺序调：①分数线与 LOSS；②瓶率、偏移、抓取速度；③性子修正；④各台 PACE 与扣分除数。分数线尽量不动，「几秒算高」对玩家是一句不变的话。
2. **20 Hz 会不会「粘手」。** 控制条每 50 ms 才走一步，必须插值渲染。原型实测；粘的话只能小调 accel / inBar 倍率，tick 率不能改（硬约束）。
3. **新手期偏苦。** v2 已做：L1–3 火候条保底 18%、时限缩到 15 秒（熬不出来也不拖）、画布倒数、落点虚影（L1–3，只画远处目的地）、练习模式、推荐等级提示。仿真：新手 bot 在 L1★1 约 66% 出低品质（v1 89%），仍有 56–65% 的局到点，但到点就在 15 秒结束。可选加码：首局教程不计品质（待拍板 H）。「L1–2 掉速减半」解决不了熬时限（框住率 60% 时仍要约 20 秒），不再推荐。
4. **种子必须下发，读种子的外挂能算出完美输入**（星露谷也有同类外挂）。v2 起瓶的种类不在种子里，外挂挑不出金瓶局，只能挑「有瓶局」（约 3 成到 4 成局）。兜底：闪耀硬封顶（冷却 + 日上限）、机械节奏封顶、跨局统计（含「有瓶局挑着打」，§18.7）、回放复核、材料与信用点成本。可选升级「分段下发子种子（每 2 秒一段）」能把外挂的预知压到 2 秒，代价是网络卡顿时客户端要停下来等，默认不做。剩余风险：带随机抖动的机器人能稳定刷超凡；超凡只有 30 分钟、消耗真实食材，危害有限。
5. **悬停宏遇上安静的食材。** 「每 tick 交替」宏在 L10★1「沉」性子原始约 37% 超凡（沉性食材停在 30% 线附近，条恰好悬停在那里）。节奏检测能封顶，加了随机抖动的悬停宏要靠「不跟食材」统计发现。若实测成问题，可把沉/浮停线改为每局随机。
6. **双手台的门槛。** 炸锅、烤炉、备餐台要一只手按住、另一只手按动作键，触控板、单手玩家吃亏。必须支持改键；可提供「双击空格 = 动作键」备选。v2 已把炸锅的漏压从「悬崖」改成「斜坡」并降了升温（§13.2）；仿真里「按动作键后分心 3 tick」最伤炸锅（熟练 L5★4 超凡+ 66 → 59，其它台 64–68），真人试玩先收炸锅和厨锅的对比数据。还太累的备选：`oilDrop` 280 → 350（压一下管更久）、拉长压火冷却，或改成「按住动作键持续降温」。
7. **20 Hz 的节拍精度。** 「正好」实际约 ±50–75 ms，比真正的音游粗；按键必须锁存，否则快速点按会丢；MC 声音有约 50 ms 延迟，需要校准偏移项。
8. **掉线算撂勺，偏狠。** 料变家常、信用点不退。备选：非主动掉线给 30 秒重连窗口续局（引入「拔网线暂停」作弊面，默认不做）。
9. **闪耀率是纸面值。** 高手满级约 1.7%/局，叠加冷却 30 分 + 日上限（建议 3）。v2 起金瓶放在保持 Perfect 也够得着的地方，低星不再全看运气。低星永久菜可能被 PvP 玩家囤（如 ★3 的生命类），日上限是主要闸门。
10. **批量最高「高」可能被嫌不够爽**；放到超凡则超凡变便宜（一局 6 份）。
11. **快手**让 3 分钟的低品质菜可以挂机量产，可能压低低品质菜市价。
12. **负面必定生效**让中品质菜明显变差。v2 门槛提到 中 120 / 高 150 后，中品质约 30–55% 带负面（v1 86–91%），高品质只在明确事故时带。
13. **FD 厨锅接入成本高**：要 mixin 它的方块实体和界面，暂停它的自动进度，兼容风险比三个新台子高。
14. **手熟数据**：每人最多 204 道 × (计数 + 个人最佳)，要存档、要同步给客户端；菜表增删要有迁移方案。
15. **旧菜兼容**：旧调味台盖过章的菜带「多个效果 + 旧品质」NBT，需要决定保留旧效果还是按新表重新解释。
16. **与腐烂系统衔接**：锅内暂存的料、出品槽里的成品算不算腐烂，要和腐烂方案对齐（腐烂稿写了「厨师品质菜不进仓」）。
17. **JS 与 Java 算岔**：任何一处用了浮点、用 `>>` 当除法、对负数取模、调换了 tick 内顺序、少抽或多抽一个随机数，两边都会算岔，而且很难查。golden 必须进 CI，代码评审清单专列一条。

### 24.4 驳回与暂缓汇总
- **手感 8（内核上报按住比例）暂缓**：先看预测渲染之后真人还觉不觉得粘手。
- **手感 1③「开局火候 300 → 500」未采用**：审查给的二选一，选了「厨锅时限不跟 PACE」。

- **数值 2 的两个可选项没改**：门槛改完已达标，少动旋钮。
- **数值 6 没按 98% / 24，用了 100% / 32**：98% 对极端稳的连点仍误判 15.7%，100% 宏照样抓得到。
- **数值 7 的备用 `oilDrop` 350 没启用**：会让普通玩家掉进冷油，改用不伤人的 `oilRiseIn` 4；`oilDrop` 350 留作待拍板 N。
- **数值 7「菜表补三列」没直接改菜表**：`dish-stars.tsv` 是已拍板的表，改成出提案文件 `sim/dish-play.tsv`（待拍板 Q）。分台表按「每台每星真实用到的组合」逐格跑、写明每个组合的菜数，没有再做按菜数加权的合并表（检查已覆盖审查担心的问题）。
- **数值 9（批量）不改**：审查结论就是不需要。
