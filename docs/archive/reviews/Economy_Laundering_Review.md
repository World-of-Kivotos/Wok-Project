# 经济体系"跨账号洗额度/养蛊"社区反馈 - 设计评审意见书

状态: 评审完成, 待主策划拍板修复范围。mod 尚未上线。
评审方法: 多 agent 并行(5 路真码取证 + 5 路联网研究[MMO 虚拟经济/反 RMT/反洗钱 AML/机制设计/国内策划防搬砖] + 4 视角深度分析[漏洞分类/修复架构/红队量化/宏观长线] + 9 条对抗验证)。本文结论一律以真码行号为准, 区分"已确认机制"与"被夸大量级"。
反馈来源: 社区玩家(非开发者), 原始语境为"养蛊/养尸/DNF 小号养大号/献祭流/后勤部内循环"。

---

## 一、一句话结论

玩家的直觉抓对了一个**真实存在的结构性问题类别**(逐账号节流 + 物品可自由转移 + 变现口不卡职业 = 教科书级的 structuring/false-name 失配), 这点值得表扬。但经真码量化与对抗验证, **"垄断印钞机"这个量级是被显著高估的**: 真正能凭"接收他人产出"在自己账号上**铸出新钱**的通道只有一条 —— 卖菜, 而它每账号每天硬顶 ~2160 信用点(零钱级)。真正值钱的产出(矿)在"挖掘那一刻"就结算给破坏者, 递给别人也变现不了。所以这不是印钞机, 是"印零钱机"。

需要做的不是上重型结构改造, 而是: **3-4 个低成本原子补丁(上线前)** + **几条长线市场/通胀护栏(可迭代)** + **把高杠杆购买力锚到不可转移货币 AZURE**(让"钱堆给一个人"这件事本身变得无所谓)。重型方案(产出绑定 NBT / 公会级合并额度 / 全服供给定价)在 80 人合作向小服属杀鸡用牛刀, 且会直接误伤合作体验, 暂缓。

---

## 二、根因(一句话 + 形式化)

> 货币注入的节流(第十一章衰减主闸 faucet)把限额挂在"收款账号 UUID"上, 但被限额的产出物在 MC 里物理可自由转移(箱子/丢地/跳蚤市场, 引擎级禁不掉), 且卖出口不卡职业 —— 于是"计量边界(单账号)"与"价值实现边界(整团体)"分离。

形式化: faucet 计数键 = `(playerId, "credit_faucet")`(`EconomyWalletData.recordFaucetGrant` L174), 是自我申报身份; 物品转移成本 c≈0 -> 不满足 false-name-proof(机制设计的 Sybil 抗性)。等价于反洗钱里的 structuring(把一笔超限流拆成多笔各自不超账号额度) + smurfing(多账号当 mule)。

关键: 这**不是曲线参数问题**。把衰减底数从 0.6 调到 0.5、把档从 60000 调到 30000, 都改变不了"群体上限 = 全员 faucet 之和"这个等式。要修就得把节流锚从"账号钱包计数器"下沉到别的维度(产出物可交易性 / 产出者身份 / 全服供给), 或者让"钱堆给一人"无所谓(AZURE 锚定)。

## 三、已确认的机制 vs 被夸大的量级(本评审最重要的一节)

社区把"养蛊"描述成"过剩产出塞进队友闲置额度, 凭空生出一大笔钱"。对抗验证逐条核实后, 结论分两半:

### 结构机制: 确认成立
- faucet 严格按账号计量, 跨账号零关联(`EconomyService.grantDaily` 用 `player.getUUID()` 分区, L134/139)。N 个白名单账号 = N 份独立日额度。
- `/farmer sell <amount>` 无任何 `.requires` 职业门(`FarmerSystem.java:69-76`); `FarmerWheatSellService.sell` 对任意持 mod 小麦者发币、零职业校验。
- mod 小麦的种子 `farmer_seed` 可由 1 个原版 `wheat_seeds` 无门槛合成, LOW 耕地 1 级即可放 -> 从未入职的小号也能自产自卖。
- 跳蚤市场卖家进账走裸 `economy.grant`(`MarketEngine.java:189/255`), **绕过衰减主闸** -> 已铸 CREDIT 在账号间转移只受 5% 手续费约束。
- 物品层零绑定(全库无 soulbound/bind-on-pickup/no-trade NBT), 私下手递无摩擦无审计。

### 量级: 被显著高估(9 条对抗验证的一致修正)
1. **唯一能"凭接收的物品在自己账号铸新钱"的口子只有卖菜, 且硬顶 2160/天。** `WHEAT_BASE_PRICE=1`, 收购价 `= floor(1 * max(0.25, 0.97^over))`; 超过 2160 株软上限后第一株即 `floor(0.97)=0`。即单账号卖菜一天最多铸 **2160 信用点**(硬顶, 非软顶), 经 5% 市场费回流后净 ~2052/mule/天。
2. **对比基准: 一个 solo 矿工自己的 faucet 几何主项 ~149,093 信用点/天。** 一个 wheat-mule 一整天的贡献 ≈ 矿工 14 分钟产出。要靠卖菜洗到等于 1 个矿工, 需要 ~73 个全程配合的真人, 每人每天种满 2160 株(L1 非农夫满负荷仅 ~108-432 株/时, 即近 20 小时纯操作)。这是负 EV。
3. **真正值钱的产出(矿)物理上不可 washing。** `settleOreSale` 只从 `onBlockBreak` 触发(谁破谁得), 仓库里的钻石/金锭**没有任何 NPC 出售命令**。mule 拿到递过来的钻石变现不了, 只能走市场 P2P(那是转移已铸的钱, 不铸新钱)。
4. **跳蚤市场是零和转移, 不是铸币。** 买家先被扣 CREDIT, 卖家收 proceeds, 5% 蒸发为 sink。它能**汇集**财富, 不能**印**财富 —— 每个参与者的 CREDIT 仍是被各自 faucet 限过的。
5. 所谓"80 人全动员铸 ~1190 万/天汇集到一人", 拆穿了其实是"80 个人各自老实挖到自己的 149k 再自愿送给会长"。faucet 对每个人都生效了; 这不是漏洞印钞, 是 80 个人在打工 + 自愿赠与。
6. "对敲伪造行情"被**驳回**: 代码里根本没有"行情/指导价"预言机(市场是纯手动挂单板, 无成交价聚合), 没有可被污染的锚。真实风险是 faucet 汇集, 不是行情伪造。

诚实结论: 社区担心的"凭空生钱印钞机"在当前数值下不成立; 但"财富可几乎零摩擦地汇集/集中到一人"(再分配, 非铸币)是真的, 而它的危害大小**取决于"堆起来的 CREDIT 能买到多大的结构性优势"** —— 这就把球踢到了下面 AZURE 锚定那条。

## 五、修复建议(分三档, 按性价比与必要性)

### Tier 0 - 低成本原子补丁, 建议上线前做(零回归面, 不伤合作)

- **T0-1 给 `/farmer sell` 加职业门。** 与"卖矿绑定挖掘动作"口径一致, 堵住"随便拉个闲号当卖菜容器"。改 1-3 行(命令注册 `.requires` 或服务层 `JobServices.level(player, FARMER) >= N` 前置)。
  - 注意: `IJobService` 当前**只有 level 概念, 无"是不是农夫"的成员(membership)概念**(默认每人全 7 职业 L1)。所以只能做"等级门"(level>=阈值), 阈值要 >1 才有过滤意义, 且会误伤真在练的低级农夫 -> 阈值取低或给宽限。它**收窄但不根除**(真练了农夫的队友仍是 real-identity Sybil)。
- **T0-2 把卖菜 2160 硬顶钉成契约。** 现在"卖菜只值 2160/天"这条**承重的安全线是意外的**(靠 base=1 下取整到 0)。加一条 GameTest 断言"第 2161 株收购价==0、gross 在软上限处封顶", 并在 `WHEAT_BASE_PRICE` 注释写明"一旦调高于 1, 此硬顶失效, 需重评 washing 上限"。防有人将来把 base 调到 5 时无声放大 5 倍。纯测试+文档, 零运行期改动。
- **T0-3 刷怪/无限输入物 NPC 收购红线 + 回归测试。** 当前刷怪掉物零 NPC 铸币口(正确), 但这是"恰好没接", 脆弱。补一条契约 GameTest 断言"mob 死亡/掉落不产生任何 grantDaily 入账", 并文档化设计禁令: 任何可被刷怪塔/自动农场无限产出的物品, **严禁挂带正地板的 NPC 收购价**(走 AZURE 或无地板趋零)。防一次回归就开洞(V7)。近零成本。
- **T0-4 接通 `market.history`。** 现在返回空数组桩(`MarketActions.java:168-175`, DAO 缺 `transactionsByPlayer`), 是已知 TODO。`transactions` 表其实每笔都写了。补这个查询: 既给玩家侧审计, 又为下面的净流入巡查打底。

### Tier 1 - 值得做, 可迭代/上线后(治本与长线健康)

- **T1-1(最深的杠杆)把高杠杆购买力锚到 AZURE。** AZURE 不可转移已证(`Currency.AZURE.isTransferable()=false`), 塔罗毕业用 AZURE 计价已经是对的。审计所有 CREDIT 可买的**高杠杆物**(战力/产能/进度/稀有配方/维度门票), 尽量改 AZURE 计价或账号绑定亲手赚。**这一步一旦做到位, "钱堆给一个人"就失去意义** —— 洗来的 CREDIT 买不到结构性优势, 危害从"垄断印钞买碾压"降级为"多点闲钱"。这是让前述整个 washing 问题低风险化的总开关, 优先级最高。
- **T1-2 补一个常态/累进 CREDIT sink(反 mudflation)。** 现在所有 sink 都是一次性(卡包/工费/调味/5% 手续费), 无"必须持续花掉"的黑洞 -> 净流入长期为正, 数月后货币贬值、新人被价格墙隔离。补养成耐久维修/功能续费, 或市场税随近期净流入累进(固定额 sink 暴富后失效, 只有百分比/累进全周期有效)。
- **T1-3 薄市反操纵护栏。** 80 人薄市易被少量资本控盘(清低价货囤积再抬价/低价倾销打垮散户/双账号对敲)。加: 基础品价格带(指导价 ±窗口)、单账号在架挂单条数上限 + 挂单 24-72h 过期、关键品类买方侧 cap(现仅卖方铜铁 512)。注意所有按账号的 cap 都需配合"按净流入/协作组"推理, 否则换号即绕。
- **T1-4 净流入人工巡查(检测兜底, 非自动封禁)。** market.history 接通后, 加管理员周报: 列"只收不付的中心节点"(hub-and-spoke 汇集签名)。80 人熟人服样本小、社交透明, 这种模式肉眼可见。对"自愿赠与 vs 养蛊"靠社交语境区分。这是 BitCraft"审计而非监管"的最小落地。

### Tier 2 - 对本服属过度设计, 暂缓(除非上线后监控发现真滥用)

红队视角 + 量级修正一致认为, 下列重型结构改造**为了堵一个 2k/天负 EV 的洞而引入会激怒社区的副作用**, 不建议现在上:

- **产出端绑定 producerUuid(Bind-on-Produce NBT)。** 理论上是转移免疫的标准答案(WoW BoP), 但: (a) NBT 不堆叠 -> 不同产出者的同种物不能 stack, 背包/箱子占格暴涨; (b) 跨 farmer+market+economy 三处结构改动; (c) **直接焊死合作体验** —— 玩家不能把自己种的菜送新人、不能摆摊、不能搞公会后勤分工。在"FF14 生产职业 + 合作向"的服务器砍掉合作。**仅当未来真的给"仓库物品"开了 NPC 铸币口时才需要它。**
- **公会级合并额度(aggregate faucet)。** 直接惩罚组队/公会协作, 与本服合作哲学对冲。否决。
- **全服共享供给定价(global bonding-curve)。** 有公地悲剧副作用: 大户洗货压低全服买价会连带砸诚实单人卖家。重且对独狼不公。暂缓。

## 六、需要主策划拍板的价值取舍

1. **风险定级与上线门槛。** 本评审建议: Tier 0 四条(都很便宜)上线前做; 重型结构方案**不**作为上线阻断项。这是基于"铸新钱只有 2k/天卖菜"的量级判断。若主策划风险偏好更保守(宁可牺牲合作体验换零洗白), 则需重新评估是否提前上 Bind-on-Produce —— 但请注意它对合作向小服的体验代价。
2. **AZURE 锚定的力度(最关键的设计决策)。** 要把多少"高杠杆购买力"从 CREDIT 挪到 AZURE? 挪得越多, "财富集中"越无害, 但 CREDIT 经济的可玩性(用钱买好东西的爽感)越弱。这是经济手感的核心权衡, 需要主策划定调哪些东西"必须亲手赚不可交易", 哪些留给 CREDIT 自由流通。
3. **要不要常态 CREDIT sink(耐久/续费)。** 反通胀有效但会增加养成负担/磨损感, 与某些"轻松产出"的设计取向冲突。需主策划定。

## 七、被瞄错的更大杠杆: "多开"是身份层问题, 不是经济层

红队视角的一个重要提醒: 如果一个人真有 N 个白名单账号, 让每个 alt **直接挖矿**才是收益最大化 —— 每个 alt 自带完整 149k/天 faucet, 是 wheat-mule 的 73 倍。这说明:

- faucet 按 UUID 计量对"多账号"本就无能为力, 这是**身份层(白名单准入审核 / IP-HWID / alt 检测)**的职责, 不是 faucet/市场层能解决的。
- 社区把矛头指向"洗额度", 其实指错了层。真要防多账号通胀, 该补的是**白名单审核严格度**, 而不是给经济系统加结构性枷锁。
- 为 wheat-washing 上重型修复, 是"在错误的层解决一个小问题, 同时放着真正的大问题(多开挖矿)不管"。

建议向上反馈时把这点讲清楚: **"一个人靠多个号变富"的担忧, 真正的闸门在准入审核, 不在经济机制。**
