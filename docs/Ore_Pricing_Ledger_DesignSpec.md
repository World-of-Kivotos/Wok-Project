## 一、当前已定价（DECIDED，代码现状）

只有 3 个"系统龙头矿"有价 + 每日软上限。衰减口径：`price(n) = base × max(0.25, 0.97^max(0, n-cap))`。

| 矿 | base（信用点/个） | 每日软上限 cap | 满 cap 日上限 = base×cap | 来源 |
|---|--:|--:|--:|---|
| 下界残骸 | 4,500 | 8 | 36,000 | ShopPriceTable + EconomyConstants |
| 钻石 | 500 | 64 | 32,000 | 同上 |
| 金 | 120 | 256 | 30,720 | 同上 |

衰减：超过 cap 后每多 1 个 ×0.97，跌到 base 的 25% 地板。例：钻石第 65 个 = 485，深 over 夹到 125。

**已编码的核心结论**：金（中级，30,720）已经"极限勉强跟上"钻石（高级，32,000）——你的设计直觉在代码里成立。

## 二、缺口（本次要补）

`HighValueOre` 枚举只有 DIAMOND/GOLD/NETHERITE_SCRAP。**铜、铁、煤、红石、青金、绿宝石全部无价、无 cap**
（`ShopPriceTable` 注释把它们划为"低价矿，属各自子系统物价职责，不落货币层"，但那个子系统还不存在）。

这正是"铜+时运能否比得过高级"的唯一口子：**没有 cap 的矿，收入不被任何东西封顶**。

## 三、两类矿（定价哲学）

| 类 | 矿 | 主销路 | 定价机制 | 收入封顶来源 |
|---|---|---|---|---|
| **系统龙头矿** | 钻石/金/残骸/绿宝石 | 卖系统（settleOreSale） | base × 软上限衰减 | 每日软上限（**当前是软膝盖非硬顶，见下注**） |
| **材料矿** | 铜/铁（**煤本轮排除**） | P2P 卖给职业 | 市场浮动 + 系统低保底 | 下游需求 + 低 cap 的保底 |

- **铜** 的真实价值是 P2P 卖给军火商（造发射药，经济文档锚 ~28 占位，`服务器经济系统设计文档.md:372`）；系统只给一个**低保底价**，防止"没军火商在线时铜一文不值"，但保底 < P2P，逼玩家走供应链。
- **铁** 同理（卖工程师造护甲板）。
- 铜/铁的系统保底**必须带 cap**，否则连锁+隧道+时运的高吞吐能把"卖系统铜"刷穿。
- **煤本轮排除**：军火商配方不吃煤（`Munitions_Job_DesignSpec.md:48`），下游买家悬空，不进系统收购（见 5.2 / 8.6）。
- **「硬封顶」更正**：代码衰减有 0.25 地板（`AbuseGuard.java:233-239`），过 cap 后停在地板线性继续涨，故 base×cap 当前是「软膝盖」非硬顶。要成真硬顶须裁定（第十章 Critical-2 / 第九章 Critical-2）。

## 四、核心铁律：软上限 = 收入上限（反通胀北极星）

`Miner_Job_DesignSpec` 第六章 + 方案 B：

1. **时运/连锁/隧道只让你"更快/更省块撞上限"，绝不抬上限**。时运额外掉落**计入**当日产出物计数（方案 B），所以撞限更快≠收入更多。注：实现上时运只作用连锁/隧道路径（铜/铁/煤），高价矿手挖单块不吃矿脉时运（第八章 8.5）。
2. **高价矿物理排除连锁/隧道**（`CHAIN_HARD_EXCLUDE` `MinerConstants.java:170-175`）：钻石/金/残骸/绿宝石只能手挖单块。铜/铁/煤才进白名单（`:159-164`，但 Hard 无 copper/coal feature，第八章 8.1）。
3. 所以**理想上一个矿的收入天花板 = base × 每日软上限**，与吞吐无关——但这条**仅在 base×cap 是硬顶时成立**。当前代码 0.25 地板使其成软膝盖（第七章 1 / 第九章 Critical-2），须先裁定地板/硬顶口径，铁律才真生效。要让"铜+时运 < 高级"，需 `铜_base × 铜_cap < 钻石/残骸天花板` **且** 地板尾巴被掐断。

## 七、结论：铜+时运能不能比得过高级？（按真源衰减曲线复核）

简短版：**单看"卖系统"路径，不能**（base×cap 的乘积，铜 6,000 ≪ 钻 32,000）；
**但当前代码有两个口子让这个结论在实践中不成立**，必须先堵（见第九章 Critical）。

1. **"卖系统铜有 cap 兜住"的前提是衰减地板足够低——而代码地板是 0.25，不是 0**。`AbuseGuard.buyPrice`（`AbuseGuard.java:233-239`）是 `price(n)=base×max(0.25, 0.97^(n-cap))`。过 cap 约 46 块后衰减到 25% 地板就**永远停在地板、不再继续衰减**。于是 base×cap 是「软膝盖」不是「硬天花板」：撞 cap 后吞吐越高、地板尾巴越长，收入线性继续涨。
   - 钻石地板 = 500×0.25 = **125 CP/个**；金 = 30；残骸 = 1,125；铜（若 base 15）= 3.75。
   - 红队实算：钻石 8h 现实约 1,280 个 → 总收入约 **19 万 CP**，是「ceiling 32,000」的约 6 倍，单矿即反超军火商 17.5 万。所以「矿工理论 < 军火商」的跨职业序在地板尾巴下崩。
   - **要让 base×cap 真成硬顶**，二选一（第十章 Critical-2）：(a) 地板砍到 0 或 ~0.02（过 cap 趋近免费）；或 (b) 每矿加一道「当日绝对块数硬顶」，撞顶后 `settleOreSale` 返 0。在此之前，所有「ceiling」只是下界不是上界。

2. **铜 P2P 卖军火商无任何每人每日 cap，是比"卖系统铜"更大的口子**。一名矿工独供一个 L10 军火商全部 2,400 铜/日（`Munitions_Job_DesignSpec.md:99` 反推），按 P2P 锚 28（`服务器经济系统设计文档.md:372`）= **67,200 CP/日 = 钻石单矿 32,000 的 2.1 倍**。军火商弹药需求只封「总量/价格」不封「单人吞吐」，市场自限挡不住单点垄断。须配一道「按矿工本人计的每日铜产出/出售软上限」（不分卖系统还是卖军火商，复用 0.97/0.25，cap≈850–900 铜/人/日使 base×P2P 落在 ~3 万同档）。这与 5.2 的系统保底 cap 400 是两套口径（第十章 Major-A）。
   - 注：经济文档只锚到铜 P2P=28（占位，`:372`），原 DRAFT 写的「28–45」中的 45 在三份文档里查无来源，本轮按 28 算，不引用 45。

3. **中级金（30,720）≈ 高级钻石（32,000）的「极限勉强跟上」在代码里成立**（第一章），本轮不动——但这只在「单矿独立封顶」口径下成立；若维持 `settleOreSale` 现状（高价矿可叠加），Medium 玩家金叠绿宝石可在叠加层反超 Hard 单钻（第九章 Critical-1 / 第十章 Critical-1）。

## 八、调研接地（worldgen 配矿实况 / 跨职业锚 / 吞吐撞限 / 材料矿 P2P 需求）

### 8.1 worldgen 配矿实况（真源 = vanilla noise + biome JSON feature 列）

真源维度走 vanilla `minecraft:noise` 生成器（`dimension/mining.json`），三个 biome JSON 的 feature 列直接决定哪些矿挖得到。逐 JSON 核对：

| biome | 真源 ore feature（`features[6]` 段） | 含高价矿？ |
|---|---|---|
| `mining_easy.json:37-42` | coal_upper/lower, iron_upper/middle/small, copper | 无 |
| `mining_medium.json:37-43` | coal_lower, iron_middle/small, copper_large, **gold**, redstone, lapis | 仅金 |
| `mining_hard.json:37-43` | iron_middle, **gold/gold_lower**, redstone_lower, lapis_buried, **diamond/diamond_large/diamond_buried** | 金 + 钻 |

**关键事实（影响定价）**：
- **三 biome 全无绿宝石 feature、全无残骸 feature**。绿宝石/残骸在真源 worldgen 产出为 0，给它们定价（绿宝石 18,000 / 残骸 36,000）当前**空转**。
- **Hard 无 copper、无 coal feature**（只 iron/gold/redstone/lapis/diamond）。第六章 Hard 合计已据此剔除铜。
- 另一套 `ore/OreType.java`（绿宝石 cap 12/36/96、残骸 cap 0/6/20 等难度梯度，`OreType.java:52-65`）+ `OreSystem.placementFor`（`OreSystem.java:62`）是**死代码**：全库 grep 证 `GenerationScheduler`/`worldgen` 包**零调用** `placementFor`/`OreType`/`OreSystem`，生成管线只产体素不铺自定义矿。故 `OreType` 的 maxCount 不能当任何产出/定价锚。
- 连带影响：矿工探矿技能 `OreScanService.scan`（`OreScanService.java:68`）查 `OreSystem.cachedPlacement`，而该缓存只在 `placementFor` 被调用时填充——既然无生产调用方，探矿技能当前事实失效（不影响定价数值，影响矿工 L6/L8 探矿里程碑体验，见第十章 H）。

**定价前置**：给绿宝石/残骸定价、给探矿技能数值，前提是先接线 worldgen——要么切回自定义生成器调 `OreSystem.placementFor`，要么补自定义 emerald/debris `PlacedFeature`。否则数值是纸面。

### 8.2 结算通道实况（settleOreSale 现状）

- `settleOreSale`（`EconomyService.java:80-89`）直接 `ledger.credit` 入账，**不经** `grantDaily`（`:99-118`）的统一 credit_faucet 软上限 + `faucetCreditAfterDecay` 衰减。
- 全库 grep 证 `settleOreSale` **无生产调用方**：只有 `EconomyGameTests`（单测）与 `MinerGameTests:575`（mock 覆盖）引用；`EconomySystem.onBlockBreak`（`:166`）只 `recordMinedOre` 计数、**不发钱**。即当前生产路径下卖矿一分钱都没真正入账，结算时机（on-break 自动 vs 商店卖矿）尚未定（第十章 G）。
- 对比：农夫卖菜 `FarmerWheatSellService` 走 `grantDaily`（key=`credit_faucet`，`FarmerConstants.java:77`），**已并入**统一 faucet。两条路径口径分叉是红队 Critical-1 的根。

### 8.3 跨职业锚（经济文档 8.4，`服务器经济系统设计文档.md:354-362`）

| 职业 | 定位 | 满级日产/收益锚 |
|---|---|---|
| 矿工 | 产出（封顶） | ~11–19 万 CP（撞每日软上限） |
| 农夫 | 产出 | ~3 万株小麦/日（单价 config，未定标，见 8.4） |
| 军火商 | 产出（半被动） | ~17.5 万 CP/日（满产满销；现实 ~13–16 万，`Munitions:102`） |
| 普通全职业玩家(5h) | — | ~16 万 CP/日 |
| 千年工程师 | sink | 满修 ~3.6 万 CP（花钱，非收入） |

矿工锚定位（FF14 生产职序「主动单产职 < 半被动满产 < 全职业玩家」）：
- **理论天花板**：Hard 真源可达三矿（铁+金+钻）独立封顶合计 73,220（第六章），低于经济文档矿工锚上沿 19 万——但注意经济文档 19 万本身可能含残骸/绿宝石（worldgen 当前拿不到）与地板尾巴（第七章 1），口径待对齐。
- **现实大头**：撞穿钻/金两高价矿即落点（残骸 worldgen 拿不到），约 5.5–7 万（第六章 Hard realisticDaily），显著低于军火商半被动 17.5 万与普通玩家 16 万，守住「主动单产职不反超半被动」。

### 8.4 农夫横向序（共用 credit_faucet，必须连带定标）

- `WHEAT_BASE_PRICE=1`（`FarmerConstants.java:60`，自承 PENDING）+ `DAILY_CREDIT_FAUCET_CAP=2160`（`:85`，自承 PENDING「接通后须与矿工传同一值」）均为占位。
- 农夫满级 ~3 万株（经济文档 8.4）在单价定标前无法换算 CP。矿工卖矿与农夫卖菜**共用** `credit_faucet` 键（`FarmerConstants.java:77`），二者不能单调一个：若 settleOreSale 并入统一 faucet（Critical-1），统一 cap 必须连带为「矿工主力 + 农夫」联合标定（农夫占位 2,160 远小于钻石单笔 32,000，直接沿用会把矿工腰斩、农夫被挤爆）。
- 红队警告：若小麦单价拍到 ×10 锚的 10 CP/株，3 万株 = 30 万 CP，反超所有人——是更隐蔽的印钞口。建议据满级 3 万株反算使农夫满级日 CP 落矿工现实同档或略低（更被动安全），量级约 2–3 CP/株（待统一 cap 定后联合标定）。

### 8.5 吞吐撞限时间与方案 B 时运口径

- 高价矿全在 `CHAIN_HARD_EXCLUDE`（`MinerConstants.java:170-175`，含钻/金/残骸 + 绿宝石），物理排除连锁/隧道，只能手挖单块。
- 矿脉时运（`MinerConstants.java:55-58`，+8% L4 → +50% L10）javadoc 称「对一切矿生效」，但实现上时运只作用连锁/隧道路径——高价矿手挖单块走 vanilla 直接物化，**当前拿不到矿脉时运额外掉落**。故时运只对连锁白名单的铜/铁/煤（`CHAIN_WHITELIST` `:159-164`）生效。定价依据不引用「时运对钻石生效」。
- 含义：高价矿撞 cap 速度不被时运加速，靠手挖 + 找矿 + 走位，现实日产由在线时长 + danger 压力主导，不是吞吐——这正是反通胀北极星想要的（吞吐过剩、收入由 cap 锁死）。前提同样是 base×cap 真成硬顶（第七章 1）。

### 8.6 材料矿 P2P 需求（军火商配方真值）

- 军火商步枪弹配方（`Munitions_Job_DesignSpec.md:48-49`）：直造 7 铜 + 16 火药 → 40 发；L6 提炼 7 铜 + 16 火药 → 70 发。L10 ~24,000 发/日（`:99`）。
- 铜日需 ≈ 24,000 ÷ 70 × 7 ≈ **2,400 铜/日**（单个 L10 军火商）。这是 5.2 铜 cap 400（6 名矿工人均分摊）与 P2P 单点垄断风险（第七章 2）的数据来源。
- 煤：军火商配方**只吃铜+火药不吃煤**，工费是扣信用点销毁（`:51`），煤的下游真实买家在三份文档无量化锚——故 5.2 煤本轮不进系统收购。

## 十一、决策定稿（用户拍板 2026-06-18）

本节裁定第十章 Critical-1/2/3 与 Major-A，覆盖其「待定」表述。

### ② 统一收入主闸 = 衰减曲线（取代硬上限；红队 Critical-1 DECIDED）

`settleOreSale` 卖矿与农夫卖菜并入**同一条** `grantDaily` credit_faucet 衰减曲线（高价矿不再独立封顶、不再可叠加印钞）。该曲线**不是硬上限，是无地板（见①）的收敛衰减**：

- 首档到手 **6 万**，衰减率 **0.6**（每等量努力档到手 = 上一档 ×0.6），渐近线 = 6 ÷ (1−0.6) = **15 万**。
- 画像落点：休闲(1 档) ~6 万 / 正常(~2.2 档) ~10 万 / 肝帝(~6 档) ~14 万 / 极限渐近 **15 万**。

| 等量努力档 | 该档到手 | 累计到手 |
|---|--:|--:|
| 1 | 6.00 万 | 6.00 万（休闲） |
| 2 | 3.60 万 | 9.60 万 |
| ~2.2 | — | 10.0 万（正常） |
| 3 | 2.16 万 | 11.76 万 |
| 4 | 1.30 万 | 13.06 万 |
| 5 | 0.78 万 | 13.84 万 |
| ~6 | — | 14.0 万（肝帝） |
| →∞ | →0 | 15 万（渐近，够不到） |

「等量努力档」= 等量毛收入（按基础价值算）；系统按当日累计毛收入施衰减发净到手。
含义：**15 万 = 一个玩家一天「系统印钞」的实际天花板**；P2P 跳蚤收入不在内（第三/四章），靠手续费 sink + 需求自限管。

### ① 衰减地板 = 1%（红队 Critical-2 DECIDED）

`AbuseGuard.buyPrice` 与 `faucetCreditAfterDecay` 的地板从 **0.25 砍到 0.01**：过最大衰减后单价 = 基础价 ×1%（钻石 500→5 或 600→6，见待确认）。1% 尾巴细到无人肝（毛 6 万只换 600 CP），故 15 万是「滑下去够不到」的软墙而非硬墙。**主闸与逐矿两层地板都用 1%。**

### ③ 铜 P2P 单人产出 cap（红队 Major-A DECIDED）

按矿工本人计的每日铜产出/出售软上限 **≈ 850–900 铜/人/日**（不分卖系统还是卖军火商，复用 0.97/0.01 衰减），并入跳蚤手续费 + 流水审计防对敲。封「源头」（铜是挖出来的），不封 P2P 流通。

### 架构后果（简化）

- 逐矿 `buyPrice` / per-ore cap **降级**为「只决定优先挖哪种矿（相对吸引力）+ 首档肥度」，不再背控通胀（主闸已锁总量）。
- 第十章 **Critical-3「×1.75 旋钮」作废**：总收入由衰减曲线定，不再靠 cap×1.75；高价矿 base/cap 沦为相对权重。

### 仍待确认（Minor）

- 钻石基础价 **500 vs 600**：有了主闸后只影响相对吸引力 + 首档肥度，不影响 15 万总顶。待用户一句。
- 第十章 Major-C（Easy 偏穷）/ D（worldgen 接线）/ Minor E–H 不受本裁定影响，仍按原表。
