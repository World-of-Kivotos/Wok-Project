# 铸甲师护甲机制设计规格

## 文档元信息

- 用途：记录“千年工程师”玩家可见名称调整为“铸甲师”后的护甲系统长期设计，并作为插板护甲第一阶段的实现依据。
- 目标平台：Minecraft 1.20.1、Forge 47.x、Java 17、TaCZ 1.1.8。
- 关联文档：[千年工程师职业设计](MillenniumEngineer_Mod_DesignSpec.md)、[冠军星级词条系统设计](ChampionStarAffix_System_DesignSpec.md)、[枪匠组件平衡路线](Gunsmith_Component_Balance_Roadmap.md)。
- 实现状态：“完整钻石套顶多属于 III 级中甲”的增强目标已经确认；弹道与非 TaCZ 护甲敏感伤害的推荐矩阵仍待用户确认，护甲代码尚未开始实现。
- 状态图例：`DECIDED` 已由用户确认；`VERIFIED` 已由当前代码、依赖或既有文档核对；`PROPOSED` 当前推荐方案；`PENDING` 实现前仍需拍板；`DEFERRED` 后续阶段再实现。

### 文档权威边界

1. 本文档负责铸甲师的护甲类型、受击公式、枪匠联动和护甲实现阶段划分。
2. `MillenniumEngineer_Mod_DesignSpec.md` 继续负责既有纳米修复、生产台、职业等级和一次性维修特效。
3. 两份文档发生护甲机制冲突时，以本文档为准；发生既有生产与修复经济冲突时，以千年工程师职业设计为准，直至另行完成整合评审。
4. “铸甲师”目前只调整玩家可见名称。第一阶段保留 `JobId.ENGINEER`、`engineer` 存档键、已有注册 ID 和配置文件名，避免旧玩家职业数据失效。

## 一、职业与护甲系统定位

### 1.1 职业名称（DECIDED）

- 玩家可见职业名：铸甲师。
- 既有纳米修复和生产能力继续属于该职业，不因改名删除。
- 新增的护甲设计、制造、维护和状态管理成为铸甲师最重要的子系统。

### 1.2 护甲设计目标

用户确认的目标（DECIDED）：

1. 不把所有护甲做成数值不同的百分比减伤。
2. 每个护甲家族必须使用不同的防护资源，并存在能够被玩家理解的武器反制方式。
3. 护甲体系与已完成枪匠系统共同校准，而不是各自独立平衡。

技术事实与实现目标：

1. `VERIFIED`：TaCZ 将一次弹丸的伤害拆分为普通弹道段和穿甲段。
2. `DECIDED`：插板只处理 TaCZ 拆分完成后的普通弹道段，不直接读取枪匠 NBT，也不重复计算枪匠系数。
3. `VERIFIED`：服务器玩家基准生命为 80 HP，并处于高 DPS 枪械环境，不能套用原版 20 HP 经验。
4. `DECIDED`：客户端显示、物品提示和服务端实际结算使用同一组配置值。

### 1.3 已确认的护甲家族

| 护甲家族 | 核心资源 | 主要反制轴 | 方向状态 |
|---|---|---|---|
| 轻型插板护甲 | 较低连续防护，换取机动收益 | 穿甲率（DECIDED） | 第一阶段，DECIDED |
| 中型插板护甲 | 中等连续防护，无机动修正 | 穿甲率（DECIDED） | 第一阶段，DECIDED |
| 重型插板护甲 | 较高连续防护，承担机动惩罚 | 穿甲率（DECIDED） | 第一阶段，DECIDED |
| 电浆护盾 | 可恢复的能量容量池 | 最终单发伤害、爆头和持续输出（PROPOSED） | 方向 DECIDED，实现 DEFERRED |
| 纳米陶瓷板护甲 | 有限次完整拦截 | 射击次数与高射速（PROPOSED） | 方向 DECIDED，实现 DEFERRED |
| 弹力护甲 | 将部分伤害转入数秒内结算的创伤池 | 持续火力与创伤累积（PROPOSED） | 方向 DECIDED，实现 DEFERRED |

本轮不增加其他护甲家族。烧蚀涂层、动力外骨骼或定向防护等构想不进入当前范围，未来另行评审。

插板护甲使用两条独立轴：I-VI 是全局可比较的防护等级，轻型、中型、重型是同等级内的防护与机动构型。两条轴共同形成 18 个第一版配置档位（DECIDED）。

## 二、第一阶段范围：插板护甲系列

### 2.1 本阶段包含

用户确认的范围（DECIDED）：

1. I-VI 防护等级乘以轻型、中型、重型构型，共 18 档插板护甲。
2. 三类插板的机动差异。
3. 与枪匠完成乘算后的伤害和爆头结果，以及 TaCZ 源枪的 `armorIgnore` 穿甲率联动；爆头是否符合插板保护条件另行拍板。

为满足后期精英怪高伤害环境，本轮另行提出一项范围扩展（PROPOSED）：对普通精英近战、护甲敏感投射物、护甲敏感爆炸和 `champion_skill_aoe` 等非 TaCZ 护甲敏感伤害提供独立防护，不让高单发伤害击穿原版护甲公式后完全失去等级差异。

交付要求（DECIDED）：

1. 按第三章第一版公式区分 TaCZ 直接弹道伤害的普通段与穿甲段。
2. 必要的物品提示、服务端配置与状态同步。
3. 纯公式与状态自动测试，以及固定 TaCZ 测试实例中的实弹集成测试。

### 2.2 本阶段不包含（DECIDED）

- 电浆容量、破盾和充能。
- 纳米陶瓷完整拦截次数。
- 弹力护甲创伤池。
- 稀有护甲模块与随机词条。
- 枪匠射速组件、穿甲组件或其他枪匠扩展。
- 对冠军系统、酿酒师、厨师或其他职业进行顺手重构。

如果插板实现必须修改共享伤害管线，应先单独评审影响范围；不得把相邻模块改动夹带进插板护甲实现分支。

## 三、术语与基础伤害模型

### 3.1 术语

| 符号 | 含义 |
|---|---|
| `H` | 用于文档推导的本次弹丸概念总伤害，已包含源枪数据、距离曲线、启用时的枪匠伤害系数和爆头倍率；不存在一个直接提供完整 `H` 的 `LivingHurtEvent` |
| `p` | TaCZ 对本次弹丸解析并限制到 `0.0-1.0` 的 `armorIgnore`；插板实现不需要重新读取该值 |
| `M` | 肉伤，即不穿甲的弹道伤害部分 |
| `P` | 穿甲伤害部分 |
| `R` | 当前防护等级与构型在第一版矩阵中对应的肉伤防护率 |
| `G` | 当前防护等级与构型对非 TaCZ 护甲敏感伤害的固定防护率 |
| `D` | 用于文档比较的两段伤害在插板处理后的名义总和，不是单个事件值，也不是最终扣血 |

本项目内“肉伤”是方便讨论的简称，正式含义为“非穿甲弹道伤害部分”，不是新的 Minecraft 伤害类型。

### 3.2 TaCZ 伤害拆分（已核对实现）

```text
M = H × (1 - p)
P = H × p
```

TaCZ 会将同一颗弹丸拆成普通弹道伤害和无视护甲的穿甲伤害，并分别调用伤害入口。`LivingHurtEvent` 实际收到的是已经包含爆头结果的 `M` 或 `P`，不是完整的 `H`；当 `p = 0`、`p = 1`、某段为零或被其他处理器取消时，不保证能够观察到两个非零事件。

第一阶段插板不重新配对两段调用，也不重算 `H` 或 `p`。在插板处理器边界内，必须直接对普通弹道段执行：

```text
normalSegmentAfter = normalSegmentBefore × (1 - R)
```

铸甲师插板处理器不修改穿甲段。该伤害类型会绕过原版护甲值与韧性，但仍可能受到保护附魔、抗性、TaCZ 防弹属性和职业减伤等其他独立伤害层影响；这些层与插板的先后顺序见 6.2，不能预先统称为下游。不得将两段重新合并并制造第三次伤害。

### 3.3 插板核心公式（DECIDED）

```text
D = P + M × (1 - R)
```

展开后为：

```text
D = H × p + H × (1 - p) × (1 - R)
```

这条公式用于平衡推导和界面说明，并不要求代码在运行时重建完整 `H`。定案的是插板处理器输入与输出之间的边界公式，不是玩家最终扣血公式；6.2 的减伤层顺序确定前不得注册实际受击处理器。它保证：

- `p = 0` 时，全部弹道伤害受到插板防护。
- `p = 1` 时，插板完全不起作用。
- 提高插板防护档位只增强肉伤防护，不会偷偷削弱穿甲价值。
- 枪匠提高伤害或爆头后直接提高 `H`，不会绕过或重复进入护甲公式。

插板是否覆盖爆头的普通弹道段仍为 `PENDING`；在该规则确认前，第三章公式只描述“符合插板保护条件的命中”。

### 3.4 不允许的结算方式

1. `VERIFIED`：不使用 TaCZ 通用 `bullet_resistance` 作为插板主防护，因为该属性会同时降低普通弹与穿甲弹。
2. `DECIDED`：不得让插板百分比、原版护甲值、护甲韧性和另一套职业减伤在未知顺序下叠乘上线；具体顺序与总上限仍为 `PENDING`。
3. `DECIDED`：不在铸甲师代码中读取 `MiningDimGunsmith` NBT 重新计算伤害、爆头或射程。
4. `VERIFIED`：不以两次 `LivingHurtEvent` 的出现次数代表两颗子弹；TaCZ 的肉伤段和穿甲段仍属于同一弹丸。

## 四、I-VI 级轻型、中型与重型插板

### 4.1 三类共同规则（弹道规则 DECIDED；非 TaCZ 规则 PROPOSED）

1. 三类插板共用第三章的伤害公式。
2. 已确认由 I-VI 防护等级与轻、中、重构型共同决定弹道肉伤防护率 `R`；另推荐用同样两条轴决定非 TaCZ 护甲敏感伤害防护率 `G`。构型另行决定机动修正；耐久、维修和装备成本差异仍待确认。
3. 同一玩家在同一时刻只生效一种插板类型，不能把轻、中、重三档逐件线性叠加。
4. 在铸甲师插板处理器边界内，穿甲段不受插板档位影响。
5. 插板未装备、未生效，或被后续耐久规则判定为完全失效时，不得残留隐藏的自定义减伤。
6. 第一版不模拟胸、腹、侧面等独立覆盖区域；轻、中、重不是额外的局部命中判定。爆头保护资格仍按第九章单独拍板。

### 4.2 类型定位（弹道与机动 DECIDED；非 TaCZ PROPOSED）

| 类型 | 防护关系 | 机动关系 | 第一版玩法定位 |
|---|---|---|---|
| 轻型插板 | `R_light < R_medium` | 提供正向机动修正 | 游击、侦察、快速换位，以正面承伤能力换取机动能力 |
| 中型插板 | 位于轻型与重型之间 | 不提供正向或负向修正 | 通用基准，便于建立其他护甲的平衡参照 |
| 重型插板 | `R_heavy > R_medium` | 提供负向机动修正 | 阵地、突破与正面交火，以速度换持续防护 |

已确认的弹道防护关系必须始终满足：

```text
0 < R_light < R_medium < R_heavy < 1
```

若采用 4.5 的非 TaCZ 固定防护方案，推荐同时满足：

```text
0 < G_light < G_medium < G_heavy < 1
```

### 4.3 第一版增强弹道防护数值（PROPOSED）

I-VI 是全局防护等级，轻、中、重是同等级内的构型差异。根据已确认的钻石套定位，推荐第一版 TaCZ 肉伤防护率 `R` 如下：

| 防护等级 | 轻型 | 中型 | 重型 |
|---|---:|---:|---:|
| I | 45% | 50% | 55% |
| II | 60% | 65% | 70% |
| III | 75% | 80% | 85% |
| IV | 85% | 88% | 90% |
| V | 90% | 92% | 94% |
| VI | 94% | 96% | 98% |

用户确认后，表格才成为实现与配置的权威默认值。高等级不再线性增加：越接近 100%，每减少一个百分点的剩余伤害都越强，因此推荐保留递减增幅。

该矩阵保证：

1. 同等级严格满足轻型小于中型、中型小于重型。
2. 同一构型随等级严格增强；低一级重型不会反超高一级轻型。
3. 最高值为重型 VI 的 98% 肉伤防护，仍保留 2% 肉伤泄漏，不取代纳米陶瓷板未来的完整拦截定位。
4. 穿甲仍按第三章完全通过；整发实际减伤率为 `(1 - p) × R`，不是表内 `R` 本身。

完整无附魔钻石套的原版伤害减免最高为 80%。因此 III 级中甲的 `R = 80%` 可以在任意纯肉伤段上达到或超过钻石套，落实“完整钻石套顶多属于 III 级中甲”的弹道定位。V-VI 级必须依靠高穿甲率、耐久消耗、成本和机动惩罚反制，不能再通过继续膨胀普通肉伤解决。

两把地板枪在各等级的整发实际减伤如下：

| 防护等级 | M4A1，20% 穿甲（轻/中/重） | AKM，25% 穿甲（轻/中/重） |
|---|---:|---:|
| I | 36% / 40% / 44% | 33.75% / 37.5% / 41.25% |
| II | 48% / 52% / 56% | 45% / 48.75% / 52.5% |
| III | 60% / 64% / 68% | 56.25% / 60% / 63.75% |
| IV | 68% / 70.4% / 72% | 63.75% / 66% / 67.5% |
| V | 72% / 73.6% / 75.2% | 67.5% / 69% / 70.5% |
| VI | 75.2% / 76.8% / 78.4% | 70.5% / 72% / 73.5% |

当 `p = 0` 时，整发实际减伤等于表内防护率；当 `p = 1` 时，三种构型和六个等级的插板减伤均为 0。专用穿甲弹的具体穿甲率档位属于弹药系统后续平衡，不在本轮修改枪匠或源枪数据。

### 4.4 第一版机动修正规则（DECIDED；总上限 PENDING）

| 构型 | 移动速度修正 |
|---|---:|
| 轻型 | +3% |
| 中型 | 0% |
| 重型 | -4% |

1. 第一版只调整玩家移动速度，不同时加入冲刺、跳跃、开镜或换弹修正，避免一次引入过多变量。
2. 表内百分比使用 `MOVEMENT_SPEED` 的瞬态 `MULTIPLY_TOTAL` 修饰：轻型 amount 为 `0.03`，重型为 `-0.04`，中型不挂修饰。与酿酒师现有 `MULTIPLY_BASE` 移速按原版属性顺序结算。
3. 机动值只由构型决定，不随 I-VI 防护等级再次增长或衰减。
4. 机动修正按玩家当前生效的插板类型聚合一次，不按护甲件数累加。
5. 属性修正必须使用稳定、固定的标识，换装、登录、死亡、克隆和跨维度后重复计算不得叠层或残留。
6. 轻甲加速需与 TaCZ 持枪减速及酿酒师现有移动增益一同测试。最终玩家移动速度总上限仍为 `PENDING`。
7. 枪匠操控组件继续影响枪械本身；插板不得修改成品枪 NBT 来实现移动效果。

### 4.5 非 TaCZ 护甲敏感伤害（PROPOSED；最终总帽接线 PENDING）

推荐让普通精英近战、护甲敏感投射物、护甲敏感爆炸以及 `champion_skill_aoe` 使用固定防护率 `G`。这套候选数值不会像原版护甲公式一样被高单发伤害快速侵蚀：

| 防护等级 | 轻型 | 中型 | 重型 |
|---|---:|---:|---:|
| I | 30% | 35% | 40% |
| II | 40% | 45% | 50% |
| III | 55% | 60% | 65% |
| IV | 65% | 70% | 75% |
| V | 75% | 78% | 80% |
| VI | 80% | 83% | 85% |

```text
nonTaczArmorDamageAfter = damageBefore × (1 - G)
```

1. `G` 是完整生效插板系统的总防护率，不是每个护甲部位各自拥有一份，也不得与原版护甲值、韧性再次乘算。
2. III 级中甲以 20 点及以上单次伤害作为钻石套内容定位基准：20 点时两者都受到 8 点伤害；48 点和 72 点精英重击下，III 级中甲分别受到 19.2 与 28.8，完整钻石套则受到 32.64 与 60.48。低于约 20 点的碎片伤害中，钻石套可能因原版公式接近 80% 上限而短暂更强；常规 TaCZ 子弹另由 `R = 80%` 的 III 级中甲弹道基线兜住。
3. V-VI 级本体最高停在 85%，为职业、抗性和附魔留下空间。仅对非 TaCZ 护甲敏感伤害，其所有被动防护建议在合并后统一封顶 90%；当前代码只对职业来源执行 85% 帽，真正的最终 90% 帽需要独立共享伤害管线评审，不能夹带进插板实现。
4. `bypasses_armor`、虚空、摔落、饥饿、火焰、魔法、DoT、反震真伤和命定处决不进入 `G` 公式，也不进入建议的护甲敏感伤害 90% 被动聚合器。冠军普通近战、重炮与嗜血的普通分量、电磁蓄力、天雷、小男孩和利刃华尔兹应当进入。当前反震与处决伤害源只绕过护甲和保护附魔，并不绕过状态效果；这里保留其原有伤害源语义，不把现状误写为已经免疫职业减伤或抗性。
5. TaCZ 子弹只走第三章的 `R` 与穿甲分段公式，不再叠加 `G`。非 TaCZ 的 90% 建议总帽也不得把 V-VI 级零穿甲弹道统一压平。
6. 大额 AOE 后的两秒伤害免疫缓冲是冠军系统的反叠杀硬规则，不属于被动百分比防护，完全位于建议的 90% 聚合器之外。
7. `VERIFIED`：当前冠军 `ARMOR_PIERCING` 词条把所谓穿甲分量加回普通 `mob_attack` 事件，实际上仍会被护甲削减。它不能被当作已经存在的护甲反制；若要提供精英穿甲，必须在独立修复分支中把普通段与真正绕甲段拆开。

### 5.3 M4A1 第一版数值示例

M = 9.75 × 0.80 = 7.80

套用第四章 IV 级插板数值：

| 重型 IV | 90% | `1.95 + 7.80 × 0.10` | 2.73 | 72% |

该示例是第一版 IV 级候选值的精确评审样本，只覆盖身体命中；矩阵确认后再转为验收样本。M4A1 不是完整枪械梯度，爆头是否受插板保护仍待拍板。

## 六、装备模型与兼容边界

### 6.1 单一生效来源（PROPOSED）

推荐由胸甲、载板背心或护甲核心唯一决定玩家当前护甲家族和插板档位。其他护甲槽可以提供外观、耐久或非防护属性，但不得各自产生完整的插板减伤。物品形态究竟是独立可穿胸甲、载板背心加可替换插板，还是整套护甲，仍为 `PENDING`。

采用单一权威槽的理由：

- 防止轻、中、重逐件叠加。
- 为后续电浆、纳米陶瓷和弹力护甲提供互斥入口。
- 简化提示、HUD、存档和受击测试。
- 防止换装组合形成没有明确弱点的多重防御。

是否最终采用胸甲作为唯一生效来源仍为 `PENDING`，但在替代方案确认前不得按四件独立叠加实现。

### 6.2 与原版护甲的关系（PROPOSED；最终聚合 PENDING）

1. 对 TaCZ 弹道伤害，第三章的 `R` 公式替代原版护甲值与韧性的弹道减伤，不得在插板后再次套用钻石甲公式。
2. 对 4.5 定义的非 TaCZ 护甲敏感伤害，固定 `G` 公式替代原版护甲值与韧性，不得逐件或逐层重复乘算。
3. 对 4.5 明确排除的伤害，插板不提供自定义防护；是否由其他系统处理，遵循该伤害类型原有规则。
4. 物品形态尚未确定，因此表内数值表示完整生效护甲系统的总预算，不得直接复制到头盔、胸甲、护腿和靴子四个部位。

当前结算顺序事实（VERIFIED）：Forge 1.20.1 的 `LivingHurtEvent` 位于原版护甲、韧性、抗性和保护附魔计算之前；TaCZ 1.1.8 的防弹属性处理器位于 `LOW`，Wok 的 `PlayerDamageReduction` 聚合点位于 `LOWEST`。新插板若另起处理器，结果会受到事件优先级影响。

仍必须明确插板相对于 TaCZ 防弹属性、职业减伤、保护附魔和抗性效果的聚合点与事件优先级。当前 `PLAYER_MAX_REDUCTION = 85%` 只覆盖注册进 `PlayerDamageReduction` 的来源，不是包含所有防御层的真正最终帽。4.5 推荐的 90% 被动帽只允许聚合非 TaCZ 护甲敏感伤害；处决、反震真伤、冠军 DoT 和两秒硬免疫必须完全绕开该聚合器。共享伤害管线需要另行评审，这些规则拍板前不得注册实际受击处理器。

### 6.3 与既有纳米系统的冲突（发布阻塞项）

1. 既有“纳米护甲板”是通用维修消耗品，不是本系统的可穿戴插板。将其玩家可见名称调整为“纳米修复板”只是 `PROPOSED` 命名候选；是否改名仍需用户确认，已有注册 ID 不应随显示名变化。
2. 既有“纳米多重护盾”是按件存在的限时全伤害免疫，与新护甲资源模型冲突。
3. 新插板发布前必须确定旧护盾对新护甲是禁用、迁移还是退役；未处理前不得允许两者叠加上线。
4. 插板耐久是否由普通耐久、独立完整度或可替换板件表示仍为 `PENDING`。

## 七、后续护甲家族备忘

本章保存用户已确认的概念方向以及明确标出的待评审建议，不提供实现常量。

### 7.1 电浆护盾（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 使用可恢复能量容量，不提供百分比减伤。
- 护盾击碎后等待一段时间才能重新充能。
- 高伤害、低穿甲的肉伤武器应当能够快速消耗护盾。

待评审建议（PROPOSED）：

- 按概念总伤害点数消耗容量，穿甲率不提供额外破盾加成。
- 护盾不足时保留溢出伤害。
- 爆头和持续输出按实际最终伤害继续消耗容量。

候选公式：

```text
shieldAfter = max(0, shieldBefore - H)
overflow = max(0, H - shieldBefore)
```

这里的 `H` 仍是概念值。未来实现必须选择能够“一颗弹丸只处理一次”的上游边界，并明确纳入爆头结果；不得在插板的分段 `LivingHurtEvent` 处理器中重新配对两段来恢复 `H`。

### 7.2 纳米陶瓷板护甲（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 有剩余次数时完整抵挡一次符合条件的伤害。
- 每次成功抵挡消耗一次，次数耗尽后完全失去自定义防护。

待评审建议与技术约束：

- 高射速与连续射击是主要反制。
- TaCZ 一颗子弹拆出的肉伤和穿甲两段只能共同消耗一次；未来应使用一弹一次的上游事件或稳定弹丸标识，不得按观察到的 `LivingHurtEvent` 次数扣除。
- 霰弹按每颗弹丸还是同一次开火合并计次仍为 `PENDING`。

### 7.3 弹力护甲（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 将部分伤害延迟为数秒内逐步结算的创伤，而不是直接消除伤害。

待评审建议（PROPOSED）：

- 爆发命中时只立即承受一部分，剩余部分加入玩家创伤池。
- 持续火力会不断累积创伤，构成主要反制。
- 创伤状态不能通过脱甲、换装、下线或跨维度清除。
- 创伤比例、结算时间、治疗交互和致死规则仍为 `PENDING`。

候选模型：

```text
immediateDamage = H × (1 - q)
traumaAdded = H × q
```

其中 `q` 为延迟比例，创伤在后续确认的时间内分段结算。
