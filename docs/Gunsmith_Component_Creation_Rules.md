# 枪匠新组件制作规范

> 状态：已确认，后续制作枪匠新组件统一遵循本规范。
> 关联文档：[枪匠组件命名计划](Gunsmith_Component_Naming_Plan.md)、[枪匠组件平衡与后续扩展路线](Gunsmith_Component_Balance_Roadmap.md)、[格赫娜高速导气组件规格](Gunsmith_Gehenna_High_Speed_Gas.md)。

## 一、规范定位

本文件是枪匠新组件从设计、图标、数据显示到实现验收的通用工作规范。单件组件仍需建立独立规格，用于确定其平台、槽位、属性公式、获取方式和兼容策略；单件规格不得省略或绕过本文件规定的身份、显示、排序与验收要求。

制作新组件前，必须先确认以下五个独立维度：

| 维度 | 含义 | 示例 |
|---|---|---|
| 平台 | 枪械兼容族 | `AK`、`AR` |
| 槽位 | 实际装配位置 | 导气、枪机、枪管 |
| 组件类型 | 同平台、同槽位下的结构或功能变体 | 基础导气、红冬高压导气 |
| 品质 | 同一组件类型内部的品质档位 | 普通、改良、军规、精密、传奇 |
| 制造势力 | 组件的世界观制造方 | 红冬、格赫娜 |

制造势力不是枪械平台。势力标识不能参与或替代平台兼容判定。

## 二、组件身份与命名

### 2.1 身份要求

每个新组件必须明确：

1. 唯一且稳定的内部 `variant` 标识。
2. 适用平台。
3. 唯一装配槽位或明确批准的槽位集合。
4. 五档品质的数值规则。
5. 制造势力；基础组件不绑定势力。
6. 正面效果与负面代价。
7. 数据版本及旧物品、旧成枪兼容规则。

平台或槽位不匹配时必须明确拒绝，不能通过显示名、贴图或默认值猜测组件身份。

### 2.2 显示名

基础组件继续使用：

```text
{平台}基础{槽位} {品质}
```

势力特制组件使用：

```text
{势力名称}{功能特征}{部件类型} {品质}
```

示例：

- `AR基础导气 传奇`
- `红冬高压导气 军规`
- `格赫娜高速导气 精密`

功能特征必须直接表达组件的主要性能方向，不能只使用玩家无法理解的内部代号。

## 三、品质与数值设计

### 3.1 品质顺序

所有可生产组件默认沿用五档品质：

```text
普通 -> 改良 -> 军规 -> 精密 -> 传奇
```

组件进入实现前必须逐档确定：

- 初始数值。
- 品质换算公式或逐档表格。
- 最终上限与下限。
- 单件浮动系数是否参与特殊效果。
- 哪些变化是增益，哪些变化是减益。

不得只写“提高”或“降低”而不提供可验证的实际数值。不得在结算末端用静默钳制替代已批准的平衡规则。

### 3.2 收益与代价

特殊组件必须提供明确构筑取舍，不能成为基础组件的无条件全面上位替代。显著强化核心属性时，至少绑定一项会在实战中真实生效的代价或限制。

正面效果与负面效果必须同时满足：

- 写入组件或成枪数据。
- 出现在装配预览中。
- 出现在物品或成枪 tooltip 中。
- 参与最终实战属性结算。
- 由自动测试断言具体数值。

### 3.3 已确认示例

红冬高压导气是 AK 平台导气槽的势力特制组件，以伤害提升交换射速与垂直后坐表现：

| 品质 | 伤害乘区 | 射速乘区 | 垂直后坐乘区 |
|---|---:|---:|---:|
| 普通 | `1.20` | `0.95` | `1.30` |
| 改良 | `1.40` | `0.90` | `1.60` |
| 军规 | `1.60` | `0.85` | `1.90` |
| 精密 | `1.80` | `0.80` | `2.20` |
| 传奇 | `2.00` | `0.75` | `2.50` |

其中伤害提高是增益，射速降低和垂直后坐提高是减益。

格赫娜高速导气是 AR 平台导气槽的独立组件，其射速、上跳后坐、散布、射程替换和兼容规则以[独立组件规格](Gunsmith_Gehenna_High_Speed_Gas.md)为唯一数值来源，不在通用规范中复制公式。

## 四、简介规则

每个部件必须提供一条简介。

基础部件统一采用以下句式，只替换部件名称：

```text
基础的枪机，用于最基本的枪械组装，不提供额外的加成，当然也没有额外的性能惩罚。
```

势力组件简介必须同时说明：

1. 制造或改装势力。
2. 调校方式或结构特点。
3. 核心增益。
4. 对应代价。

格赫娜高速导气的已确认简介为：

```text
经过格赫娜学院加压调教过的高速导气箍，使其射速变得更快，当然，后坐力也有所增高。
```

简介用于解释设计意图，不能替代实际属性行；文案、数据与实战结果必须一致。

## 五、势力与图标

### 5.1 当前势力清单

枪匠组件当前允许使用以下制造势力或集团标识：

1. 红冬。
2. 山海经。
3. 千禧年。
4. 格赫娜万魔殿。
5. 格赫娜。
6. 格赫娜风纪委员会。
7. 百鬼夜行。
8. 阿拜多斯。
9. 凯撒 PMC。
10. 圣三一。

格赫娜、格赫娜万魔殿和格赫娜风纪委员会是三个独立的制造标识，不得相互替代。

### 5.2 图标处理

- 基础组件不添加势力 LOGO。
- 势力组件在物品图标右下角添加对应 LOGO，用于避免与普通组件混淆。
- LOGO 只表示制造势力，不表示枪械平台，也不参与数据判定。
- 组件主体继续采用当前物品图标处理流程。
- 势力 LOGO 不做低清化，保持原始清晰度和可辨识轮廓。
- LOGO 不得遮挡主体关键结构，尺寸和边距在同批图标中保持一致。
- 品质继续由现有品质外框或品质色表达，不使用 LOGO 表达品质。
- 每个“平台、槽位、组件类型、品质”组合必须绑定唯一且正确的模型数据。

势力图标同质化的整体视觉重制暂缓；在新规范另行确认前，不把独立轮廓重制作为新增组件的强制交付条件。

## 六、tooltip 信息层级

组件 tooltip 必须依次提供：

1. 适用平台。
2. 部件槽位。
3. 组件型号或制造势力。
4. 简介。
5. 品质。
6. 单件浮动系数。
7. 特殊属性效果。

颜色规则：

| 信息 | 颜色语义 |
|---|---|
| 增益 | 绿色 |
| 减益 | 红色 |
| 中性说明 | 灰色或既有中性色 |
| 特殊组件或效果标题 | 金色 |
| 品质 | 对应品质色 |

特殊效果必须分行显示，不能将多个不同方向的属性合并为统一颜色。颜色必须按属性含义判断，例如伤害提高和射速提高是增益，射速降低、散布提高和后坐力提高是减益。

浮动系数的显示规则为：

- 高于 `x1.000`：绿色。
- 低于 `x1.000`：红色。
- 等于 `x1.000`：中性色。

颜色只负责辅助识别，正负号和数值必须同时保留，不能仅靠颜色传达属性方向。

## 七、创造模式排序

枪匠组件在创造模式物品栏中统一采用：

```text
平台优先 -> 同系列连续 -> 势力系列
```

具体规则：

1. 先按平台形成完整分组。
2. 同一平台的基础系列必须连续排列完成。
3. 该平台的势力特制系列排列在基础系列之后，并按势力分别保持连续。
4. 同一系列内部按槽位和品质顺序排列。
5. 势力组件不得穿插到基础系列中间。

## 八、数据、兼容与装配

- 组件类型使用稳定 `variant` 保存，不能塞入平台、槽位、品质或显示名。
- 新物品显式保存平台、槽位、品质、组件类型、单件系数和数据版本。
- 新成枪显式保存已装组件类型及其最终属性缓存。
- 旧数据缺少组件类型时，只能按明确的版本迁移规则读取为基础组件。
- 不得根据名称、贴图或 LOGO 反推组件类型。
- 组件只能装入匹配的平台和槽位；不兼容数据必须明确拒绝。
- 特殊组件不得擅自增加、删除、替换或重排源枪射击模式。
- 装配预览、成枪 NBT、成枪 tooltip 与 TaCZ 实战属性必须一致。

## 九、实现与验收清单

每个新组件至少完成以下闭环：

1. 建立或更新独立组件规格。
2. 注册稳定组件类型及平台、槽位兼容关系。
3. 完成五档品质数值或明确的品质公式。
4. 完成名称、简介、中英文 tooltip 和正负属性颜色。
5. 完成五档图标、品质表现及势力 LOGO。
6. 接入冲压选择、材料消耗与产物数据。
7. 接入装配校验、预览、成枪数据和实战属性。
8. 验证旧物品和旧成枪迁移。
9. 添加可达业务用例，覆盖平台限制、槽位限制、五档数值、正负效果、装配结果和非法组合拒绝。
10. 对应工程编译通过；核心业务变更的 Forge GameTest 日志必须出现 `All N required tests passed`。
11. 部署前核对 WOK 本体产物与测试目录，不能把 WOK 本体和 WOK步战附属混装。

## 十、新组件资料模板

后续提出新组件时，按以下模板提供资料：

```text
组件名称：
稳定 variant：
制造势力：
适用平台：
部件槽位：

核心增益：
性能减益：

普通品质数值：
改良品质数值：
军规品质数值：
精密品质数值：
传奇品质数值：

浮动系数参与方式：
组件简介：
主体参考图：
势力 LOGO：
获取或制造方式：
旧数据兼容要求：
```

资料确认后，先更新独立组件规格，再进入代码、资源、测试和客户端部署阶段。
