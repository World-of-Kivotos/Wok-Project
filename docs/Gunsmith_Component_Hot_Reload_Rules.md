# 枪匠特殊组件热更新规则

## 一、目标

枪匠特殊组件的伤害、爆头倍率、射速、有效射程、散布、全向后坐、额外垂直后坐和开镜速度倍率由服务端 datapack 管理，不再把平衡数值写死在组件枚举中。服务器可用 `/reload` 更新规则，无需替换 JAR 或重启服务端。

服务端始终是规则权威。玩家登录及 datapack 重载完成后，服务端会向客户端同步完整规则快照，物品说明、组装预览与实际 TaCZ 属性使用同一份数值。

## 二、数据位置

内置规则位于：

`data/miningdim/gunsmith/components/<variant>.json`

服务器覆盖规则时，在世界目录放置 datapack，例如：

`world/datapacks/wok_gunsmith_balance/data/miningdim/gunsmith/components/red_east_high_pressure_gas.json`

覆盖包的第二层目录必须写 `miningdim`，不能换成自己的包名：datapack 的覆盖语义要求覆盖方沿用被覆盖资源的完整标识。写成别的命名空间时该文件会被忽略并在日志留一条 WARN，不会生效，也不会影响开服。

`red_east_high_pressure_gas` 是红冬高压导气的稳定内部标识。显示名继续使用“红冬高压导气”，不得为了修正文案改动内部标识，否则会破坏存量物品兼容。

## 三、字段契约

每个规则文件必须完整提供以下字段：

- `damage`：特殊组件自身的额外伤害倍率，与枪机伤害系数继续相乘，不是整枪伤害上限。
- `headshot`：特殊组件自身的额外爆头倍率，在基础枪管品质系数之后相乘，不会被基础“枪机×枪管品质”封顶吞掉。
- `fire_rate`：射速倍率。
- `effective_range.operation`：射程运算方式，只允许 `multiply` 或 `replace`。
- `effective_range.values`：五档品质的射程倍率。
- `ammo_speed`：TaCZ 弹丸速度倍率；大于 `1.0` 表示弹速提高。
- `armor_ignore`：穿甲倍率；小于 `1.0` 表示穿甲下降，是特殊组件常用的负面代价字段。
- `spread`：直接乘到最终腰射与瞄准散布上的倍率；大于 `1.0` 表示散布恶化。
- `recoil`：直接乘到最终水平与垂直后坐上的全向倍率；大于 `1.0` 表示后坐增大。
- `vertical_recoil`：在全向后坐之后再次施加的额外垂直倍率。
- `ads_speed`：开镜速度倍率；小于 `1.0` 表示开镜变慢。

每组倍率必须同时包含 `common`、`improved`、`milspec`、`precision`、`legendary`。数值必须有限且位于 `0.05-10.0`。上列字段一个都不能少（`effective_range` 计 `operation` 与 `values` 两项，另外九项各计一项，共十一项），漏写任意一项本次加载都会失败。

第四节起的数值表只列该组件真正偏离 `1.0` 的字段；表里没出现的字段，该组件五档一律为 `×1.00`，但写覆盖文件时仍必须把它们完整写出来。

加载失败时的行为分三档，运维据此判断日志：

- 文件名必须精确等于组件稳定标识。`basic`、`gehenna_high_speed_gas`、`mk_ax_a_receiver` 只是存量物品迁移用的历史别名，不是合法文件名；用它们命名的文件会被忽略并在日志留 ERROR。`base.json` 同样不接受覆盖，基础组件恒为全 `1.0` 的单位规则。
- 覆盖文件字段缺失、品质不全、数值越界或运算方式未知时，本次加载明确失败：`/reload` 报 `commands.reload.failure` 并继续使用上一次成功加载的完整快照；开服期则整包加载失败，服务端不会带着半套规则启动。
- 覆盖文件 JSON 语法错误（尾逗号、缺引号）走另一条路径：原版只会打印一行 `Couldn't parse data file ...` 后丢弃该文件，且被它覆盖的 JAR 内置副本不会再被读取。此时该组件回退到 JAR 内置数值，日志另给一条指名该组件的 ERROR，服务端照常启动 —— 但你的平衡改动没有生效，看到这条 ERROR 就去修上面那行解析错误。

`multiply` 表示把规则倍率乘到对应基础组件系数上；`replace` 表示特殊组件用规则倍率替换基础组件对该属性的系数。红冬高压导气的射程使用 `multiply`：五档规则值均为 `0.60`，表示在各品质原有射程系数上追加 40% 惩罚，而不是把最终射程锁定为同一个数值。

## 七、实际叠乘顺序

- 最终伤害：`TaCZ 基础伤害 × 枪机系数 × 各特殊组件伤害倍率`。
- 最终爆头倍率：`TaCZ 基础爆头倍率 × 基础枪管品质系数 × 各特殊组件爆头倍率`。
- 最终有效射程：`TaCZ 基础射程 × 导气品质浮动系数 × 各特殊组件射程倍率`。
- 最终散布：`TaCZ 基础散布 ÷ 护木系数 × 各特殊组件散布倍率`。
- 无外部配件时的最终水平后坐：`TaCZ 基础水平后坐 ÷ 枪托系数 × 特殊导气全向后坐倍率`。
- 无外部配件时的最终垂直后坐：`TaCZ 基础垂直后坐 ÷ 枪托系数 × 特殊导气全向后坐倍率 × 额外垂直后坐倍率`。
- TaCZ 外部配件只修正“原枪后坐”部分；势力组件自身增加的后坐作为独立增量在外部配件之后叠加，不会被制退器、握把等同比消除。
- 带外部配件时的水平系数：`(外部配件水平倍率 + 全向后坐倍率 - 1) ÷ 枪托系数`。
- 带外部配件时的垂直系数：`(外部配件垂直倍率 + 全向后坐倍率 × 额外垂直后坐倍率 - 1) ÷ 枪托系数`。
- 最终穿甲：`枪型基础穿甲 × 服务端穿甲基线倍率 × 各特殊组件穿甲倍率`。
- 最终弹丸速度：`TaCZ 基础弹速 × 各特殊组件弹速倍率`。
- 最终射速：`TaCZ 基础射速 × 特殊导气射速倍率`。
- 最终开镜时间：`TaCZ 基础开镜时间 ÷ 握把系数 ÷ 各特殊组件开镜速度倍率`。

## 十二、存量枪兼容

枪匠成枪数据版本 v7 只在 NBT 中缓存由品质浮动系数推导出的基础属性，并保存各组件的 `variant`、品质和原始系数。特殊组件的动态倍率在读取枪械时从当前规则快照计算。AR 始终使用原有六槽；早期误写为机匣的 v4 MK-AX-A 数据会迁移回枪机槽。v5 的五槽精准射手成品会补入系数 `1.0` 的兼容握把；v6 的四槽栓动式步枪成品会补入系数 `1.0` 的兼容撞针，两类旧成品的原操控均保持不变。

因此，热更新后：

- 已经组装的红冬枪械立即使用新数值。
- 新组装枪与旧枪使用同一规则，不需要重新组装。
- 单纯调整平衡倍率不再要求提升枪械数据版本。
- v1、v2 存量枪继续走既有迁移读取；v2 红冬枪允许旧的射程缓存 `1.0`，运行时按当前规则计算。

## 十三、运维流程

1. 修改服务器 datapack 中对应组件 JSON。
2. 先校验 JSON 语法以及五档品质是否齐全。
3. 在服务端执行 `/reload`。
4. 确认日志出现枪匠规则加载成功记录。
5. 用已存在的成枪和新组装枪分别核对 tooltip、组装预览与实射属性。

新增组件型号仍属于代码与资源扩展：必须先注册稳定 `variant`、平台与槽位兼容、图标/CMD、语言键和默认 datapack 文件。热更新接口只允许调整已注册组件的属性，不能凭 JSON 动态创建新的组件类型。
