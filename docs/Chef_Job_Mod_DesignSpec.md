# 厨师 职业 Mod — 设计规格文档

## 文档元信息

- 用途: 厨师职业实现阶段的唯一架构与机制参考。所有规则以本文档为准, 不得凭记忆改写。
- 目标平台: Minecraft 1.20.1 + Forge 47.x + Java 17。
- 部署环境(硬约束): 公服人均初始血量 80(非原版20)、TACZ 枪械(TTK 以秒计)、死亡不掉落、PvP+PvE。战斗向数值一律 %最大血量、抗性≤III、不破枪战 attrition。
- 跨 mod: 设计目标为支持任意食物 mod 的菜(农夫乐事 FD、烟火凡人心 FID 等), 经 `ItemStack.getFoodProperties(entity)` 通用判定, 软依赖(`ModList.get().isLoaded`)接入, 不碰别人 mod 内部。
- 状态图例: DECIDED 已定稿；本阶段锁定的实现选择、标签契约和客户端同步字段均以本文为准。
- 前置依赖: 复用职业框架两项前置(entry 玩家 Capability 的 `EnumMap<JobId,JobProgress>` 重构、公共 menu 脚手架)+ 共享 `ModEffects`(自定义效果框架)。

## 一、职业定位与设计目标 (DECIDED)

1. **品质层定位**: 厨师不从生料做菜, 也不再造一套"加调料给 buff"的系统(烟火凡人心已有该系统, 见第九章)。厨师拿**任意已做好的成品菜**(FD/FID/原版/任意食物 mod), 在调味台用技艺**盖一个品质 + 加厨师效果**, 锦上添花。定位 = 美食家/调味大师。
2. **品质 5 档**: 低级/中级/高级/超凡/闪耀(沿用塔罗/工程师同款词汇), 即"超凡面包""闪耀牛排"这种。
3. **跨 mod 通用**: 品质是盖在 ItemStack 上的 NBT, 不注册新物品, 故对任何食物 mod 自动支持。
4. **等级 1-10**: 谁做谁得经验, 复用全职业曲线与每日衰减。
5. **核心卖点**: 高级厨师的菜在吃下时有额外加成(饱食/续航/治疗/buff 强化/净化等), 且能放大别的 mod 菜自带的 buff(增香)。

## 二、核心机制总览 (DECIDED)

| 机制 | 一句话 | 章节 |
| --- | --- | --- |
| 品质 NBT | 给任意食物盖 `chefQuality`, 显示"超凡面包", 吃时给加成 | 三 |
| 调味台 | 5 档方块 + 投成品菜 + 调料 + 烹饪小游戏(火候+调味) | 四 |
| 调料 | 软依赖复用 FID 真实调味料, 偏置效果池 | 五 |

| 经验 | 谁做谁得, 按品质递增, 每日软上限 | 七 |
| 跨 mod | FID=调料矿, FD=成品菜库, getFoodProperties 通用 | 八 |

## 三、品质系统 (DECIDED)

- 品质 = ItemStack NBT `chefQuality`(低/中/高/超凡/闪耀)。物理上还是原物品(`minecraft:bread`/`farmersdelight:hamburger`/...), 只带品质标记 -> 跨 mod 通用、不注册新物品。
- 显示"超凡面包": `stack.setHoverName(带品质颜色的 Component, 可去斜体)` 改名; `ItemTooltipEvent`(对任意物品触发)读 NBT 追加"品质/食用加成"tooltip 行。两者通用, 模组菜也吃。
- 吃时加成: `LivingEntityUseItemEvent.Finish` 读 `chefQuality` + 效果 NBT, 按品质结算。
- **品质决定两件事**: (a) 效果倍率列; (b) **一道菜带几个效果**(低级 1 个 -> 闪耀最多 3 个)。
- **超凡/闪耀 = 零负面**: 不出夹生/烧焦/倒胃/多盐/失败品, 黑暗的大凶也不触发(100% 大吉)。低/中/高 才有翻车风险。这强化"高品质严格更优"且给"大成=道道完美"的身份。
- 副作用: 不同品质的菜彼此不堆叠(NBT 不同), 与原版同菜也不堆叠(预期, 同塔罗牌)。

## 四、调味台 (DECIDED 主方案)

- 5 档横向双格料理工位(低级/中级/高级/超凡/闪耀调味台), 同工程师五档生产台思路: **台档 + 厨师等级**决定能出的最高品质。左右半边只保留一个主方块实体和一份库存，破坏任一半都会安全拆除整台并返还库存。
- 客户端采用 GeckoLib 4.8.2 渲染一套横跨两格的精细动态模型；主格统一驱动空闲/烹饪动画，副格不重复渲染。五档共用几何和动画、使用独立材质图集，烹饪状态由服务端同步，不能由客户端自行切换。
- 输入: **成品菜(任意 mod)** + 可选**调料**(第五章)。
- **烹饪小游戏(服务端权威, 客户端只渲染, 防作弊)**, 两层:
  1. 火候条: 温度随时间涨, 点击控制保持"完美火候"绿区; 太生→低品质, 完美→高品质, 过火→失败品/多盐(仅低/中/高)。
  2. 调味 QTE: 烹饪中冒"调味时机点", 命中一次=给这道菜掷一个效果; 命中越多→效果越多、品质越高; 漏掉→降品质/翻车。
- **目标品质挑战**: 开始前由玩家选择目标品质，可选上限为 `min(调味台档位, 厨师等级上限)`。目标基础成功率为低/中/高/超凡/闪耀 `100%/70%/45%/25%/10%`；完美控火最多增加 50 个百分点，每次正确 QTE 增加 10 个百分点，最终封顶 100%。服务端只掷一次；达成即产出目标品质，未达成则降一档产出，不吞菜、不返还已完成事务的费用。效果仍由命中**从"已解锁池"随机掷出**, 池随厨师等级扩大(低级只有基础+翻车, 高级才解锁膳香/回甘等强效果)。
- 反挂机天然成立: 每道菜都要主动打小游戏, 漏斗/机器刷不了。
- 实现选择(DECIDED): 采用目标品质选择 + 火候按住/释放控火 + 四位置调味 QTE 的主方案；服务端保存目标品质、动态成功率、计时器、目标位置、命中数和结算结果，客户端只渲染并发送动作意图。QTE 支持鼠标及主键盘/小键盘 `1-4`，不启用投菜后自动概率结算的降级方案。

## 五、调料系统 (DECIDED)

- 调料 = 调味时额外投入的消耗品, 用来**偏置小游戏能掷出的效果池/方向**。
- **软依赖、可配置**: 调料集合走 tag + config(`ModList.get().isLoaded("flavor_immersed_daily")` 守卫), mod 不在则那几样不要求。默认填入 FID 真实调味料 + 原版糖/蜂蜜 + FD 番茄酱。
- FID 真实调料 ID(源码/jar 确认, `flavor_immersed_daily:<id>`):
  - 咸鲜: `salt` `soy` `pepperedsalt` `thickbroadbeansauce` `sweetflourasuve`
  - 油脂: `cookingoil` `sesameoil` `butter` `cream`
  - 糖: `brownsugar` `crystalsugar` `whitesugarsyrup` `concentratedsyrup`
  - 酸: `vinegar`
  - 辛香: `chillipowder` `drysichuanpepper` `chinesepicklyashpowder` `ginger`/`groundpowder` `garlic`/`garlicpowder` `cumin`/`cuminpowder` `onionpowder` `sesamepowder`
  - 复合底料: `curry` `spicy_hot_pot_base` `pepper_hot_pot_base`
  - 注: FD 源码确认几乎无调料, 唯一 `farmersdelight:tomato_sauce`。
- 调料→效果池映射(DECIDED 起步契约):

| 调料 | 偏向效果池 |
| --- | --- |
| 盐/酱油/椒盐 | 续航鲜味(耐饥/饱腹/增量/增香) |
| 糖/糖浆 | buff 强化(增香/回味、延长时长) |
| 油/黄油/奶油 | 战斗辅助(披甲/膳香, 高品质门控) |
| 醋 | 净化/解控(回甘/回神) |
| 辣椒/花椒 | 战斗/急迫(火爆向、椒麻) |
| 姜/蒜/孜然 | 驱寒保健/探索(温饱/夜照/抗负面) |
| 咖喱/火锅底料 | 高级复合(多效果、闪耀向) |

## 六、效果系统 (DECIDED 已定 8 个及扩展池)

全部效果在吃菜时(`LivingEntityUseItemEvent.Finish`)读 NBT 结算; 窗口/周期型需配套 tick/事件状态机(见第十一章)。

### 6.1 已定 8 个核心效果(用户定稿)

| 效果 | 低 | 中 | 高 | 超凡 | 闪耀 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 增香(原 buff 时长 ×) | 1.2 | 1.5 | 2 | 3 | 5 | **只乘时长不乘等级**; 黑名单排除金苹果/附魔金苹果 + FID 战斗向调味效果(见第九章), 否则破红线 |

| 回味(饱和 ×) | 1.5 | 2 | 3 | 4 | 5 | 饱和≤饱食自限 |
| 饱食(跳跃提升 60s) | I | II | III | IV | V | 纯 addEffect |
| 膳香(额外回血) | 20 | 40 | 60 | 80 | 200 | 战斗向, 高品质解锁; 建议改 %最大血量(闪耀=满血); 进食可打断兜底 |

锁定纳入效果池：耐饥、提神、饱腹、披甲、凝脂、镇火、余韵、稳膛、夹生、烧焦、倒胃、夜照、潜鳃、轻羽、流萤。沁脾不纳入；盛宴和回礼留作后续扩展，不进入本次结算池。

## 七、等级与经验 (DECIDED)

### 7.1 谁做谁得
每次在调味台完成一道菜, 经验记给操作小游戏的厨师 UUID; 买来/别人做的菜不产经验(堵代练, 仿工程师 producerUUID)。

### 7.2 单菜原始经验(按达成品质, 进 config)
低级 50 / 中级 80 / 高级 130 / 超凡 220 / 闪耀 400 原始经验 -> 奖励手艺。数值已按 7.4 推演标定(使"打满每日上限的菜数"落在合理区间); 原示例 10/20/40/80/160 在低级过肝(休闲档每天 220 道), 已废弃。

### 7.3 等级曲线 + 每日软上限(复用全职业, 已验证)
总需求 61,900(L1→2 3,300 … L9→10 12,200)。每日有效经验软上限衰减: 0-2000 ×1.00 / 2000-2800 ×0.40 / 2800-3400 ×0.20 / 3400-3800 ×0.08 / 3800+ ×0.02(软顶约 4,000/天)。

### 7.4 升级速度推演(已实算)
天数与全职业同框架——每日软上限是闸门, 单菜经验只决定"打满每日上限要做几道菜", 不抬高天花板:

| 画像 | 日投原始经验 | 满级天数 |
| --- | --- | --- |
| 休闲(打到舒适即下) | ~2,200 | ~29.8 |
| 正常(每天数小时) | ~4,000 | ~22.1 |
| 肝(大半天) | ~7,000 | ~18.2 |
| 肝满(全天) | ~12,000 | ~16.3(软底 ~15.5) |

每天需做的菜数(= 日投原始经验 / 单菜经验, 7.2 数值):

| 画像 | 低级 | 中级 | 高级 | 超凡 | 闪耀 |
| --- | --- | --- | --- | --- | --- |
| 休闲 | 44 | 28 | 17 | 10 | 6 |
| 肝满 | 240 | 150 | 93 | 55 | 30 |

节奏特征: 早期最肝、越往后越轻松——L1 只能做低级菜(单菜经验最低、要做最多道), 随升级 + 解锁高档台能做高品质菜, 用更少的菜打满每日上限(自然激励升级, 先苦后甜)。

### 7.5 反挂机
每道菜须主动打小游戏(不能 AFK), 比工程师还强(机器自动产不了); 配每日软上限, "囤一箱面包梭哈"不成立。

## 八、跨 mod 集成 (DECIDED, 源码已验证)

- **调料 = FID**(第五章真实 ID); **被调味的菜 = FD + FID + 原版 + 任意食物 mod**。
- 通用判定: `ItemStack.getFoodProperties(entity) != null` 即"可调味食物", 零 per-mod 代码。FD/FID 的菜全用标准 `FoodProperties`, 全覆盖。
- FD 成品菜库(源码 ModItems.java 确认): 约 60 道, 含简餐(汉堡/三明治/饺子/寿司卷)、汤炖(各种 stew/soup/炒饭)、拼盘(意面/烤羊排/牛排土豆)、盛宴(烤鸡/蜜汁火腿/牧羊人派)、甜点、饮品、肉片半成品。
- 注意点:
  1. FD 盛宴类是**可放置方块食物**(roast_chicken/honey_glazed_ham 等), 调味"切份"的边界实现期定。
  2. FD/FID 部分菜自带 buff -> 增香会放大; **增香黑名单必须含 FID 的战斗向调味效果**(糖浆装甲/火爆狂攻/椒麻麻痹/刺穿流血/酸蚀穿透等, FID 共 ~34 个状态效果)+ 原版金苹果。
- 软依赖纪律: 所有 FID/FD 物品引用经 config/tag + `ModList.isLoaded` 守卫, mod 缺失不崩。

## 九、架构落地 (DECIDED)

- `ChefModule implements Subsystem` 是唯一公开入口，内部持有 `ChefSystem` 运行时装配；`MiningDim.registerSubsystems()` 只登记 `ChefModule`。
- 等级数据并入 entry 的 `MiningPlayerData`(`EnumMap<JobId,JobProgress>`, 不新挂 capability)。
- 厨师自定义效果(余韵/披甲/凝脂/稳膛/耐饥… 的计时标记)注册进共享 `ModEffects`(供多职业复用)。
- 调味台 GUI + 小游戏 复用公共 menu 脚手架。
- 所有数值(品质倍率/效果数值/经验/调料映射/小游戏参数/增香黑名单)进 `MiningServerConfig` ForgeConfigSpec(或牌效式 datapack JSON), 硬编码即缺陷(C6)。

## 十、可实现性结论 (Forge 1.20.1, DECIDED)

| 模块 | 可实现性 | 关键 API | 工作量 |
| --- | --- | --- | --- |
| 品质 NBT + 显示 | 可实现 | setHoverName + ItemTooltipEvent(通用) | 小 |
| 吃时加成 | 可实现 | LivingEntityUseItemEvent.Finish 读 NBT | 中 |
| 调味台 5 档 + 小游戏 | 可实现但有坑 | 公共 menu + 服务端时序权威 + 客户端渲染 | 大 |
| 窗口/周期效果 | 可实现但有坑 | "eat-time 盖章 + PlayerTickEvent/Living*Event 状态机", 非一次性 | 中 |
| 战斗向效果 | 可实现 | heal(%maxHP)/setAbsorptionAmount/LivingHurtEvent(爆炸 Tag) | 中 |
| 等级/经验 | 可实现 | 并入 EnumMap + 每日衰减 | 小 |

实现期红线:
- "全是 eat-time"只对纯加 buff/瞬时的成立; 窗口/周期/衰减型(耐饥/披甲/凝脂/稳膛/余韵/轻羽…)需配套 tick/事件状态机(共享基础设施, 要预算)。
- **稳膛(抗击退)严禁用 AttributeModifier**(撞泄漏红线), 用 `LivingKnockBackEvent`。
- 增香乘时长 + 黑名单(金苹果 + FID 战斗效果)。
- 战斗向回血/护盾 %最大血量、进食可打断、一菜一战斗效果。

## 十三、实现期工作分解 (DECIDED)
