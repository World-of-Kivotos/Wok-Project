# 特勤干员 职业设计规格（SpecialAgent Job）

> 状态标记：DECIDED = 已拍板；PENDING = 待定。
> 2026-09-30 补完：悬赏系统的四项前提已拍板并上线（10.5、第十二章），接取悬赏成为入职点（7.0），封印恢复快照改为随精英 capability 持久化（10.2），战术扫描补齐第四章探测列的分级字段与首次发现经验（第五章、8.1）。
> 平台：Forge 1.20.1 / Forge 47.x / Java 17。modid：`miningdim`。
> 前置真源：[JobFramework_Shared_Foundation_DesignSpec.md](JobFramework_Shared_Foundation_DesignSpec.md)（统一进度/升级/经济/menu 地基）、[ChampionStarAffix_System_DesignSpec.md](ChampionStarAffix_System_DesignSpec.md)（精英怪星级词条体系，本职业深度联动）、[服务器经济系统设计文档.md](服务器经济系统设计文档.md)（信用点/青辉石/盖章/产出闸）。
> 设计哲学：与本项目所有职业一致，走 FF14 生产职业路线——**主打经济产出，战斗仅少量加成**，不做战力核心。

## 一、概述与定位（DECIDED）

特勤干员是一个**服务于 PVE 的经济/情报职业**：玩家通过**寻找精英怪 → 扫描情报 → 参与击杀 → 完成悬赏**赚取信用点（周常额外少量青辉石）。它不是战术 buff 位、也不是 DPS 位，而是"把恶心的精英变得可打、并靠找得多/看得透/打得准来赚钱"的个人经济职。

三大特色能力：

- **探测（战术扫描）**：渐进式情报扫描，等级越高把精英看得越透——核心经济引擎。
- **封印**：临时压制精英的少量词条，让自己这一仗打得动；绝不永久削废。
- **悬赏 + 击杀经济**：每日/周常悬赏 + 击杀精英的贡献分赃 + 加强奖励。

职业等级 1-10，与精英星级同尺度（L 级 ≈ 能应对 N★），便于门控对齐。

---

## 二、与精英怪体系的联动（核心闭环，DECIDED）

精英怪体系负责"出题"（精英带恶心词条），特勤干员负责"解题"（找到、看清、临时去爪牙）。这是本职业的存在价值：带一个高级干员打世界 BOSS，能短暂封掉它的命定之死/小男孩，团队压力骤降。

闭环：**探测找到目标 → 扫描看清词条/威胁 → 1 个封印槽花在刀刃上开窗口 → 趁窗口打出贡献 → 按贡献从固定池分钱 + 完成悬赏**。

## 三、奖励模型：贡献池分赃（DECIDED）

为同时消除**抢怪、蹭枪、叠叠乐**三个问题，精英奖励一律走"固定池 + 伤害贡献占比瓜分"：

1. **固定奖励总池**：每只精英一个池，大小由它**出生盖章的初始星级**决定（即使被封印削弱也不变——封印不影响"值多少钱"）。
2. **按合格贡献者的伤害占比瓜分**（占比加权，非领奖台排名）：`份额 = 池 × 个人伤害 / 合格总伤害`。占比制让合作严格更优、无 denial 动机；可附最高贡献者一个小幅 top bonus（量级 PENDING）。**严禁按人头复制**。
3. **入池门槛（防蹭枪，盖章双门槛、取一即合格）**：个人贡献 ≥ 该精英总有效血的 **0.5%** **或** ≥ 团队人均有效伤害的 **15%**，满足其一即进分配（`ContributionPool.STAMP_THRESHOLD_BOSS_HP_RATIO` / `STAMP_THRESHOLD_TEAM_AVG_RATIO`，与 ChampionStarAffix 第十一章、Champion_Effects_Guide 2.6 同口径）。正规多人团队每人份额远超两道门槛，单发蹭伤两道都进不去；但人少、团队总伤害低的场景下第二道门会被拉低，届时未达 0.5% 的玩家也可能入池。
4. **掉线作废回池**：死亡结算时不在线的贡献者，其份额作废、回池重分给在场合格者。
5. **封印不计贡献**（纯伤害论）：封印不是伤害，封了也得自己打才分得到钱——防"封一下就躺分"的恶意蹭怪。

伤害账本挂在精英体系的**单一受击拦截点**（见 ChampionStarAffix 9.2 净减伤单点）：每次受击按攻击者累计"有效伤害"，死亡时读账本结算。记账口径按星级分两支（`ChampionRewardHandler` 在 LOWEST 读 `event.getAmount()`）：

- **1-5★（无自定义血池）**：`ChampionBloodPoolHandler` 把净减伤后的值 `setAmount` 回写 event，账本记的就是经 9.2 净减伤单点算出的净伤。
- **6★+（有血池）**：血池 handler 只 `pool.applyDamage(净伤) + setCanceled(true)`，**不回写 event**，故账本读到的是净减伤**前**的名义入伤（玩家实际打出的有效输出口径）。这是刻意与血池扣血口径分离的（代码原话："贡献是输出统计，不是扣血量"），目的是不让高减伤精英压低玩家的贡献占比。

## 五、探测支线：战术扫描面板（DECIDED）

唯一情报载体是**一个面板**（不走聊天栏，避免高级后信息太多 UI 堆叠）。每次扫描脉冲按等级把这只精英的数据"逐格解密"，未解锁字段显示"加密/未解析"。

- **只给原始数据，不给弱点结论**：面板呈现词条/品质/数值，"怕火/怕狙"由玩家自己研究。
- **词条品质显示**：每条词条带品质色标（普通灰白/中级绿/高级蓝/超凡紫/闪耀金，见 ChampionStarAffix 9A.7）。
- **范围**作为副线随级涨（64 格 → 跨区块），主线是"看得多透"。
- **悬赏雷达**（L6）：面板顶部标注是否当前悬赏目标。
- **实时透视**（L9+）：当前血量/护盾/寒霜层数/技能 CD 实时刷新；L10 全属性实时。
- **Glowing 高亮**（L8）：穿墙可见，只有扫描者本人看得到（见下方实现）。

形式：主动脉冲带长 CD（60s → 30s 随级缩），防全图刷新。

### 5.1 实现口径（2026-09-30）

每个扫描目标在 `job.agent.scan` 与 `job.agent.state` 里同形；解锁等级取**发出脉冲那一刻**的干员等级，未解锁的格一律发显式 JSON `null`（键在、值为 null——减伤率、单击补足的真值本来就可能是 0，把 null 画成 0 就是对玩家撒谎）。`job.agent.state` 另发 `scanFieldUnlockLevels`（逐格照抄 `AgentScanField`），面板的"需要 Lv.N"占位不在前端另抄一份等级。

| 字段 | 内容 | 解锁 |
|---|---|---|
| `star`、词条行 | 星级；按等级逐条解密的词条（L1 一条 → L5 全部） | L1 起 |
| `effectiveHp` | 总有效血（6★+ 为血池上限） | L3 |
| `armor` / `damageReductionPct` | 原版护甲属性 / 复合装甲满层与缩小化经 75% 封顶合成的减伤率 | L4 |
| `bulletResistancePct` | 超高分子 + 重甲 + 偏导闪避期望合成的子弹抗性（未封顶，封顶作用在与减伤率的乘积上） | L5 |
| `attackDamage` / `singleHitPct` / `movementSpeed` | 原版攻击属性 / 与精英近战同一钳制函数的单击补足比例 / 当前移速 | L6 |
| `bountyTarget` | 悬赏雷达：打死它能否推进你已接未完成的悬赏（L8+ 已入职时世界 BOSS 也算），对照的是你**现在**的悬赏板 | L6 |
| `mechanics` | 已解密机制词条的时序：蓄力/预兆（`chargeSeconds`）、每人打断阈值（`interruptDamagePerPlayer`）、冷却（`cooldownSeconds`） | L7 |
| 词条行 `quality` | 品质（COMMON…LEGENDARY，面板按 9A.7 色标） | L8 |
| `pos` + 高亮 | 脉冲当刻坐标；逐玩家发光 | L8 |
| `live` | 实时：当前血 / 上限 / 吸收量 / 该精英叠在你身上的寒霜与燃烧层数；L10 再加全属性 | L9 / L10 |

- **没有数据来源、不臆造的子项**：技能实时 CD（各技能的冷却进度是精英 handler 的私有状态，要暴露得先改精英侧）；复合装甲叠层、撕裂层数（同为私有状态）；护盾（精英没有护盾池，用原版吸收量代替）；打断阈值只有小男孩有定值（每人 120），自我修复任意近战即打断、命定之死的阈值随玩家 DPS 算，都不给数；瞬发技能不给蓄力时间；小男孩一次性不给 CD。`chargeSeconds` 口径略宽：天雷 / 凯撒互换 / 刀锋华尔兹是预兆时长，自我修复是 6 秒引导，命定之死是 8 秒标记倒计时。刚毅的单击上限与重甲对近战/爆炸的免疫阈值不在百分比字段里，可由词条 + L8 品质推出。
- **6★+ 的 `armor` 对扣血无效**：血池精英的伤害在原版护甲结算前就被取消，数值照实发，面板不据此下结论。
- **逐玩家高亮**（`AgentScanGlow`）：服务端实体不动，只给扫描者单独发一个带发光位的实体数据包，别人看不到。原版重新同步标志位时（每 tick 核对真实标志字节）、扫描者重新开始追踪目标时都会补发，另外每秒兜底重申一次；快照到期或重扫时发真实标志字节熄灭。为此在 access transformer 里开了 `Entity.DATA_SHARED_FLAGS_ID`，没加 mixin。高亮只在客户端追踪得到的实体上显示，距离比 384 格扫描半径短。
- **实时透视**：L9+ 脉冲的目标，每次 `job.agent.state` 在读者当前维度按网络 id 回查，并核对 UUID 与脉冲当刻一致（网络 id 会被复用）、仍存活，才重读；否则报 `tracked:false`。不会新增目标、不重读坐标。面板只在这种快照有效期内每 2 秒轮询一次。

## 六、封印支线（DECIDED）

干员唯一的战斗向工具，且高度克制——只为"让你这一仗打得动"，不为"把 Boss 变废"。

- **临时**：有时长 + CD（被动 8s→12s、机制 3s→5s；CD 见总表），时间一到词条恢复。
- **少量**：同时 1 槽（L9 起 2 槽，仅高星用得上）。
- **每精英 1 槽（8★+ 为 2），先到先得**：多干员压一只也加不上更多封印 → 防叠叠乐。
- **类型/星级门控**：被动词条 L3 起可封；机制/核心类（命定之死/小男孩/天雷等）**仅 L8+ 可短暂封印、绝不永久移除**；可封星级随级抬到 10★。
- **封印只压"词条效果"，不动"基础膨胀"**：精英的基础血量/移速等基础数值封不掉——你只开窗口，不削废。
- **交互**：在扫描面板内**点击已解密的词条**即封印（探测与封印合一）。未解密的词条点不了——天然耦合"扫得透才封得到"。点击后该行变灰 + 恢复倒计时，封印进 CD。校验失败给原因提示（需更高等级 / 槽已占 / CD 中）。

## 七、加强奖励 / 日常周常权限 / 伤害加成（DECIDED）

### 7.0 入职标志（activeAgent）门

加强奖励（7.1）与对精英伤害放大（7.3）这两笔**特勤专属福利**，只对 `AgentBountySavedData.isActiveAgent` 标记为"做过特勤活计"的玩家生效。

- **为什么要这道门**：职业框架的 `IJobService.level` 对任何玩家（含从没碰过特勤的人）都恒返 1 级默认值，用等级作门等于把额外信用点和伤害放大泄漏给全服每个打死精英的人（`AgentDamageBonusHandler` / `AgentRewardHandler` 注释原文）。
- **两个置位入口**（2026-09-30 拍板）：接取悬赏成功（`AgentBountyService.accept`，L1 起可接日常）与封印申请成功（`AgentSealHandler`）。标志一经置位永久保留。L1/L2 干员接一张日常即可入职，第四章那两列从 L1 起可达。
- **扫描刻意不置位**：扫描对全员开放、职业等级对任何人默认 1 级，在扫描里置位等于"站在精英旁边点一次按钮"就吃福利，正是这道门要防的事。接取悬赏是玩家主动选择做特勤活计的动作，而且悬赏只推进已接的那几张，不会替没接的人记进度。
- **经验刻意不受此门约束**（`AgentRewardHandler.grantAgentKillXp`，F016 死锁修复）：经验是玩家升到 L3、进而封印、进而入职的唯一通路，共用这道门会形成"没入职→没经验→升不了级→封不了→进不了职"的死锁。经验不产货币且走职业框架经验软上限，与两笔真福利性质不同。

### 7.1 加强奖励（额外击杀信用点）
- **击杀精英怪本身额外给你个人信用点**——与悬赏奖励无关、**不含青辉石**。
- 数值：`额外信用点 = f(初始星级) × 加强奖励系数（×1.0 → ×3.0）`，绝对底值随星级、留经济 config。
- **从池外给的个人 faucet**：不挤占他人贡献占比；**受经济每日衰减主闸约束**（防印钞），经 `grantDaily` 并入 `EconomyConstants.GLOBAL_DAILY_CREDIT_FAUCET_KEY`（`credit_faucet`）/ `GLOBAL_DAILY_CREDIT_FAUCET_TIER`（60,000 CP 一档，跨档系数 0.6、1% 地板），与矿工卖矿/农夫卖菜共享同一每人每日天花板（`AgentRewardHandler.grantAgentKillBonus`）。注意 `economy.daily.*` 是钻石/下界残骸/金的逐矿种软上限，与本机制无关；AbuseGuard 里也没有 mob-kill faucet 这个东西。

### 7.2 日常周常权限
- 悬赏槽位：日 1→5、周 0→3（周常 L4 解锁）。槽位 = 本期能接几张，做完不退。
- 可接悬赏星级随级抬到 ≤L★；日常/周常实际目标最高 9★（困难矿区自然刷出上限，10★ 只出自世界 BOSS）。L8 起开放世界 BOSS 讨伐令（不占槽位，见 10.5）。
- **悬赏青辉石**来自周常悬赏（≥L4）与世界 BOSS 讨伐令（≥L8），产出经双轴门控：每玩家每周悬赏青辉石软上限 50（`AgentBountySavedData.WEEKLY_AZURE_SOFT_CAP`，撞顶只发剩余额度；精英掉落不计入）+ **与精英怪 6★+ 掉落共享**的每人每日硬上限 30（`EconomyConstants.AZURE_DAILY_FAUCET_CAP`，经同一 `azure_faucet` 键的 `grantAzureDaily` 硬截断）。日上限截掉的部分记为待补发（`BountyBoard.pendingAzure`），登录或下次完成悬赏时自动补，不吞玩家已经挣到的量。青辉石来源口径见十一章（2026-09-30 拍板双源并存）。

### 7.3 伤害加成
- 仅对**精英/冠军怪** +5% → +15%（L1-L9 每级 +1%，L10 多跳 1 个百分点到 +15%；`AgentSkillTable.DAMAGE_BONUS_PERCENT`）。纯帮干员够到入池门槛，**不做战力核心**（FF14 哲学）。受 7.0 入职标志门约束。

## 八、升级线（DECIDED）

### 8.1 XP 来源（贴合"找→扫→杀→悬赏"循环）

| 来源 | XP（示例·可调） | 说明 |
|---|---|---|
| 首次扫描发现精英 | 星级 × 8（1★=8 … 10★=80） | 每只仅首次，奖励"找"，防重复扫刷。**已实现**（`AgentDiscoveryXp`，见下方说明） |

**XP 来源的实现状态（2026-09-30 全部生效）**：四条来源都经 `AgentLevels.grantRawXp` 入账、走职业经验软上限，且都**不受**入职标志门约束（F016 死锁理由见 7.0）。
- 击杀：`AgentRewardHandler.grantAgentKillXp`，星级 × 60 × 贡献占比。

## 十、架构与实现（DECIDED）

### 10.1 探测/扫描
- 目标识别走自研冠军 capability（`MiningChampions.get(target)` → `MiningChampionData.isChampion()`，见 `AgentScanProbe`）：非本工程盖章的精英直接不扫。
- 扫描脉冲：按干员等级把该精英的 星级/词条/品质/血池/属性/技能时序**分级推送**到干员面板；数值由集成层 `AgentScanStatsReader` 从精英 capability 与实体属性读出，分级解密、字段锁定与可封门裁决落在纯逻辑 `AgentScanSnapshotBuilder`（GameTest 可断言）。字段表见 5.1。
- 高亮不用原版 `Glowing` 药水效果（那会让所有玩家都看到），而是逐玩家发实体数据包（`AgentScanGlow`，见 5.1）。

### 10.2 封印
- 封印 = 服务端权威调 `MiningChampionData.removeAffix`，把被封的那几条**直接从自研 capability 摘掉**（不写 sealed 标记、不逐钩子判 sealed——词条数据已被摘空，各 handler 自然读不到，效果即时失效）。
- 到期按**增量快照**（只记本次封印摘掉的那几条）合并回当前词条表，**刻意不做整份词条集覆盖**：窗口内小男孩（`LITTLE_BOY`）起手时会自摘这条一次性词条，整份还原会把它重新装回去，变成可重复触发的漏洞。
- **增量快照随精英持久化**（2026-09-30 修复）：被摘词条与原品质登记在精英 capability 上（`MiningChampionData.recordSealedAffix`，NBT 键 `sealed_affixes`，只在有封印时写出），随实体存盘（此前只记在进程内存里）。恢复有三条路径，谁先到谁恢复，登记取走即清（`takeSealedAffixes`），后到者空转：
  - 在线到期：服务端 tick 扫描（原路径）；
  - 区块卸载后重新载入 / 重启后载入：`EntityJoinLevelEvent`（Forge 47.3 先反序列化 capability 再发该事件）。重启后内存封印账本已空，载入即恢复——只可能让封印提前结束，不会变成永久；封印窗口仍未到期时则重新登记追踪、到期再恢复；
  - 区块仍加载但实体不在追踪表里（视距外）：`LivingTickEvent` 每秒对账一次，已追踪的跳过。
- 恢复只动词条表：星级、有效血、当前血量、世界 BOSS 标记、`summonedByAffix` 身份一律不动。`AgentSealExecutor` 的内存表只剩追踪索引（维度 + 保留期），不再持有词条。
- 对**挂了常驻 MOVEMENT_SPEED AttributeModifier 的词条**——高速移动 / 超速移动 / 自我修复单元三条——`removeAffix` 只清 capability、摘不掉实体身上那条修饰，故封印时还须额外摘除，否则封印只是观感（面板回 OK 但精英移速一格没变）。因这三个修饰的固定 UUID 是 `champion.integration` 包私有常量、`job.agent` 侧跨包引用不到，当前按 modifier 的公开 name 字符串匹配摘除（`champion_sprint` / `champion_overdrive` / `champion_self_repair_root`）。这是字符串耦合而非类型安全引用，对侧改字面量会静默失效且无编译期告警，彻底修法是把这三个 UUID 提到双方都能引用的公共位置。解封无需对称补挂：词条一回到 capability，对应 handler 每秒扫描时会自动重挂修饰。
- 超高分子的子弹抗性**不是**常驻 AttributeModifier（它是受击时按比例折算的减伤率，见 ChampionStarAffix 9.6），不涉及本机制。
- 计时到期恢复；面板/名牌刷新走既有扫描推送与网络同步通道（全仓无 `IAffixSyncable` 这一接口）。

### 10.3 贡献账本与分赃
- 账本挂 ChampionStarAffix 9.2 的**单一受击拦截点**：`playerUUID → 累计有效伤害`（口径按星级分两支，见第三章）。枪伤、近战、DoT 统一走 `LivingHurtEvent` 这一个入口，攻击者用 `event.getSource().getEntity() instanceof ServerPlayer` 判定；子弹另按伤害类型 id `tacz:bullet*` 识别以计减伤。**全程不监听 TACZ 的 `EntityHurtByGunEvent`**（该事件全库只被工程师板甲耐久用），也**暂无**按伤害源 owner 归因的代码（召唤物/弹射物归因待细化，见 `ChampionRewardHandler.resolvePlayerAttacker`）。
- `onDeath`/`LivingDeathEvent` 读账本 → 入池门槛过滤 → 占比瓜分 → 掉线作废回池 → `IEconomyService.grant`。
- 加强奖励在结算时对达门槛的干员额外发个人信用点（受日软上限）。

### 10.4 面板 UI（走 WebUI，非原生 Screen）
- 面板走 WebUI（MCEF 渲染远端 React）：服务端在 `AgentWebUiActions.registerAll` 注册 `job.agent.state` / `job.agent.scan` / `job.agent.seal` 三条 WebUiAction，外加悬赏接取 `job.agent.bounty.accept`（`AgentBountyWebUi`）。分级解密、封印九态裁决、悬赏槽位与翻期一律服务端权威（`AgentSealSeam.buildScanSnapshot` / `requestSealResult` / `BountyBoard`），客户端只渲染；点击词条 → `job.agent.seal`，点击接取 → `job.agent.bounty.accept`。
- 原 `AgentScanMenu` / 原生 Screen 那条路径**已整条删除**（决策 J9：统一 UI 入口走平板 hub，不为特勤单开 ad-hoc 原生入口），`com.miningdim.menu` 包内已无任何 Agent 相关项。**故本节不再走 JobFramework 公共 menu 脚手架**，12.0 表格"载体"一行同此口径。

### 10.5 悬赏（DECIDED 2026-09-30，已实现）

每日/周常悬赏 = 每个玩家一块个人悬赏板；完成判定走击杀盖章 + 入池门槛；UTC 翻日 + ISO 周重置；载体是特勤面板（WebUI）。代码在 `job.agent` 包：`BountyDefinition`（一张悬赏）、`BountyGenerator`（掷取）、`BountyRewardTable` / `AgentBountyConfig`（奖励数值）、`BountyBoard`（悬赏板）、`AgentBountyService`（接取/推进/发奖）、`AgentBountyWebUi`（面板投影与接取 action）。

**10.5.1 三种目标**

| 目标 | 周期 | 说明 |
|---|---|---|
| 讨伐 N 只 ≥X★ 精英 | 日常 / 周常 | 星级类 |
| 讨伐 N 只 ≥X★、带某池词条的精英 | 日常 / 周常 | 词条类。类别直接用精英体系的四池（生存 / 战斗 / 机动 / 技能，`AffixPool`） |
| 世界 BOSS 讨伐令 | 常驻（EVENT） | L8+ 已入职干员参与击倒世界 BOSS 且达入池门槛即结算；不占槽位、不用接取 |

世界 BOSS 只由管理员指令 `/mchampion worldboss` 召唤、出现时间不定，放进周常槽会出现"整周没刷 BOSS、槽位白占"的死单，所以做成不占槽的常驻讨伐令。代码强制 EVENT 周期与世界 BOSS 目标成对。

**10.5.2 目标星级与讨伐只数**

- 目标星级 X 的上限 = min(可接星级 L, 9)。10★ 只出自世界 BOSS，不进日常/周常。下限：日常 = 上限 − 3，周常 = 上限 − 2（都不低于 1），同一块板上有轻有重可挑，周常整体偏难。
- 讨伐只数 N 按 X 配表，使一张悬赏的工作量大致随奖励同涨；6★ 起按约 4 人小队设计，日常在这一档只要一只：

| X | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 日常（星级类） | 4 | 3 | 3 | 2 | 2 | 1 | 1 | 1 | 1 |
| 周常（星级类） | 15 | 12 | 10 | 8 | 6 | 4 | 3 | 2 | 2 |

- 词条类只数：日常 = 同星星级类 − 1、周常 = 同星星级类减半向上取整，都至少 1。少掉的那部分是"先找到目标"的成本——扫描面板正是干这个的。
- **词条类只掷出现率达标的组合**：精英词条逐池贪心掷取（生存 → 战斗 → 机动 → 技能），低星总词条上限很小，排在后面的池经常一条也分不到，写死"技能池 3★ 起"之类的门会掷出几乎完成不了的单。`BountyGenerator` 启动时用精英自己的 `AffixRoller` 按固定种子每星模拟 400 次，得出每星每池的出现率，只掷出现率 ≥ 35% 的（池, 星级）组合；精英那边改预算或掷法，这张表自动跟着变。
- 掷取时 40% 尝试掷成词条类（没有达标的池就退回星级类），同一块板上尽量不重复。

**10.5.3 奖励（12.1 第 2 条拍板"保守"档）**

| | 信用点 | 干员经验 | 青辉石 |
|---|---|---|---|
| 日常（每张） | 2,000 ~ 6,000 | 400 ~ 1,500 | 0 |
| 周常（每张） | 15,000 ~ 30,000 | 2,500 ~ 6,000 | 8 ~ 15 |
| 世界 BOSS 讨伐令（每次） | 30,000 | 6,000 | 15 |

- 区间两端对应目标星级 X = 1 与 X = 9，中间线性插值（信用点按百取整、经验按十取整、青辉石四舍五入）。奖励只随"目标有多难打"走，讨伐只数已按星级配平。
- 绝对量全部在 `miningdim-agent.toml` 的 `[bounty]` 段（`enabled`、`dailyCreditMin/Max`、`dailyXpMin/Max`、`weeklyCreditMin/Max`、`weeklyXpMin/Max`、`weeklyAzureMin/Max`、`worldBossCredit/Xp/Azure`），默认值即上表；`enabled = false` 可整体关闭悬赏（已发的奖励不受影响）。槽位、星级门、讨伐只数属于第四章结构，不开配置。
- 完成那一刻自动发奖，没有领取按钮（领取按钮带来的只有"忘了领就翻期作废"和领取时机套利）。信用点经 `grantDaily` 并入全服 `credit_faucet` 主闸（与卖矿、加强奖励共享衰减，**不**援引任务模块的独立键例外）；经验经 `AgentLevels.grantRawXp` 走职业经验软上限；青辉石见 7.2。

**10.5.4 悬赏板**

- 可接张数 = 当前槽位 + 余量（日常 +2、周常 +1），玩家从中挑，接满槽位即止。槽位按**接取那一刻**的等级查表：当天升级当天就能多接。
- 翻期：日戳变了清空本日悬赏重掷，ISO 周戳变了清空本周悬赏重掷。周期内升级只**补掷**到应有张数，已有悬赏原样保留，否则升一级就能把整块板换一遍，等于免费重摇。
- 接取后**不能放弃、不能重摇**：悬赏是"周期性但不可重摇"的来源，放弃再接会把槽位变成反复刷好单的抽奖机。
- 未接取的悬赏不计进度；一次击杀可同时推进多张已接悬赏（日常与周常互不排斥）。
- 词条类按精英**本来**带的词条判：击杀瞬间仍挂着的 + 正被封印摘走的（10.2 的登记）。否则干员正确使用封印反而让自己的悬赏不算数。
- 只有打开过特勤面板的玩家才有悬赏板；击杀结算只推进已有板上已接的悬赏，不为路人建板。
- 悬赏板存 `AgentBountySavedData`（overworld SavedData `miningdim_agent_bounty`），键 `boards`；某张悬赏读不回来（枚举改名等）只丢那一张，不拖垮整份存档。

**10.5.5 接取结果码**（`job.agent.bounty.accept`，入参 `{period: "DAILY"|"WEEKLY", bountyId}`；业务拒绝走结果码，只有入参非法才抛 `INVALID_REQUEST`）

`OK` / `DISABLED`（运营关闭）/ `NOT_FOUND`（跨日跨周后的旧 id）/ `ALREADY_ACCEPTED` / `LOCKED`（周常未解锁）/ `NO_SLOT` / `STAR_TOO_HIGH`（等级被管理员调低）。回执带整段最新悬赏板与 `newlyActiveAgent`（本次接取是否让玩家首次入职）。

**10.5.6 与后续平衡分支的衔接**

暂缓的平衡分支（`feat/balance-champion-rewards`，方案 D8）给加强奖励加了"特勤占比门槛"，并注明悬赏 qualifiedKill 与它同一道门。本实现基于上线基线，qualifiedKill = 进入贡献池分配（在线 + 盖章双门槛）；D8 合入时把 `AgentRewardHandler` 里传给悬赏的合格集换成过了 `ContributionPool.meetsAgentShareThreshold` 的那部分即可。
