# 铸甲师护甲机制设计规格

## 文档元信息

- 用途：记录“千年工程师”玩家可见名称调整为“铸甲师”后的护甲系统长期设计，并作为插板护甲第一阶段的实现依据。
- 目标平台：Minecraft 1.20.1、Forge 47.x、Java 17、TaCZ 1.1.8。
- 关联文档：[千年工程师职业设计](MillenniumEngineer_Mod_DesignSpec.md)、[冠军星级词条系统设计](ChampionStarAffix_System_DesignSpec.md)、[枪匠组件平衡路线](Gunsmith_Component_Balance_Roadmap.md)。
- 实现状态：本文档已建立，护甲代码尚未开始实现。
- 状态图例：`DECIDED` 已由用户确认；`VERIFIED` 已由当前代码、依赖或既有文档核对；`PROPOSED` 当前推荐方案；`PENDING` 实现前仍需拍板；`DEFERRED` 后续阶段再实现。

### 文档权威边界

1. 本文档负责铸甲师的护甲类型、受击公式、枪匠联动和护甲实现阶段划分。
2. `MillenniumEngineer_Mod_DesignSpec.md` 继续负责既有纳米修复、生产台、职业等级和一次性维修特效。
3. 两份文档发生护甲机制冲突时，以本文档为准；发生既有生产与修复经济冲突时，以千年工程师职业设计为准，直至另行完成整合评审。
4. “铸甲师”目前只调整玩家可见名称。第一阶段保留 `JobId.ENGINEER`、`engineer` 存档键、已有注册 ID 和配置文件名，避免旧玩家职业数据失效。

## 一、职业与护甲系统定位

### 1.1 职业名称（DECIDED）

- 玩家可见职业名：铸甲师。
- 既有纳米修复和生产能力继续属于该职业，不因改名删除。
- 新增的护甲设计、制造、维护和状态管理成为铸甲师最重要的子系统。

### 1.2 护甲设计目标

用户确认的目标（DECIDED）：

1. 不把所有护甲做成数值不同的百分比减伤。
2. 每个护甲家族必须使用不同的防护资源，并存在能够被玩家理解的武器反制方式。
3. 护甲体系与已完成枪匠系统共同校准，而不是各自独立平衡。

技术事实与实现目标：

1. `VERIFIED`：TaCZ 将一次弹丸的伤害拆分为普通弹道段和穿甲段。
2. `PROPOSED`：插板只处理 TaCZ 已形成的最终普通弹道受击段，不直接读取枪匠 NBT，也不重复计算枪匠系数。
3. `VERIFIED`：服务器玩家基准生命为 80 HP，并处于高 DPS 枪械环境，不能套用原版 20 HP 经验。
4. `PROPOSED`：客户端显示、物品提示和服务端实际结算使用同一组配置值。

### 1.3 已确认的护甲家族

| 护甲家族 | 核心资源 | 候选反制轴（PROPOSED） | 方向状态 |
|---|---|---|---|
| 轻型插板护甲 | 较低连续防护，换取机动收益 | 穿甲率 | 第一阶段，DECIDED |
| 中型插板护甲 | 中等连续防护，无机动修正 | 穿甲率 | 第一阶段，DECIDED |
| 重型插板护甲 | 较高连续防护，承担机动惩罚 | 穿甲率 | 第一阶段，DECIDED |
| 电浆护盾 | 可恢复的能量容量池 | 最终单发伤害、爆头和持续输出 | 方向 DECIDED，实现 DEFERRED |
| 纳米陶瓷板护甲 | 有限次完整拦截 | 射击次数与高射速 | 方向 DECIDED，实现 DEFERRED |
| 弹力护甲 | 将部分伤害转入数秒内结算的创伤池 | 持续火力与创伤累积 | 方向 DECIDED，实现 DEFERRED |

本轮不增加其他护甲家族。烧蚀涂层、动力外骨骼或定向防护等构想不进入当前范围，未来另行评审。

## 二、第一阶段范围：插板护甲系列

### 2.1 本阶段包含

用户确认的范围（DECIDED）：

1. 轻型、中型、重型三类插板护甲。
2. 三类插板的机动差异。
3. 与已完成枪匠系统的最终伤害、爆头和穿甲数据联动。

交付要求（PROPOSED）：

1. 按第三章候选公式区分 TaCZ 直接弹道伤害的普通段与穿甲段。
2. 必要的物品提示、服务端配置与状态同步。
3. 纯公式与状态自动测试，以及固定 TaCZ 测试实例中的实弹集成测试。

### 2.2 本阶段不包含（DECIDED）

- 电浆容量、破盾和充能。
- 纳米陶瓷完整拦截次数。
- 弹力护甲创伤池。
- 稀有护甲模块与随机词条。
- 枪匠射速组件、穿甲组件或其他枪匠扩展。
- 对冠军系统、酿酒师、厨师或其他职业进行顺手重构。

如果插板实现必须修改共享伤害管线，应先单独评审影响范围；不得把相邻模块改动夹带进插板护甲实现分支。

## 三、术语与基础伤害模型

### 3.1 术语

| 符号 | 含义 |
|---|---|
| `H` | 用于文档推导的本次弹丸概念总伤害，已包含源枪数据、距离曲线、启用时的枪匠伤害系数和爆头倍率；不存在一个直接提供完整 `H` 的 `LivingHurtEvent` |
| `p` | TaCZ 对本次弹丸解析并限制到 `0.0-1.0` 的 `armorIgnore`；插板实现不需要重新读取该值 |
| `M` | 肉伤，即不穿甲的弹道伤害部分 |
| `P` | 穿甲伤害部分 |
| `R` | 当前插板对肉伤部分的防护率 |
| `D` | 用于文档比较的两段伤害在插板处理后的名义总和，不是单个事件值，也不是最终扣血 |

本项目内“肉伤”是方便讨论的简称，正式含义为“非穿甲弹道伤害部分”，不是新的 Minecraft 伤害类型。

### 3.2 TaCZ 伤害拆分（已核对实现）

```text
M = H × (1 - p)
P = H × p
```

TaCZ 会将同一颗弹丸拆成普通弹道伤害和无视护甲的穿甲伤害两次调用。`LivingHurtEvent` 实际收到的是已经包含爆头结果的 `M` 或 `P`，不是完整的 `H`。

第一阶段插板不应重新配对两次事件，也不应重算 `H` 或 `p`。推荐直接对普通弹道段执行：

```text
normalSegmentAfter = normalSegmentBefore × (1 - R)
```

铸甲师插板处理器不修改穿甲段。该伤害类型会绕过原版护甲值与韧性，但仍可能继续受到保护附魔、抗性、外部防弹属性和职业减伤等其他下游来源影响。不得将两段重新合并并制造第三次伤害。

### 3.3 插板概念公式（PROPOSED）

```text
D = P + M × (1 - R)
```

展开后为：

```text
D = H × p + H × (1 - p) × (1 - R)
```

这条公式用于平衡推导和界面说明，并不要求代码在运行时重建完整 `H`。它保证：

- `p = 0` 时，全部弹道伤害受到插板防护。
- `p = 1` 时，插板完全不起作用。
- 提高插板防护档位只增强肉伤防护，不会偷偷削弱穿甲价值。
- 枪匠提高伤害或爆头后直接提高 `H`，不会绕过或重复进入护甲公式。

插板是否覆盖爆头的普通弹道段仍为 `PENDING`；在该规则确认前，第三章公式只描述“符合插板保护条件的命中”。

### 3.4 不允许的结算方式

1. `VERIFIED`：不使用 TaCZ 通用 `bullet_resistance` 作为插板主防护，因为该属性会同时降低普通弹与穿甲弹。
2. `PROPOSED`：不允许插板百分比、原版护甲值、护甲韧性和另一套职业减伤在未知顺序下全部相乘。
3. `PROPOSED`：不在铸甲师代码中读取 `MiningDimGunsmith` NBT 重新计算伤害、爆头或射程。
4. `VERIFIED`：不以两次 `LivingHurtEvent` 的出现次数代表两颗子弹；TaCZ 的肉伤段和穿甲段仍属于同一弹丸。

## 四、轻型、中型与重型插板

### 4.1 三类共同规则（PROPOSED）

1. 三类插板共用第三章的伤害公式。
2. 第一阶段已知差异包括肉伤防护率与机动修正；耐久、维修和装备成本差异仍待确认。
3. 同一玩家在同一时刻只生效一种插板类型，不能把轻、中、重三档逐件线性叠加。
4. 在铸甲师插板处理器边界内，穿甲段不受插板档位影响。
5. 插板未装备或未生效时不得残留隐藏的自定义减伤；若后续采用耐久机制，损坏状态也适用本条。

### 4.2 类型定位（防护与机动方向 DECIDED，玩法定位 PROPOSED）

| 类型 | 防护关系 | 机动关系 | 候选玩法定位 |
|---|---|---|---|
| 轻型插板 | `R_light < R_medium` | 提供正向机动修正 | 游击、侦察、快速换位，以正面承伤能力换取机动能力 |
| 中型插板 | 位于轻型与重型之间 | 不提供正向或负向修正 | 通用基准，便于建立其他护甲的平衡参照 |
| 重型插板 | `R_heavy > R_medium` | 提供负向机动修正 | 阵地、突破与正面交火，以速度换持续防护 |

必须始终满足：

```text
0 < R_light < R_medium < R_heavy < 1
```

### 4.3 第一轮靶场候选值（PENDING，不是定案）

| 类型 | 肉伤防护率候选 | 移动速度候选 |
|---|---:|---:|
| 轻型插板 | 25% | +8% |
| 中型插板 | 40% | 0% |
| 重型插板 | 55% | -12% |

这些数值只用于建立第一轮测试样本。未经用户确认、完整枪械梯度测试和其他职业叠加测试，不得把它们当作正式常量。

对于穿甲率为 20% 的 M4A1，上述候选值对应的实际整发减伤分别约为 20%、32% 和 44%，而不是直接获得 25%、40% 和 55% 全伤害减免。

### 4.4 机动修正规则（PROPOSED）

1. 第一版只调整玩家移动速度，不同时加入冲刺、跳跃、开镜或换弹修正，避免一次引入过多变量。
2. 机动修正按玩家当前生效的插板类型聚合一次，不按护甲件数累加。
3. 属性修正必须使用稳定、固定的标识，换装、登录、死亡、克隆和跨维度后重复计算不得叠层或残留。
4. 轻甲加速需与 TaCZ 持枪减速及酿酒师现有移动增益一同测试。最终玩家移动速度总上限仍为 `PENDING`。
5. 枪匠操控组件继续影响枪械本身；插板不得修改成品枪 NBT 来实现移动效果。

## 五、服务器与枪匠平衡基线

### 5.1 服务器基线（DECIDED，引用现有设计）

| 项目 | 当前基线 |
|---|---:|
| 玩家初始最大生命 | 80 HP |
| AKM | 9 伤害、600 RPM、25% 穿甲、爆头 1.5 倍 |
| M4A1 | 6.5 伤害、810 RPM、20% 穿甲、爆头 1.5 倍 |
| 入门精装持续有效输出 | 约 45 HP/s，包含命中与换弹空窗 |

AKM 与 M4A1 只是地板枪。狙击、反器材、霰弹、RPG、爆炸武器和服务器自定义枪包的完整梯度尚未汇总，因此不能仅凭这两把枪确定正式护甲数值。

### 5.2 完成版枪匠的输入边界（VERIFIED）

1. 枪匠启用时，会在 TaCZ 属性缓存中形成最终伤害曲线、爆头倍率、射程、操控和散布等属性。
2. 当前基础组件品质系数范围为 `0.96-1.50`。
3. 当前枪匠不修改源枪 RPM，也不修改 `armorIgnore`。
4. `LivingHurtEvent` 接收到的普通段或穿甲段已经包含枪匠伤害、距离曲线和爆头结果；铸甲师不得重新构造完整 `H` 或重复乘算。
5. fresh 配置当前默认 `gunsmithEnabled = false`。所有枪匠联动实弹测试必须显式启用枪匠并在报告中记录配置状态。
6. 当前默认的枪匠“伤害系数 × 爆头系数”等效倍率上限为 `1.80`，配置允许调整的最大值为 `2.25`。护甲测试必须按实际配置读取这一上限，不能默认双 `1.50` 一定完整相乘为 `2.25`。
7. 枪匠伤害与爆头组件主要提高单发压力；TaCZ 对本次弹丸解析出的穿甲率决定插板反制能力；源枪射速留给后续纳米陶瓷系统使用。

### 5.3 M4A1 候选公式示例

枪匠已启用且采用最高伤害系数组装时，M4A1 身体单发可按 `6.5 × 1.50 = 9.75` 作为当前样本。取 `p = 0.20`：

```text
P = 9.75 × 0.20 = 1.95
M = 9.75 × 0.80 = 7.80
```

套用第四章候选插板数值：

| 类型 | 计算 | 插板后伤害 |
|---|---|---:|
| 轻型 | `1.95 + 7.80 × 0.75` | 7.80 |
| 中型 | `1.95 + 7.80 × 0.60` | 6.63 |
| 重型 | `1.95 + 7.80 × 0.45` | 5.46 |

示例只验证公式量级，不代表 M4A1 是最终平衡基准，也不代表候选防护率已经确认。

默认爆头复利帽下，M4A1 当前最高爆头样本为：

```text
6.5 × 1.5（源枪爆头）× 1.80（枪匠等效倍率帽）= 17.55
```

只有把配置上限调整为 `2.25` 时，该样本才会达到 `21.9375`。爆头是否属于插板保护命中仍按第九章待拍板规则处理。

## 六、装备模型与兼容边界

### 6.1 单一生效来源（PROPOSED）

推荐由胸甲、载板背心或护甲核心唯一决定玩家当前护甲家族和插板档位。其他护甲槽可以提供外观、耐久或非防护属性，但不得各自产生完整的插板减伤。物品形态究竟是独立可穿胸甲、载板背心加可替换插板，还是整套护甲，仍为 `PENDING`。

采用单一权威槽的理由：

- 防止轻、中、重逐件叠加。
- 为后续电浆、纳米陶瓷和弹力护甲提供互斥入口。
- 简化提示、HUD、存档和受击测试。
- 防止换装组合形成没有明确弱点的多重防御。

是否最终采用胸甲作为唯一生效来源仍为 `PENDING`，但在替代方案确认前不得按四件独立叠加实现。

### 6.2 与原版护甲的关系（PENDING）

必须在编码前从以下方向中确定一个：

1. 新插板装备自身不提供原版护甲值与韧性，所有弹道防护都由本文公式负责。
2. 新插板保留有限的原版非弹道防护，但 TaCZ 弹道伤害必须避免与本文公式重复减伤。

无论选择哪一项，都必须明确保护附魔、抗性效果和其他职业减伤的结算顺序。现有玩家职业减伤上限不能自动视为包含原版护甲、保护附魔和新插板后的最终总上限。

### 6.3 与既有纳米系统的冲突（发布阻塞项）

1. 既有“纳米护甲板”是通用维修消耗品，不是本系统的可穿戴插板。将其玩家可见名称调整为“纳米修复板”只是 `PROPOSED` 命名候选；是否改名仍需用户确认，已有注册 ID 不应随显示名变化。
2. 既有“纳米多重护盾”是按件存在的限时全伤害免疫，与新护甲资源模型冲突。
3. 新插板发布前必须确定旧护盾对新护甲是禁用、迁移还是退役；未处理前不得允许两者叠加上线。
4. 插板耐久是否由普通耐久、独立完整度或可替换板件表示仍为 `PENDING`。

## 七、后续护甲家族备忘

本章保存用户已确认的概念方向以及明确标出的待评审建议，不提供实现常量。

### 7.1 电浆护盾（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 使用可恢复能量容量，不提供百分比减伤。
- 护盾击碎后等待一段时间才能重新充能。
- 高伤害、低穿甲的肉伤武器应当能够快速消耗护盾。

待评审建议（PROPOSED）：

- 按概念总伤害点数消耗容量，穿甲率不提供额外破盾加成。
- 护盾不足时保留溢出伤害。
- 爆头和持续输出按实际最终伤害继续消耗容量。

候选公式：

```text
shieldAfter = max(0, shieldBefore - H)
overflow = max(0, H - shieldBefore)
```

### 7.2 纳米陶瓷板护甲（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 有剩余次数时完整抵挡一次符合条件的伤害。
- 每次成功抵挡消耗一次，次数耗尽后完全失去自定义防护。

待评审建议与技术约束：

- 高射速与连续射击是主要反制。
- TaCZ 一颗子弹拆出的肉伤和穿甲两段只能共同消耗一次。
- 霰弹按每颗弹丸还是同一次开火合并计次仍为 `PENDING`。

### 7.3 弹力护甲（方向 DECIDED，实现 DEFERRED）

用户确认的方向（DECIDED）：

- 将部分伤害延迟为数秒内逐步结算的创伤，而不是直接消除伤害。

待评审建议（PROPOSED）：

- 爆发命中时只立即承受一部分，剩余部分加入玩家创伤池。
- 持续火力会不断累积创伤，构成主要反制。
- 创伤状态不能通过脱甲、换装、下线或跨维度清除。
- 创伤比例、结算时间、治疗交互和致死规则仍为 `PENDING`。

候选模型：

```text
immediateDamage = H × (1 - q)
traumaAdded = H × q
```

其中 `q` 为延迟比例，创伤在后续确认的时间内分段结算。

## 八、第一阶段实现验收清单

### 8.1 伤害计算

- [ ] 纯公式测试覆盖 `p = 0`、常规穿甲率和 `p = 1` 三个边界，并精确断言结果。
- [ ] 伤害源分类器分别覆盖普通弹、穿甲弹、`bullet_void` 和 `bullet_void_ignore_armor`。
- [ ] 普通弹道段只执行 `amount × (1 - R)`；在其他下游来源保持不变的测试条件下，穿甲段在铸甲师插板处理器输入与输出边界数值相同。
- [ ] 无插板时，两种弹道段都保持原值。
- [ ] 身体命中、距离衰减、爆头覆盖规则和枪匠最高伤害样本在真实 TaCZ 实弹测试中分别验证，不在插板处理器内重建 `H`。
- [ ] 默认 `1.80` 枪匠爆头复利帽和修改后的配置值都有明确测试样本。
- [ ] 新插板物品不提供会同时削减穿甲伤害的 `tacz:bullet_resistance`。
- [ ] 原版护甲、保护附魔和职业减伤不会导致未知的重复减伤。
- [ ] 同一弹丸的两段不会让未来插板耐久或命中附加效果重复扣除。

### 8.2 装备与机动

- [ ] 轻、中、重三档严格满足防护强度排序。
- [ ] 同一玩家只生效一种插板类型。
- [ ] 换装、登录、死亡、克隆和跨维度不会叠加或残留移动属性。
- [ ] 轻甲机动收益、中甲零修正和重甲机动惩罚均与提示一致。
- [ ] 插板失效或移除后不残留自定义减伤。

### 8.3 兼容与回归

- [ ] 完成版枪匠成品不被重复乘算伤害或爆头。
- [ ] 实弹测试显式启用枪匠，并记录 `gunsmithEnabled` 与爆头复利帽配置。
- [ ] 源枪完整、有序射击模式不受护甲系统影响。
- [ ] 旧纳米多重护盾不能与新插板形成未经批准的叠加。
- [ ] 非 TaCZ 伤害不会因为弹道识别失败而被错误减伤。
- [ ] 配置、物品提示与服务端计算使用同一组数值。

### 8.4 验证环境边界

TaCZ 在当前工程中为 `compileOnly` 依赖，常规 `runGameTestServer` 不加载真实 TaCZ 运行时。因此验收必须分成两层：

1. `runGameTestServer`：验证独立公式、伤害分类器、插板状态、机动属性和不变量，不伪装成真实 TaCZ 实弹结果。
2. 固定测试客户端：安装当前 TaCZ 与 MiningDim 构建，验证普通段、穿甲段、爆头、距离曲线、枪匠开关、爆头复利帽及实际装备提示，并保存配置与结果记录。
