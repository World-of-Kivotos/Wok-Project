# 服务器经济系统设计文档:货币 · 跳蚤市场 · 开箱

本服为纯外观服,不含任何 Pay-to-Win 成分。本文档定义信用点与青辉石双货币体系、跳蚤市场的动态定价与反洗钱机制、以及仿 CS2 的开箱系统。所有数值标注"建议起始值"者均为可调运营旋钮,应在上线后依据经济观测数据校准。

## 〇、前置假设与待决项

本节列出尚未闭环的关键项,优先级高于下文任何具体数值。

### 0.1 待验证前置(地基级,不解决则下文 三/四/五 大半失效)

TACz 皮肤的服务端归属授权可行性。整套"皮肤可交易、有归属的资产"经济成立的前提是:皮肤归属能落库,且 TACz 支持服务端驱动的逐玩家皮肤授权(通过 item NBT、API 或同等机制),即"未拥有该皮肤的玩家无法应用它"。

风险:若 TACz 皮肤本质为客户端资源包贴图,服务端无法强制归属——任何持有资源包的玩家都能看、能用,则"可交易、有归属"无从谈起。

行动:落地前必须验证 TACz 皮肤的存储方式与应用方式(枪械 skin 槽 / NBT / 配置)。若原生不支持服务端归属,需自行编写配套 Forge mod 兜底,否则 跳蚤市场皮肤交易、开箱产出归属、可交易性规则 全部无法落地。

状态:待验证(Blocking)。

### 0.3 货币统一、DB 边界与跨系统裁决(本版新增,优先级高于下文,覆盖与此冲突的旧表述)

本服不是纯外观服,而是"外观 + 战斗职业"混合服(矿工/农夫/千年工程师/塔罗师四个职业有实打实战斗内容)。本节裁定经济系统与这些职业的关系。

1. 信用点 = 全服唯一基础货币。一切职业的消费类扣费(塔罗卡包、矿山实例重置、服务费等)统一用信用点;玩家产出(卖矿/卖菜)回收为信用点。青辉石 = 点券式高级货币(PvE 产出、绑定不可交易),用于钥匙与闪耀卡包抽取等"额外玩法"。两币仍不可互换。

2. "无 P2W" 精确为 "无真钱 P2W"。信用点能买战斗内容(卡包等),但信用点是游戏内赚取、永不出售真钱,属正常"赚币换强度"成长,不违反 MC EULA 的真钱 P2W 限制。下文 7.1 "开箱不含战力" 仅对开箱产出成立(箱子仍只出外观);服务器整体定位为混合服。

3. 信用点是战斗相关货币 -> RMT 风险上调。信用点 RMT(真钱卖币)等于买家走后门真钱换战力,故 7.2 "冷处理" 的前提失效:信用点不可自由赠予/丢传,玩家间转移只能经 "收手续费 + 落流水审计" 的跳蚤/交易通道(堵掉零成本洗钱后门)。

4. DB 边界:
   - 信用点/青辉石余额 + 职业/世界/实例数据 -> Capability/SavedData(单服,与矿山 spec 2.4 一致)。
   - 跳蚤市场订单簿 + 玩家间交易流水审计 + 皮肤归属 + 动态基准价历史 -> PostgreSQL,仅此交易层。
   - 系统购买(卡包/箱子/重置)= 直接扣 Capability 余额;玩家间转移 = 经 DB 记录的交易通道。
   - 矿山 spec 2.4 "否决数据库后端" 据此收窄为 "世界/实例/职业数据不上 DB;跳蚤交易层用 DB,其它玩法按需接入"。

5. faucet/sink 补全:见 1.1(增列卖矿/卖菜 faucet)与 1.3(增列卡包 sink、闪耀卡包给青辉石第二个 sink)。

6. 遗留待决(不阻塞,需后续给数值):全文仍缺 faucet/sink 起始量级估算(任务币/卖矿币/箱子价/青辉石日产/钥匙价),冷启动期无数据可校准,建议补一节量化锚(参照职业 spec 的天数推演);跳蚤市场可交易标的范围(皮肤 only vs 通用)需明确,且与塔罗"禁卡牌交易"对齐。

## 一、货币体系

双货币,信用点为基础货币,青辉石为高级货币。两者不可互换——这是高级货币能维持价值的硬前提,一旦允许信用点自由兑换青辉石,青辉石即贬为信用点的附属,失去独立意义。

### 1.1 信用点(基础货币)

获取途径:

1. 任务:日常、周常、挑战任务。
2. 刷怪:普通怪物掉落信用点。
3. 交易:作为跳蚤市场的成交媒介在玩家间流转(零和转移,非新增产出)。
4. 资源收购(卖矿/卖菜):系统按动态收购价回收玩家产出的矿石/作物,是信用点量级最大的 faucet(远超任务+刷怪),见 economy 代码 AbuseGuard.buyPrice 与农夫 spec 第八节"NPC 动态收购"。

防沉迷(刷币递减):单人每日通过刷怪获取信用点设软上限,超过阈值后单位产出递减。任务币与卖矿/卖菜币同样须设每日上限/递减(复用 economy 既有 UTC 翻日 + 软上限框架),不可只对刷怪设闸而留任务/卖菜为无递减印钞口。配套两条反作弊规则:

- 仅对玩家造成过有效伤害的怪物掉币(反挂机)。
- 刷怪笼(生成器)产出的怪物降权或不掉币(反刷怪农场)。

说明:普通怪掉币是刷怪农场的经典漏洞,若不设递减与上述限制,单台高效刷怪机即可击穿整个经济。

### 1.2 青辉石(高级货币)

定位:高级货币,硬绑定玩家,不可转移、不可交易。绑定即从根上堵死青辉石的 RMT(卖币)通道。

获取途径:精英怪(冠军强敌等)PvE 击杀掉落。

已知约束(见 0.2):青辉石只从战斗产出且不可流转,意味着不打怪的玩家(纯建筑、纯交易)无法获得青辉石,从而无法购买钥匙、无法开箱。这是有意为之的设计取舍——开箱与战斗玩法绑定。若后续希望放宽,可为青辉石增设非战斗龙头(登录、在线时长、建筑赛、交易里程碑等),但需注意新龙头是否需要独立的递减规则。

### 1.3 货币分工与不互换

两种货币各自的通胀/通缩风险方向相反,sink 必须分开设计:

- 信用点:产出大(任务+刷怪+卖矿卖菜+全员日常),需要同量级的大 sink,否则通胀。其 sink 是"购买箱子"(四.1)与"购买卡包(普通/高级,战斗玩家主力 sink,缓解不开箱玩家无 sink 的问题)"。
- 青辉石:产出小(仅精英怪),需求集中在钥匙与闪耀卡包抽取(后者给青辉石第二个 sink)。若钥匙过贵会导致青辉石流通不起来、开箱经济卡死;若产出/消耗失衡则流通停滞。

货币总量 = 累计产出 − 累计销毁。任何"手续费、扣费"只有在货币被真正销毁(而非进入某个服务器账户)时才算 sink;若进入管理员账户则是再注入,反而加剧通胀。

## 二、交易信用等级(I–V)

等级划分:I 级 / II 级 / III 级 / IV 级 / V 级。

提升方式:每笔成交累积交易信用,达到阈值自动升级。

等级权益(两项):

1. 单日交易额度上限:单日通过跳蚤市场买入、卖出所消耗货币的上限。买入与卖出分开计算。
2. 手续费率减免:等级越高,跳蚤成交的常规手续费率越低。

设计说明:仅靠"抬高额度上限"对玩家激励有限。把"费率递减"挂到等级上,既给了升级的实质收益,又与反洗钱目标一致——下文偏离手续费是反洗钱主力,而常规费率减免作为高信用玩家的正常优待,两者不冲突。

防刷信用:买卖分开计上限可抑制对敲刷信用,但真正让对敲不划算的是手续费(见 三.3)与流水审计(见 三.5)。

建议起始值(可调):各等级单日额度按梯度递增;常规费率从 I 级较高逐级递减至 V 级较低。具体数字上线后依据玩家分布与货币流速校准。

## 三、跳蚤市场

玩家间交易场所。核心机制:卖家承担手续费、动态基准价、偏离手续费曲线、交易冷却、流水审计。

### 3.1 手续费基本规则

由卖家承担,成交时销毁(确认是 sink,不入任何账户)。

费率结构(详见 3.3):正常价格带内收常规低费率(随交易信用等级递减),偏离基准价越远费率成倍增加。

### 3.2 动态基准价(base)与生命周期

基准价不由人工逐一拍定,而由系统按近期成交滚动均价动态计算。人工定价在数百上千 SKU 规模下不可维护、必然滞后、且是腐败点;动态均价随市场自适应,唯一代价是冷启动期无数据。

基准价的生命周期状态机(必须在实现中明确,否则上线首周手续费模块会因无数据/除零而报错或乱收):

```
新皮肤上架
  → 阶段一:7 天交易禁售(无成交记录,无 base)
  → 阶段二:解禁后头若干单自由定价(在无 base、手续费仅按固定低费率的状态下成交,这些单据用于建立初始 base)
  → 阶段三:成交量攒够后,启用动态 base 与偏离手续费曲线
  → 阶段四(薄市场退化):见下
```

薄市场处理:成交量低于阈值的冷门皮肤,极少量异常单即可把均价带飞。规则:成交量低于阈值者,要么不启用动态 base(退回宽松固定费率),要么改用更长时间窗口摊平。不可让"一周成交两三单"的冷门皮肤与"日成交上百单"的热门皮肤共用同一套灵敏均价逻辑。

均价计算参数(需在文档/配置中明确定义):

- 时间窗口:滚动 N 天(建议起始 7 天,薄市场退化时拉长)。
- 异常值剔除:计算前掐头去尾(建议剔除最高、最低各 5%),抗操纵。

冷启动期(开服初期):开服第一周市场全为新皮肤、全处于 7 天禁售、全无 base,偏离手续费整体处于未激活态。这是预期行为。配置中需明确"经济系统冷启动期手续费按固定低费率,均价数据攒够后切换",避免上线时误判为模块故障。

### 3.3 偏离手续费曲线

目的:抑制价格异常的洗钱单(对敲)。RMT 的典型操作是挂超低价(买家真钱付完,卖家在游戏内 1 信用点甩给指定人)或异常高价(高价"回购"垃圾完成定向转移)。因此对偏离基准价的双向行为均加重收费。

曲线结构:

1. 正常带:基准价的某区间内(建议起始 70%–150%)只收常规低费率。此带是关键——必须给市场正常波动留出免重罚空间,否则某皮肤正常涨价 40% 也被当洗钱罚,玩家不敢挂单,流动性被自掐,与"流通爽快"的定位直接冲突。
2. 偏离带:超出正常带后,手续费随偏离程度成倍增加,双向(过低、过高)都罚。极端偏离时手续费可超过物品基准价本身,使 1 信用点的洗钱单在经济上完全不成立。
3. 上限与拒单:可设硬性挂单价格区间(如基准价的 30%–300%),超出直接拒绝挂单——离谱定价连挂都挂不上,比"放任挂单再用手续费惩罚"更干净。

机制边界(必须知晓):偏离手续费只能挡"价格异常"的 RMT。它会把 RMT 逼向"在基准价附近正常挂、正常成交、真钱在游戏外结"——这种单据看起来就是笔正常交易,偏离手续费对其完全无感。这类只能靠流水审计(3.5)兜底。两层缺一不可。

### 3.4 交易冷却

仿 CS2:交易后 7 天 trade hold。开箱即得的皮肤可立即上架出售(不锁),仅"账户间交易/赠予"触发 7 天冷却。已交易过的皮肤,再次交易同样触发 7 天。

设计说明:开箱当场可卖,保留"开箱→变现"的即时爽感(与"流通爽快"一致);交易冷却仅约束二次转手,抑制定向快速转移。

与 3.2 的联动:新皮肤的 7 天禁售期恰好覆盖了动态 base 的数据真空期——禁售期无成交、无 base,解禁后的头几单自由定价反过来用于建立 base。两条 7 天规则(新皮肤禁售、交易后冷却)机制不同但时长一致。

### 3.5 流水审计

落库 PostgreSQL。用于捕捉"价格正常但本质是 RMT"的转移——即偏离手续费抓不到的那一类。

检测模式(异常即标记,人工复核):

- 同一对账户反复成交。
- 新号短期集中收取大量高价值皮肤。
- 与对敲特征吻合的成交链。

定位:兜底层,非主力。本服对 RMT 整体采取冷处理(见 七.2),审计的投入按运营精力决定,最低限度保留流水落库 + 上述异常探测即可。

## 四、开箱系统

仿 CS2。箱子用信用点购买,钥匙用青辉石购买,两者均在购买/开箱时销毁。一次开箱同时消耗两种货币——箱子近乎"日常可得"、钥匙才是真正的成本门槛,正好对应 CS2"箱子免费、钥匙花钱"的模型,只是本服钥匙花的是 PvE 绑定的青辉石。

### 4.1 箱子与钥匙

- 箱子:信用点购买,购买即销毁。这是信用点的主 sink。
  - 张力提示:"箱子便宜"与"箱子当信用点主 sink"存在张力。单价太低则单笔销毁太少、沉不动信用点。定位应是"相对钥匙便宜、绝对值仍肉疼",靠走量沉淀信用点。
- 钥匙:青辉石购买,购买即销毁。这是青辉石的 sink。

开箱强制同时消耗"一个箱子 + 一把钥匙"。两套货币经济由此耦合,但货币本身仍不互换。

### 4.2 稀有度与掉率

稀有度套 CS2 六档,顶上加金色特殊档(刀/手套类极稀有):

```
白   Consumer    浅蓝 Industrial   蓝 Mil-Spec
紫   Restricted  粉   Classified   红 Covert
金   特殊档(刀/手套类)
```

箱内掉落档位:与 CS2 武器箱一致,箱子的底档为蓝(Mil-Spec)。白、浅蓝为稀有度系统的分类层级,用于其他产出途径或分类标记,不作为箱内掉落档(如需将其纳入箱内作为更常见档,另行约定)。

掉率(箱内概率,锚定红 0.99%,金约为红的 0.4 倍,其余按 CS2 逐档约 4–5 倍梯度;合计 100%):

```
档位            箱内掉率
蓝 Mil-Spec      79.11%
紫 Restricted    15.50%
粉 Classified     4.00%
红 Covert         0.99%
金 特殊档          0.40%
合计            100.00%
```

掉率设计说明:CS2 原始红色为 0.64%,本服定为 0.99%,略松。理由——CS2 的低掉率建立在全球每天千万级开箱量上,稀有皮肤总量靠海量基数堆出;本服仅数十人,若照搬 0.64%,可能数月全服开不出几把红,稀有皮肤在跳蚤无法形成成交记录、动态 base 算不出来,反把市场冻死。0.99% 既保留稀缺感,又能让稀有皮肤真正流通。掉率本身是供给侧总阀门,比任何 sink 更直接地决定市场长相,上线后应优先依数据校准。

档内抽取:命中某稀有度后,在该档所有皮肤中等概率抽取。可选按武器热度加权(默认不加权)。

磨损度 / 计数器(StatTrak 类):默认不启用,皮肤同质化——同名皮肤完全等价,形成更深的"商品市场",单皮肤一行数据、跳蚤挂单简单。启用 float/StatTrak 会成倍放大美术、数据与市场(非同质挂单)复杂度,与本服产能现实不符。列为可选未来扩展(见 0.2)。

### 4.3 箱子构成

单个箱子 = 一套独立皮肤池,内含各档若干款。当前确定项:每个箱含红 2 款 + 金 1 款(金随机)。

蓝档允许花纹复用——这是 TACz 手绘产能不足下的必要妥协,CS2 自身低档也大量复用配色。复用方式应为"一套花纹铺多把武器"(同系列跨武器),而非"同一把武器同一贴图在箱内占两个槽"(纯凑数,玩家一眼看穿)。

各档款数建议(对齐 CS2 约 17–18 款的箱型,实际受产能约束):

```
档位   建议款数      备注
蓝      5–7         管够,花纹可复用铺多枪
紫      3–5
粉      2–3
红      2           已定
金      1           已定,随机
```

武器分配(枪种):开箱不仅抽稀有度,也决定得到哪把枪的皮肤。同档内热门枪(主流步枪/狙)与冷门枪的皮肤价值差距悬殊——没人稀罕冷门枪的红皮。产能有限,稀有档(红/金)优先画热门枪种,把美术力气花在玩家真正想要的枪上;冷门枪只在低档出现或不做皮肤。

### 4.4 抽取与防作弊

1. 服务端 RNG:抽奖结果由服务端决定,客户端不参与。
2. 原子事务:扣钥匙 + 扣箱子 + 发皮肤 必须是单个原子事务(要么全成、要么全回滚),且幂等。
3. 防 dupe 重点:皮肤一旦可换信用点即等同真金白银,此处一个复制漏洞 = 无限稀有皮肤 = 市场瞬间归零,危害比普通货币 dupe 更致命。货币与皮肤资产一律落库,绝不以物品形式存在(MC 物品复制 bug 史上击穿过无数服的经济)。

无保底:本服不设保底,纯随机(与 CS2 一致)。

概率公示:开箱掉率必须公开。

### 4.5 轮换下架(供给侧稀缺)

本服不做汰换/合约 sink,因此没有任何销毁皮肤的途径——皮肤只进不出。在此前提下,靠轮换下架从供给侧制造稀缺,替代汰换的作用。

机制:不销毁存量,但掐断增量。某箱运营一段时间后整箱退役、不再产出,使该箱皮肤自然变稀缺(同 CS2 退役武器箱逻辑)。轮换以"整箱退役"为单位。

上线节奏(已定):起步只上单个箱子;美术素材攒够后再上第二个箱,届时第一个箱进入轮换退役。架构上把"箱子"定义为可扩展容器,后续加箱不改架构。

退役永久性(待定,见 0.2):

- 永久绝版:稀缺性最强,但对后入服玩家不友好(永远拿不到老皮肤)。
- 定期复刻:对新玩家友好,但稀缺性打折。
- 建议默认:退役后进入绝版状态不再产出;是否开复刻口子,视玩家流动性决定(稳定老玩家为主可偏绝版,期待新人持续涌入可留复刻)。

无汰换 sink 的连带风险(需上线后盯数据):皮肤供给只增不减,常见皮肤价格长期单调下跌。CS2 能扛住靠汰换销毁 + 海量新玩家接盘 + 真金沉淀;本服盘子小、无新玩家洪流、又无汰换,常见皮肤砸穿是时间问题。轮换下架可托住稀有档稀缺,但常见档本质上是"安慰奖",价值预期应整体压向稀有档。若后续发现市场支撑不足,需重新评估是否引入某种皮肤 sink。

## 六、其他 sink

服务性收费,均在消费时销毁:

- /home 等传送指令:每次使用收费。
- 传送主城等:收费。

缩放规则:固定费用对富人无感、对穷人是惩罚。建议按距离或玩家财富缩放,否则这类无法真正承担 sink 作用,只是惩罚穷人。

## 七、运营、合规与可观测性

### 7.1 无 Pay-to-Win

本服无任何**真钱** P2W 成分(见 0.3)。开箱产出限于 TACz 皮肤、服务器称号等纯外观/身份物,不含任何影响战力的内容;但信用点作为基础货币可购买战斗职业内容(卡包等),属游戏内成长而非真钱付费。信用点/青辉石/钥匙仅靠游戏内产出,永不出售真钱。

合规说明:纯靠游戏内产出、不售卖货币/钥匙真钱,可规避 MC EULA 对"出售影响游戏性优势(P2W)"及付费开箱的限制。若未来改变此定位(出售青辉石/钥匙换真钱),则涉及概率公示、未成年人防沉迷等监管要求及 MC 商业授权条款限制,需重新评估——届时应核查当前最新的中国开箱合规要求与 MC 商业条款,不沿用旧版本。当前定位下无此负担。

### 7.2 RMT 态度

对 RMT(玩家以真钱在游戏外交易游戏资源)采取冷处理。纯外观服中,RMT 买不到任何战力,危害有限。措施:发布公告明确不建议、平台免责;不为此构建重型拦截系统。技术上已有的被动防线(青辉石绑定堵卖币、偏离手续费挡价格异常对敲、流水审计兜底)已足够,不再加码。

### 7.3 可观测性(让上文所有数值可调的元工具)

依托 PostgreSQL,把经济做成可量化的。所有货币流水、交易、开箱、扣费落审计日志——既是回滚依据,也是反 RMT 探针,更是数值校准的唯一事实来源。

核心指标:

- 货币总量(M0):信用点、青辉石各自的流通总量。
- 流通速度:货币周转频率。
- 基尼系数:贫富差距。
- 各 faucet / sink 的日流量:每个产出口、每个销毁口的单日货币量。

用途:本文档所有"建议起始值"都依赖此数据校准。没有这套观测,所有数值都是拍脑袋;有了它,通胀一抬头即可定位是哪个龙头漏水、哪个 sink 不够。这也是判断"信用点 sink 是否够"的依据——砍掉汰换后,信用点销毁只剩买箱子 + 手续费 + 服务收费,开箱热度退潮后 sink 是否仍足,需持续盯 M0 与各 sink 日流量。
